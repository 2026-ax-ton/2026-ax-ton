## 1. 왜 지금 이 문서인가 — 아이디어톤이 남긴 빈칸

아이디어톤 자체 평가에서 **가장 약하다고 스스로 적은 칸**이 하나 있습니다.

> **[`11-evaluation.md`](11-evaluation.md) §1.1**
> *"제품 안의 AI 가 **아직 실제로 돌지 않습니다.** 번역과 역번역은 사람이 손으로
> 입력합니다. AI 가 하는 자리를 **설계해 두고 경계를 화면에 적었을 뿐**입니다."*

같은 문장이 발표 문서 여섯 군데에 있습니다
([`presentation/01-평가지표-대조.md:90`](presentation/01-평가지표-대조.md) ·
[`presentation/04-Claude-활용.md:204`](presentation/04-Claude-활용.md) ·
[`발표-인계/06-한계와-개선-로드맵.md:17`](발표-인계/06-한계와-개선-로드맵.md) ·
[`발표-인계/13-심사위원-예상질문-배점별.md:105`](발표-인계/13-심사위원-예상질문-배점별.md) 등).

**해커톤은 정확히 그 칸을 메우는 자리입니다.**

### 1.1 다만 — 순서를 뒤집지 않습니다

아이디어톤에서 *"왜 AI 번역이 안 도냐"* 는 질문에 이렇게 답하기로 했습니다.

> *"순서를 그렇게 잡았습니다. **번역을 자동화하기 전에 검수 게이트를 먼저 만들었습니다.**
> 검수 없는 자동 번역은 오역이 그대로 안전 지시가 됩니다."*

**이 답이 여전히 유효해야 합니다.** 에이전트를 붙인다는 것은
*"이제 게이트가 있으니 그 앞에 자동 생성을 놓는다"* 는 뜻이지,
*"게이트를 치운다"* 는 뜻이 아닙니다.

그래서 아래 후보 전부가 **같은 모양**입니다.

```
  [ 에이전트가 만든다 ]  →  [ waiting 상태로 제출 ]  →  [ 사람이 판정 ]  →  [ 현장으로 ]
         자동                     자동으로는                  안 바뀜           안 바뀜
                              여기서 더 못 감
```

## 2. 전제: 외부 요청 0건 규칙을 어떻게 지킬 것인가

`CLAUDE.md` 의 **외부 요청 0건**은 이 프로젝트의 뼈대입니다.
AI API 를 부르는 순간 그 규칙과 정면으로 부딪힙니다.

### 2.1 ★ 정한 것 — ③ 관리자 화면만 예외 (2026-09-28)

| | 노동자 화면 6개 | 관리자·운영자 화면 5개 |
|---|---|---|
| 외부 요청 | **0건 그대로** | **AI 호출 허용** |
| 왜 | *"현장 인터넷이 약하다"* 가 제품의 전제. 오프라인(E1)·`file://` 확인이 전부 여기 걸려 있음 | 사무실 PC 에서 씀. 인터넷이 있는 자리 |
| 끊기면 | 지금처럼 다 됨 | **손으로 하던 길이 그대로 남음** (아래 2.2) |

**노동자가 쓰는 쪽은 한 줄도 안 바뀝니다.** 에이전트의 결과물은
`Store` 에 담긴 **데이터**로만 노동자에게 도착합니다 — 노동자 폰은 AI 를 부르지 않습니다.

### 2.2 ★ 붙여도 기존 길을 없애지 않습니다

이것이 이 설계에서 가장 중요한 한 줄입니다.

> **AI 호출이 실패하면 "지금의 화면" 이 그대로 나옵니다.**

`09-handover.md` §8.2 의 함정 표에 이미 있는 규칙입니다 —
*"버튼만 조용히 없애기 → 사람은 그것을 **고장으로** 읽음"*.
그래서 에이전트 버튼은 **더해지는 것**이고, 손으로 번역문을 넣는 칸은 **남습니다.**

그 덕분에 부수 효과가 하나 생깁니다 — **`file://` 더블클릭 확인이 계속 삽니다.**
`file://` 에서는 AI 버튼이 *"인터넷이 있어야 합니다"* 로 바뀌고 나머지는 전부 그대로입니다.

### 2.3 키를 브라우저에 두지 않습니다

API 키를 `src/` 안에 두면 **배포 주소를 여는 누구나 가져갑니다.**
그래서 호출은 **Vercel 서버리스 함수(`/api/*`)를 경유**합니다.

```
관리자 화면 (브라우저)  →  /api/translate  →  Claude API
                            ↑ 키는 여기에만 (Vercel 환경변수)
```

**이것이 이 프로젝트에 처음 생기는 서버 코드입니다.** 지금까지 없던 것이라
아래를 함께 봐야 합니다.

| 무엇 | 지금 | 붙이면 |
|---|---|---|
| Vercel Root Directory | `src` | **바뀔 수 있음** (`/api` 를 어디 둘지에 따라) |
| 빌드 | 없음 | 여전히 없음 (함수만 추가) |
| `docs/` `tests/` 가 배포에 안 올라감 | 404 로 확인됨 | **다시 확인해야 함** ← 빠뜨리기 쉬움 |
| 의존성 0 | `src/` 는 0 | `/api` 만 의존성을 가짐. **`src/` 는 계속 0** |

> **★ Root Directory 를 건드리는 것은 배포 설정 변경입니다.**
> 실제로 손대기 전에 사용자에게 먼저 묻습니다.

### 2.4 안 고른 두 안 (기록만)

| 안 | 무엇 | 왜 안 골랐나 |
|---|---|---|
| ① 서버리스 함수로 **예외 하나 추가** (화면 구분 없이) | 노동자 화면에서도 AI 호출 허용 | 오프라인 전제가 무너짐. 현장 폰이 인터넷에 기대게 됨 |
| ② **빌드 시점에 생성**해 정적 데이터로 | 배포 전에 번역을 다 만들어 파일로 굽기 | 외부 요청 0건은 지킴. 다만 **운영자가 문구를 새로 넣는 순간 못 씀** — 라이브러리가 살아 있는 데이터라 안 맞음 |

## 3. 에이전트 후보 3개

**셋 다 후보입니다.** 주제 공지 후 하나 또는 둘만 고릅니다.
셋을 다 만들 시간은 없다고 보는 편이 안전합니다.

### 후보 A — 번역·검수 에이전트 ★ 빈칸을 정면으로 메움

| | |
|---|---|
| 붙는 자리 | `admin/library.js` (운영자 문구 검수) · `admin/content.js` 3단계 (문항 번역) |
| 지금 | 운영자가 **6개 언어 번역문과 역번역을 손으로 입력**. `assets/review.js` 는 낱말 비교와 **부정 뒤집힘**만 규칙으로 잡음 |
| 에이전트가 하는 것 | 한국어 원문 → 언어별 초벌 번역 → **그 번역을 다시 한국어로 역번역** → `Review.compare()` 에 먹여 자기가 판정 → 뒤집혔으면 **다시 번역** → 그래도 뒤집히면 **"사람에게 올림" 으로 표시** |
| 사람이 하는 것 | **승인 / 대기 / 중지 판정. 안 바뀜** |
| 제출 상태 | 무조건 **`status: 'waiting'`**. 에이전트가 `reviewed` 를 쓸 수 없음 |

**왜 "에이전트" 인가** — 단발 번역 호출이 아닙니다.
**번역 → 역번역 → 자기 대조 → 실패하면 다시** 가 한 루프이고,
`Review.compare()` 라는 **도구를 부르고 그 결과를 보고 다음 수를 정합니다.**
몇 번 돌려도 뒤집힘이 안 풀리면 **포기하고 사람을 부르는 것**까지가 설계입니다.

> **지금 있는 것을 버리지 않습니다.** `review.js` 는 *"AI 여기까지 · 승인은 사람"* 의
> 경계라고 파일 맨 위에 적혀 있습니다. 에이전트는 그 경계의 **바깥쪽**에 섭니다.

### 후보 B — 문항 출제 에이전트

| | |
|---|---|
| 붙는 자리 | `admin/content.js` 3단계 (문항 만들기) |
| 지금 | 담당자가 hotspot 좌표 · choice 선택지 · match 짝을 **손으로 전부** 만듦. **교육 하나 만드는 데 가장 오래 걸리는 작업** |
| 에이전트가 하는 것 | 고른 안전 문구 + 설비 그림(`assets/diagrams.js` 가 좌표를 코드로 갖고 있음) → **3유형 문항 초안** + 오답 해설(*"어떤 사고가 되는지"*) + 언어별 번역 |
| 사람이 하는 것 | **발급 전 검토.** 발급 버튼은 사람이 누름 |

**hotspot 이 까다롭습니다** — 그림에서 위험 지점의 좌표를 짚어야 합니다.
다만 `diagrams.js` 가 설비 그림을 **코드(좌표)로** 갖고 있어서,
*"프레스의 금형 사이"* 같은 이름을 좌표로 바꿔 주는 **도구를 에이전트에게 줄 수 있습니다.**
그림을 보는 게 아니라 **구조를 읽는 것**이라 승산이 있습니다.

**이미 있는 안전장치** — `Store.qtext()` 가 번역 배열 길이를 검사합니다.
길이가 어긋나면 `answer` 인덱스가 다른 선택지를 가리켜
**틀린 작업을 맞다고 가르치게 됩니다.** 에이전트가 만든 것도 이 검사를 그대로 지납니다.

| **발표 전달력 (15)** | 발표팀 몫 | **C 가 시연에 가장 좋습니다** — 대시보드에서 *"인도네시아어 사용자가 끼임 위험을 못 알아듣고 있습니다"* 가 한 화면에 뜨는 것은 **보여 주기 쉬운 그림** |

### 4.2 ★ 에이전트로 **안 올라가는** 칸

정직하게 적습니다. 이 셋은 AI 를 붙여도 그대로입니다.

- **문제 정의의 명확성 (10)** — 이미 한 문장으로 떨어져 있고, 에이전트와 무관합니다
- **실행 활동의 충실도 (15)** 중 *"주변 의견 수렴"* — **사람에게 건네 봐야** 메워집니다
- **차별점의 방어 가능성** — 에이전트는 따라 하기 쉽습니다. 오히려 **쌓인 검수 판정 기록**이 해자에 가깝습니다

## 5. 무엇이 있어도 바뀌지 않는가 — 넘지 않는 선

`07-next-tasks.md` 맨 아래 **"★ 절대 지우지 말 것"** 표가 원본입니다.
**에이전트가 특히 어기기 쉬운 것**만 다시 적습니다.

| 선 | 에이전트에게 무슨 뜻인가 |
|---|---|
| **검수된 문구만 안전 지시로** | 에이전트는 **`waiting` 까지만** 쓸 수 있습니다. `reviewed` 로 올리는 것은 사람뿐 |
| **위험요소 신고는 익명** | 에이전트도 신고자를 알 수 없습니다. **`reports` 를 요약할 때 사람 단위로 내려가지 않습니다** |
| **미이수·미통과를 숨기지 않는다** | 에이전트가 "요약" 하면서 **미통과자를 빼면** 그게 숨기는 경로입니다 |
| **인사·평가 목적 내보내기 없음** | *"이 사람 재교육 3회"* 를 에이전트가 계산하는 것도 금지. **줄 세우기를 만들지 않습니다** |
| **미통과는 교육의 실패** | C 의 원인 가설이 *"이 노동자가 이해를 못 함"* 으로 끝나면 안 됩니다. **번역·문항·교육 쪽을 먼저 의심합니다** |
| **"면책" 표현 금지** | 에이전트가 만든 문장에도 그대로 적용됩니다 |
| **`innerHTML` 금지** | **에이전트 출력은 신뢰할 수 없는 문자열입니다.** `UI.el` 로 `textContent` 에만 |
| **`Store` 를 거친다** | 에이전트 결과도 `localStorage` 를 직접 부르지 않습니다 |

> **★ 마지막 줄이 특히 중요합니다.** AI 가 만든 텍스트를 화면에 넣는 것은
> 사용자 입력을 넣는 것과 **같은 위험**입니다. 지금 규칙이 이미 그것을 막고 있습니다.

## 6. 검사를 어떻게 붙일 것인가

이 프로젝트의 리듬은 **"만들고 → 검사 쓰고 → ★ 일부러 망가뜨려 잡히는지 본다"** 입니다
(`09-handover.md` §7.3). 에이전트도 같습니다. **다만 한 가지가 다릅니다.**

> **AI 응답은 매번 다릅니다.** 출력 내용을 검사에 박으면 그 검사는 곧 썩습니다.

그래서 **내용이 아니라 경계를 검사합니다.**

| 새로 필요한 검사 | 무엇을 지키나 |
|---|---|
| `test-agent-boundary.js` (가칭) | 에이전트 경로가 **`status: 'reviewed'` 를 절대 쓰지 못함** |
| | 에이전트 요약에 **`reports` 의 식별값이 섞이지 않음** (지금도 값 자체가 없음) |
| | 에이전트 출력이 **`innerHTML` 로 들어가는 경로가 없음** |
| | **노동자 화면 6개에서 외부 주소 0건** — 지금 검사를 그대로 유지 (§2.1) |
| | **API 키 문자열이 `src/` 안에 없음** |
| 기존 검사 | **16묶음 1,613건이 전부 통과한 채로 있어야 합니다.** 하나라도 깨지면 경계를 넘은 것 |

**AI 를 부르지 않고 검사합니다** — 가짜 응답(고정된 JSON)을 먹여서
*"이 응답이 왔을 때 우리 코드가 무엇을 하는가"* 를 봅니다.
`tests/harness.js` 가 이미 `speechSynthesis` 를 가짜로 만들어 쓰고 있어서 같은 방식입니다.

## 7. 아직 정하지 못한 것

**주제 공지를 보고 정합니다.** 지금 정하면 다시 정하게 됩니다.

| 질문 | 왜 지금 못 정하나 |

| **몇 개를 만드나** | 11월 말까지. 하나를 제대로 + 나머지는 설계만, 이 쪽이 안전해 보입니다 |

| **모델을 무엇으로** | 비용과 응답 속도를 재 봐야 합니다. 운영자가 기다릴 수 있는 시간이 얼마인지도 |

| **"주변 의견 수렴" 을 언제** | §4.2. **에이전트로는 안 메워지는 칸**이고, 실제로 가장 큰 한 걸음입니다 |
