## 2. 시장조사 — 지금 무엇이 있나

> 2026-08-28 웹 검색으로 확인한 범위입니다. **공개 정보 기준이고, 각 서비스의
> 내부 기능까지 전수 조사한 것은 아닙니다.** 아래 "확인 못 한 것" 을 함께 읽어 주세요.

### 2.1 문제의 크기 (공개 통계)

| 사실 | 출처 |
|---|---|
| 외국인 노동자 **92만 명** 규모, 취업 전·시 기초 안전보건교육 의무화 방향 | 고용노동부 |
| 외국인 근로자 산재 피해자 **2022년 8,286명 → 2024년 9,219명** | 고용노동부·근로복지공단 통계 |
| **한 해 100명 넘게 사망** | 언론 보도 (2025) |
| 전문가가 짚는 원인: **모국어 안내 부족 · 형식적인 안전교육** | 언론·연구 |
| 산업안전보건법상 사업주는 **내국인과 동일하게** 교육 실시 의무 | 고용노동부 |

**★ "형식적인 안전교육" 이 우리가 겨냥한 바로 그 지점입니다.**

### 2.2 이미 있는 것 — 세 갈래

| 갈래 | 대표 | 무엇을 하나 | 우리와 겹치는 곳 |
|---|---|---|---|
| **① 공공 다국어 교육** | 고용노동부·안전보건공단 — **16~17개국 언어** 안전보건 교육자료, 다국어 온라인 안전보건교육 서비스, 찾아가는 교육 | **콘텐츠를 언어별로 만들어 배포** | 다국어 자료 제공 |
| **② 공공 이수 관리** | 안전보건교육포털 · 건설기초안전 교육포털 — 이수확인서·이수증 발급 | **누가 이수했는지 기록·증명** | 증빙 |
| **③ 민간 온라인 교육 SaaS** | 휴넷 · HRDE · 대한안전교육협회 등 — 이수현황 실시간 확인, **법정 실적보고서 자동 생성**, 과태료 위험 알림, 수료증 출력 | **사업주의 법적 의무 이행을 편하게** | 증빙·관리 |
| **④ 픽토그램** | 고용노동부·공단 **안전보건 픽토그램 20종** (끼임·베임·컨베이어 접근금지 등) | 언어 없이 위험을 알림 | 비문자 전달 |

### 2.3 그래서 무엇이 비어 있나

세 갈래를 겹쳐 놓으면 이렇게 됩니다.

```
① 다국어 콘텐츠  →  "그 언어로 만들어서 줬다"
② · ③ 이수 관리  →  "그 사람이 들었다 / 이수했다"
④ 픽토그램       →  "그림으로 알렸다"
─────────────────────────────────────────────
                     ↑ 셋 다 "전달했다" 까지다
                     ✗ "그 사람이 이해했는가" 를 확인하는 자리가 없다
```

**공개 정보로 확인한 범위에서, "이해했는지를 개인별로·비문자로 확인하고
그 결과를 법정 증빙에 넣는" 서비스는 보이지 않았습니다.**

### 2.4 ★ 확인 못 한 것 (정직하게)

발표에서 *"진짜 없나요?"* 라고 물으면 이렇게 답하는 것이 맞습니다.

- 각 민간 SaaS 의 **내부에 이해도 평가 기능이 있는지**는 전수 확인 못 했습니다.
  다만 **온라인 교육의 일반적인 평가는 객관식 필기시험**이고,
  그것은 **한국어를 읽어야 하므로** 우리가 겨냥한 문제를 그대로 남깁니다
- 해외(EU·미국)의 다국어 산업안전 교육 제품까지는 조사하지 않았습니다
- **"없다" 가 아니라 "확인한 범위에서 안 보였다"** 로 말하는 것이 정확합니다

## 3. 차별점 — 무엇이 다른가

### 3.1 한 줄

> **다른 서비스는 "교육을 전달했다"를 증명하고,
> 우리는 "그 사람이 이해했다"를 증명합니다.**

### 3.2 항목별

| # | 차별점 | 왜 남들이 쉽게 못 따라오나 | 지금 되나 |
|---|---|---|---|
| **1** | **문해력 비전제 이해도 검증** — 문항 3유형이 전부 손가락 조작 (👆위험 지점 짚기 · ☑올바른 작업 · 🔗보호구 연결) | 기존 서비스는 **객관식 필기**가 기본. 이걸 바꾸려면 콘텐츠 제작 방식 전체를 바꿔야 함 | ✅ |
| **2** | **이해도 결과가 그대로 법정 증빙** — 서명부가 아니라 "무엇을, 어느 언어로, 얼마나 이해했는지" | 증빙 서식과 검증 데이터가 **같은 시스템 안에** 있어야 함. 교육사와 관리 SaaS 가 나뉘어 있으면 붙이기 어려움 | ✅ |
| **3** | **언어별 검수 판정** — 한 언어의 오역이 다른 언어 노동자의 안전 지시를 뺏지 않음 | 대부분 "번역본 하나 = 문서 하나". **언어를 문서의 속성이 아니라 판정의 단위로** 두는 것은 데이터 모델부터 다름 | ✅ |
| **4** | **오역을 사고로 취급하는 파이프라인** — 신고 접수 **즉시 중지**, 역번역 대조로 **부정 뒤집힘만 크게** 경고 | "확인한 뒤 내린다" 가 자연스러운 순서인데 그걸 뒤집음. **오역이 한 시간 더 붙어 있는 것이 더 위험**하다는 판단이 있어야 나옴 | ✅ |
| **5** | **미이수·미통과를 숨길 수 없는 구조** — 증빙에 걸러 보기도 결과순 정렬도 없음. **증빙은 쓰는 키가 아예 없음**(사본이 없으니 고칠 경로도 없음) | 관리 SaaS 의 판매 포인트는 보통 **"과태료 위험 알림"**, 즉 사업주 편의. **사업주가 불편해지는 방향으로 설계하는 것**은 영업상 하기 어려움 | ✅ |
| **6** | **위험요소 익명 신고를 선행지표로** — `reports` 에 식별값이 **한 개도** 없음. "내가 낸 신고" 조차 안 만듦 | 익명을 **화면 규칙이 아니라 데이터 구조**로 만든 것. 나중에 붙이면 이미 저장된 식별값이 남음 | ✅ |
| **7** | **미통과 = 교육의 실패** — 개인 점수의 인사·평가 목적 내보내기를 **아예 안 만듦** | 이 기능을 안 만드는 것이 **팔기에는 불리**함. 그런데 이게 있으면 현장이 등을 돌리고 신고가 멈춤 | ✅ |
| **8** | **설비 앞 QR → 그 설비 교육** — 외부 라이브러리 없이 QR 을 직접 만들고, 로그인을 거쳐도 목적지를 안 잃음 | 기술적으로 어렵진 않으나, **"작업 직전, 그 설비 앞에서"** 라는 교육 시점을 잡은 설계 | ✅ |
| **9** | **오프라인 우선 · 외부 요청 0건** — 인터넷 없이 열림 | 현장 인터넷이 약하다는 전제를 **처음부터** 넣어야 나오는 구조. 나중에 넣기 어려움 | 🔸 부분 (파일로는 열림 / Service Worker 는 E층) |

### 3.3 따라 하기 어려운 쪽으로 가려면

**지금 차별점은 대부분 "설계 철학" 이라 아이디어 자체는 따라 할 수 있습니다.**
평가지표가 *"극복 불가능한 차별점일수록 좋다"* 를 원한다면,
**쌓일수록 강해지는 것**으로 옮겨 가야 합니다. 후보 넷:

| # | 무엇 | 왜 시간이 지날수록 강해지나 | 필요한 것 |
|---|---|---|---|
| **A** | **검수된 다국어 안전 문구 라이브러리** (목표 200개 × 6언어) | 번역 하나하나에 **사람의 검수**가 붙어 있음. 오역 신고가 쌓일수록 정확해짐. **경쟁자가 복제하려면 같은 검수 비용을 다시 치러야 함** | 시간 · 원어민 검수자 |
| **B** | **문항별·언어별 오답 데이터** | "크메르어 노동자는 잔류 압력 개념에서 막힌다" 같은 **데이터는 이 서비스 안에서만 생김**. 쌓이면 **어떤 설명이 어느 언어에서 통하는지**를 알게 됨 | 사용자 수 |
| **C** | **문항 난이도 자동 관측** (최초 통과율 70~85% 밖이면 경고) | B 위에서만 돌아감. **콘텐츠가 스스로 좋아지는 루프** | B + 서버 |
| **D** | **감독기관 서식 연동 / 증빙 위조 검증** | 한 번 인정받으면 **바꾸기 어려운 표준**이 됨 | 기관 협의 |

> **발표에서 쓸 문장** —
> *"지금의 차별점은 설계에서 옵니다. 다만 이 서비스가 돌수록
> **검수된 번역과 언어별 오답 데이터**가 쌓이고, 그건 복제하려면
> 같은 시간과 같은 검수 비용을 다시 치러야 하는 것입니다."*

## 4. AI 활용 — 두 층으로 나눠서

**이 프로젝트에서 AI 는 두 군데에 있습니다. 섞어서 말하면 안 됩니다.**

```
1층  제품 안의 AI   — 사용자가 만나는 AI. 화면에 경계를 적어 뒀다
2층  개발에 쓴 AI   — Claude Code. 이 코드베이스가 만들어진 방식
```

### 4.1 1층 — 제품 안의 AI

#### 어디까지가 AI 인가 (화면에 그대로 적혀 있습니다)

| 화면 | 고지 | 전문 |
|---|---|---|
| **기능9 라이브러리** | `AI 여기까지` | *"초안 번역 · 역번역 대조 · 음성 합성까지가 AI 입니다. **승인은 사람이 합니다.** 아래 판정 버튼을 누르는 것은 운영자입니다."* |
| **기능2 교육 만들기** | `AI 여기까지` | *"**AI 는 안전 문구를 새로 쓰지 않습니다.** 사람이 검수를 마친 라이브러리에서 고르기만 합니다."* |
| **기능6 대시보드** | `AI 개입 없음` | *"이 화면의 숫자는 노동자가 실제로 답한 기록을 그대로 센 것입니다. 추정하거나 보정하지 않습니다."* |

#### ★ 왜 AI 를 일부러 제한했나

이 제품에서 **AI 가 틀리면 사람이 다칩니다.**

> 번역에서 부정문이 뒤집히면 *"보호구를 착용하지 마시오"* 가 됩니다.
> **오역이 그대로 사고가 됩니다.**

그래서 이렇게 갈랐습니다.

| AI 가 하는 것 | 사람이 하는 것 |
|---|---|
| 초벌 번역 (초안) | **승인 / 중지 판정** |
| **역번역 대조 — 사람이 볼 곳을 좁혀 줌** | 뜻이 뒤집혔는지 최종 확인 |
| 음성 합성 | 음성이 알아들을 만한지 (E층: 음성도 검수 상태를 가져야 함) |

**"AI 를 어디까지만 쓸지 정하는 것"** 자체가 이 제품의 설계입니다.

#### 지금 실제로 도는 것 / 안 도는 것

| | 상태 |
|---|---|
| **역번역 대조 로직** (`assets/review.js`) | ✅ **돕니다.** 낱말 차이와 **부정 뒤집힘**을 다른 세기로 표시 |
| **음성 합성** | ✅ 돕니다 (브라우저 `speechSynthesis`) |
| **초벌 번역 자동 생성** | ❌ **아직 안 돕니다.** 지금은 사람이 번역문·역번역을 입력합니다. 외부 요청 0건 규칙 때문에 클라우드 번역 API 를 부를 수 없습니다 → **서버가 생기는 시점** |

> **★ 발표에서 이 부분은 정직하게 말해야 합니다.**
> *"AI 번역 연동은 아직 안 붙였습니다. 대신 **AI 가 낸 것을 사람이 어떻게
> 검증할지**를 먼저 만들었습니다 — 역번역 대조와 판정 권한 분리입니다.
> 순서를 그렇게 잡은 이유는, 검증 없이 번역만 붙이면 **오역이 그대로 사고**가
> 되기 때문입니다."*

#### `review.js` — 왜 "부정 뒤집힘만" 크게 경고하나

파일 주석에 그대로 있습니다.

> 낱말이 다른 것만으로는 위험을 가릴 수 없다.
> *"환기팬이 돌지 않으면"* → *"팬이 꺼져 있으면"* 은 말만 바꿔 쓴 것이고,
> *"손을 넣지 마십시오"* → *"손을 넣어도 됩니다"* 는 **정반대 지시**다.
> 둘을 같은 세기로 표시하면 운영자가 표시를 무시하게 되고,
> 그러면 정작 **뜻이 뒤집힌 문구가 그냥 지나간다.**

**경고를 많이 하는 것이 안전한 게 아닙니다. 무시하게 만들면 없느니만 못합니다.**

### 4.2 2층 — 개발에 쓴 AI (Claude Code)

> 평가지표: *"Claude Code를 **어떻게, 왜 그렇게** 활용했는지 구체적으로 설명하는가"*

#### ① `CLAUDE.md` — 규칙을 세션마다 자동으로 주입

저장소 루트의 `CLAUDE.md` 를 Claude Code 가 **매 세션 자동으로 읽습니다.**
여기에 **제품 원칙과 기술 제약**을 적어 뒀습니다.

- 외부 요청 0건 · `innerHTML` 금지 · ES 모듈 금지 · 터치 60px
- 검수된 문구만 · 신고는 익명 · 미이수를 숨기지 않음 · "면책" 표현 금지
- `localStorage` 직접 호출 금지 (`Store` 를 거친다)
- git 규칙 (`main` 직접 push 금지 · `--force` 금지 · 커밋 메시지 태그)

**왜 그렇게 했나** — 혼자 개발하면 원칙은 조용히 무너집니다.
*"이번만 예외로"* 가 쌓이면 어느 순간 다른 제품이 되어 있습니다.
**사람이 매번 기억하는 대신, 도구가 매번 읽게** 했습니다.

#### ② 문서를 세션 간 기억으로 — *"docs 보고 바로 진행해줘"*

Claude Code 는 세션이 끊기면 맥락을 잃습니다. 그래서 **저장소 안 문서**를
기억 장치로 썼습니다.

| 문서 | 역할 |
|---|---|
| `docs/07-next-tasks.md` 맨 위 **"★ 지난 세션이 끝난 자리"** | 지금 상태 + 다음 한 걸음. **이것만 보면 이어갈 수 있음** |
| `docs/devlog/byeonsoyun.md` | **막혔던 것 / 어떻게 풀었는지.** 왜 이 코드가 이렇게 생겼는지 |
| 각 파일 맨 위 주석 | 그 화면이 **코드로 지키는 제품 원칙** |
| 화면 안 "여기부터 채우시면 됩니다" 칸 | 그 화면에 남은 일 |

**실제로 이게 작동한 사례** — 2026-08-27 세션이 C7 도중 **세션 한도로 끊겼습니다.**

(그때 B3 의 개발일지를 빠뜨린 것도 `07` 에 기록이 남아 있어 되짚을 수 있었습니다.)

#### ③ 검사를 사람이 아니라 도구가 지키게

**제품 원칙을 문서가 아니라 검사로 박았습니다.** 자동 검사가 보는 것:

- 신고 데이터에 신고자를 식별할 값이 **없는지**
- 미이수자를 **숨기는 경로**가 생기지 않았는지
- 증빙에 **"면책"** 이라는 표현이 없는지
- `localStorage` 를 직접 부르는 코드가 `store.js` **밖에 없는지**
- 이름을 감춘 글·댓글에서 **아이디가 새어 나가지 않는지**
- 재교육 지시가 **누적 횟수를 세거나 사람을 줄 세우지 않는지**
- **PC 화면에서 취약 항목이 이수율 타일보다 작아지지 않는지** (CSS 도 글로 읽어 확인)
- 문서(`07`)와 화면의 "할 일" 칸이 **다른 말을 하지 않는지**

**마지막 두 개가 특히 이 프로젝트답습니다.**
**레이아웃 한 줄**과 **문서 한 줄**로도 제품 원칙이 무너질 수 있어서,
거기까지 검사를 붙였습니다.

#### ④ ★ "망가뜨려 보기" — AI 가 쓴 검사를 믿지 않는 절차

**검사를 쓰고 나면 항상 일부러 코드를 망가뜨려 그 검사가 정말 잡는지 봅니다.**
안 잡히면 그 검사는 아무것도 지키지 않는 것입니다.

**이 절차로 실제로 찾은 것들** (개발일지에 전부 기록):

| 무엇 | 무엇이 문제였나 |
|---|---|
| **QR 타이밍 무늬 훼손** | 형식정보 자리를 막으면서 타이밍 무늬 두 칸을 덮어씀. **그림은 멀쩡한데 스캔이 안 되는** 고장. **되읽기 검사로는 안 잡혔고 구조 검사가 잡음** |
| **"남의 재교육 지시는 안 보인다" 가 우연히 통과** | 예시 지시가 다른 공정이라 교육 필터에 먼저 걸림. `workerId` 거르기를 지워도 통과했음 |
| **"내린 문항을 계속 낸다" 를 아무도 안 잡음** | 노동자 쪽에 그 검사가 없었음 |
| **항상 통과하게 돼 있던 검사** | `items.every(...) || items.length === 2` — 뒤 조건이 늘 참이었음 |
| **실패가 예외로 죽음** | 실패한 다음 줄이 `undefined.length` 를 읽어 터짐 → `(x \|\| [])` 로 감싸 **실패가 실패로 보이게** |

> **AI 가 만든 것을 AI 가 검사하면 사이좋게 틀릴 수 있습니다.**
> 그래서 **QR 검사에서는 블록 표를 코드에서 가져오지 않고 검사 쪽에 따로 적었고**,
> **규격(ISO/IEC 18004)의 상수와 대조**했습니다 — 그 값들은 우리가 정할 수
> 있는 것이 아닙니다.

#### ⑤ 되돌리기 어려운 일은 사람에게 물어보기

`CLAUDE.md` 에 적어 뒀습니다 — **파일 삭제 · 브랜치 변경 · 데이터 모양 변경**은
먼저 물어봅니다. 실제로 오늘 **배포(`main` push)** 와 **문서 파일 삭제** 를
진행하기 전에 확인을 받았습니다.

#### ⑥ 개발일지 — AI 가 쓰고 사람이 읽는 기록

한 덩어리가 끝날 때마다 **한 것 / 막혔던 것 / 데이터에 더한 것 / 남는 한계 /
다음에 할 것** 을 남겼습니다. **21편**이 쌓였습니다.
*"막혔던 것 / 어떻게 풀었는지"* 를 반드시 적게 한 이유는,
**며칠 뒤에는 기억나지 않고 그게 발표 재료**이기 때문입니다.

#### AI 활용을 한 문장으로

> **"AI 에게 코드를 시킨 것이 아니라, AI 가 지켜야 할 규칙과
> 스스로를 의심하는 절차를 먼저 만들고 그 안에서 일하게 했습니다."**

### 5.3 ★ 개발 도중 실제로 부딪힌 문제 — 고민의 흔적

**개발일지 21편에서 뽑은, 발표에서 이야기가 되는 것들.**

#### ① 기간으로 거르면 미수강자가 사라진다 (C2 · C1)

기간 필터를 만들 때 **"수강한 날"** 로 거르는 것이 자연스러워 보였습니다.
그런데 **아직 아무것도 안 한 사람은 날짜가 없어서 통째로 빠집니다.**
미수강자가 사라지고 **이수율이 저절로 올라갑니다.**

→ 기준을 **"교육을 발급한 날"** 로 바꿨습니다. 검사로 박았습니다.
**이 제품이 절대 하면 안 되는 일**이기 때문입니다.

#### ② 걸러 보기가 금지인 화면에서 기간 묶음을 만들어야 했다 (C1)

`proof.js` 맨 위에는 *"걸러 보기 기능도 두지 않는다"* 라고 적혀 있는데,
C1 은 "분기를 골라 뽑기" 였습니다. **이게 걸러 보기 아닌가?**

한참 보고 이렇게 갈랐습니다.

- 금지되는 것은 **"사람"** 을 거르는 것
- C1 이 하는 것은 **"무엇을 한 문서에 담을지"** — 범위 안의 **모든 대상자**가 들어감
- 다만 **경계가 얇아서** 안전장치를 문서 자체에 박았습니다 —
  **담은 범위와 "무엇이 빠졌는지" 를 문서에 적습니다**

#### ③ 답이 어느 문항의 것인지 (C6) — 원래 있던 잠재 버그

문항을 내리는 기능을 만들다가, **`answers` 가 자리(index)로만 문항을 가리키고
있다**는 것을 알았습니다. 문항 하나를 내리면 그 뒤에 푼 사람의 답이 한 칸씩 밀려서
**대시보드가 "끼임 항목 정답률"이라고 말하면서 다른 문항의 숫자를 보여 줍니다.**

> **틀린 곳을 못 잡는 것보다, 엉뚱한 곳을 가리키는 쪽이 나쁩니다.** 그걸 보고 교육을 고칩니다.

→ `progress.quiz.asked` 를 남기고 읽는 통로를 `Store.askedQuestion` 하나로 모았습니다.
**이 어긋남은 C6 이 만든 게 아니라 원래 있었고, 예시 데이터가 멀쩡해서 안 보였을 뿐**입니다.

#### ④ 기능은 만들었는데 들어갈 길이 없었다 (C7)

관리자 답글 기능을 다 만들고 보니, **담당자가 게시판에 들어올 링크가 한 곳도
없었습니다.** 주소를 직접 쳐야 했습니다. 들어가게 했더니 이번엔 **아래에 노동자
탭바가 그대로 떠서** 누르면 대시보드로 튕겼습니다.

> **튕기는 것과 돌아가는 것은 다릅니다. 튕기면 사람은 그것을 고장으로 읽습니다.**

#### ⑤ 저시력 사용자에게 "한 번 깜빡임" 은 안 보이는 화면 (B3)

글자 크기를 `ui.js`(문서 끝)에서 적용하면 **기본 크기로 한 번 그려졌다가 커집니다.**
멀쩡해 보이지만, **글자가 안 보여서 이 기능을 찾아온 사람에게는 그 한 번이
"안 보이는 화면"** 입니다. → `store.js` 가 `<head>` 에서 적용하게 바꿨습니다.

그리고 **고르는 칸의 "가" 를 실제 그 크기로 그렸습니다.**
*"작게 / 보통 / 크게"* 라는 **글자를 읽어야 고를 수 있으면 소용이 없습니다.**

#### ⑥ 배지를 붙이고 소리를 빠뜨릴 뻔했다 (B4)

메뉴에 *"익명으로 접수"* 배지를 붙였는데, **눈에만 보이게 두면
글을 못 읽는 사람에게는 없는 정보**입니다. → 음성에도 넣었습니다 (아이콘은 빼고).

#### ⑦ 카카오톡 안에서 음성이 조용히 실패한다 (V4)

폰 확인에서 찾았습니다. 카톡 내장 브라우저가 `speechSynthesis` 가 있다고 대답하고
목소리 목록도 주고 `speak()` 도 받아 놓고 **아무 소리도 내지 않습니다.**
그런데 현장에서 교육 링크를 보내는 **가장 흔한 방법이 카톡**입니다.

> 글을 읽을 수 있는 사람은 "소리가 안 나네" 하고 넘어가지만,
> **크메르어 노동자에게는 그 화면이 통째로 빈 화면**입니다.
> 그런데 화면은 아무 일 없다는 얼굴을 하고 있고 **그대로 이해도 검증을 통과합니다.**
> **이 제품이 막겠다고 만든 상황이 바로 그것입니다.**

→ **브라우저 이름으로 넘겨짚지 않고**, 실제로 소리가 시작됐다는 신호가 오는지를
보고 판정합니다. 그래야 카톡이든 나중에 나올 무엇이든 같이 걸립니다.

#### ⑧ 첫 배포가 텅 빈 화면이었다 (V2)

운영 브랜치가 `main` 인데 그때 `main` 의 `src/` 는 비어 있었습니다.
그리고 **`develop` 을 먼저 push 하면 Vercel 이 `main` 배포를 건너뜁니다.**
→ **push 순서는 `main` 이 먼저**라는 규칙이 여기서 나왔습니다.

#### ⑨ 문서와 화면이 다른 말을 하고 있었다 (B5)

`07-next-tasks.md` 는 "여덟 화면에 세 가지" 라고 적고 있었는데
**실제로 지울 것은 3줄뿐**이었습니다. 문서 말만 믿고 지웠으면
**아직 안 만든 일까지 함께 사라질 뻔했습니다.**

> 문서와 화면이 다른 말을 하면 **사람은 화면을 믿습니다.**

→ 그때부터 `test-docs.js` 가 화면의 "할 일" 칸 **안**을 봅니다.

## 6. 구현·확장 가능성

### 6.1 지금 구현 수준 (증거)

| | |
|---|---|
| 화면 | **11개 전부 실동작.** 껍데기 없음 |
| 코드 | `src/` 약 **15,000줄**, 검사 약 **5,400줄** |
| 검사 | **1,219건 · 10묶음 · 전부 통과** |
| 배포 | **살아 있음** — https://2026-ax-ton.vercel.app |
| 데이터 | 10칸, 서버가 생기면 **그대로 테이블 10개** |
| 커밋 | 기능 단위로 나뉘어 있고 **커밋 메시지에 "왜" 가 적혀 있음** |

### 6.2 서버를 붙이면 — 이미 자리를 만들어 뒀습니다

```
[화면 11개]  →  [ Store ]  →  지금: 브라우저 저장소
                    ↑
              여기 안쪽만 서버 호출로 바꿉니다.
              화면 11개는 한 줄도 안 고쳐도 됩니다.
```

**브라우저 저장소를 직접 부르는 코드가 저장소 전체에 단 한 곳뿐인지를
자동 검사가 매번 확인합니다.** 이게 이 프로젝트에서 가장 값진 설계 결정입니다.

| 순서 | 무엇 | 크기 |
|---|---|---|
| 1 | Vercel Functions (같은 배포 구조에 폴더 하나 추가) | 중간 |
| 2 | 관리형 PostgreSQL — 위 10칸이 **테이블 10개** | 중간 |
| 3 | `store.js` 안쪽 교체 | **작음** ← 여기가 핵심 |
| 4 | 진짜 인증 (지금은 목업이라고 화면에 밝혀 놓음) | 중간 |
| 5 | 파일 저장소 (신고 사진·음성 메모) | 중간 |

### 6.3 그러면 비로소 되는 것

담당자 PC 에서 만든 교육을 **노동자 폰에서 바로** · 여러 사업장 · 데이터가 안 날아감
· 신고에 **사진** · **기한 알림** · 설비 앞 QR 이 진짜 의미를 가짐(이미 구현됨)
· **오프라인 대응**

### 6.4 그때 잃는 것 — 미리 알아 둘 것

- **더블클릭으로 여는 확인 방법이 사라집니다** (지금 가장 빠른 검증 수단)
- 인터넷 없이 동작하지 않습니다 → **오프라인 대응이 별도 과제**가 됩니다
- 개인정보를 서버에 담게 되므로 **보안·법적 책임이 실제로 발생**합니다

> **지금 서버를 안 붙인 것은 게을러서가 아닙니다.**
> 서버 없이도 **제품의 핵심 주장(이해도 검증)을 전부 증명할 수 있고**,
> 붙일 자리는 미리 만들어 뒀습니다.
> *"사진이 필요해지는 시점이 곧 서버가 필요해지는 시점"* 이 이 프로젝트의 기준선입니다.

## 7. 현재 개발 수준 · 그 이유 · 한계

### 7.1 한마디로

> **"프로토타입" 이 아니라 "서버가 빠진 완제품" 입니다.**
> 화면 11개가 실제 데이터로 끝까지 돌고, 배포돼 있고, 검사 1,219건이 지킵니다.
> **빠진 것은 기능이 아니라 서버입니다.**

### 7.2 왜 이 수준에서 멈췄나 (의도적 선택)

| 안 한 것 | 왜 |
|---|---|
| 서버·DB | **핵심 주장(이해도 검증)을 증명하는 데 필요 없음.** 붙일 자리만 만들어 둠 |
| 프레임워크 | 빌드가 생기면 **더블클릭 확인**을 잃음 |
| AI 번역 연동 | 외부 요청 0건 규칙. 그리고 **검증 없이 번역만 붙이면 오역이 그대로 사고** |
| 진짜 인증 | 서버 없이는 불가능. **목업이라고 화면에 밝혀 놓는 쪽**을 택함 |
| 다중 사업장 | 하나로도 전체 흐름이 증명됨 |

### 7.3 알고 있는 한계 (전부)

| 한계 | 무엇을 하면 풀리나 |
|---|---|
| 기기 사이 데이터 공유 안 됨 | 서버 |
| 사업장 하나 전제 (증빙 표지) | 다중 사업장 모델 |
| 증빙에 쪽 번호 없음 | 작은 작업 |
| 댓글은 수정·삭제 못 함 | 작은 작업 (C3 와 같은 규칙) |
| 재교육 지시 메모가 한국어 | 지시 문구도 라이브러리에서 고르게 (E층) |
| 문항 문구가 검수를 안 거침 | 문항 검수 (E층) |
| 번역·역번역을 같은 사람이 입력 | **사람 절차 문제라 화면으로 못 막음** |
| 브라우저 음성이라 발음이 어색할 수 있음 | 서버 + 음성 검수 |
| 노동자에게 교육 기한이 안 보임 | 작은 작업 |
| PC 레이아웃 치수가 숫자로 박힘 | 작은 작업 |
| **QR 을 폰으로 안 찍어 봄** | **내일** |
| **"글자 없이 끝까지" 실증 안 됨** | **내일** |

## 8. 예상 질문과 답

> 발표 담당자용. **모르면 모른다고 하는 편이 낫습니다.**

| 질문 | 답의 뼈대 |
|---|---|
| **"직접 해보셨나요?"** | 폰으로 확인했고(2026-08-25) 거기서 카톡 음성 문제를 찾았습니다. **다만 '글자를 한 자도 안 읽고 끝까지'는 아직 제대로 실증 못 했습니다** — 만든 사람은 어디를 눌러야 할지 이미 알기 때문입니다. 그래서 다른 사람에게 아무 설명 없이 폰을 건네는 것을 남은 과제로 적어 뒀습니다 |
| **"이미 공단이 다국어 교육을 하지 않나요?"** | 맞습니다. 16~17개 언어 자료가 있습니다. **그건 "전달"까지입니다.** 저희가 하는 것은 **"그 사람이 이해했는지"를 개인별로, 글자 없이 확인하고 그 결과를 증빙에 넣는 것**입니다 |
| **"기존 온라인 교육에도 시험이 있는데요?"** | 대부분 **객관식 필기**입니다. **한국어를 읽어야 합니다.** 저희 문항은 세 유형 전부 손가락 조작입니다 — 그림에서 위험 지점 짚기, 올바른 작업 고르기, 보호구 연결하기 |
| **"AI 를 어디에 썼나요?"** | 두 층입니다. **제품 안**에서는 초벌 번역·역번역 대조·음성 합성까지가 AI 이고 **판정은 사람**입니다 (화면에 그 경계를 적어 놨습니다). **개발**에는 Claude Code 를 썼고, 규칙을 `CLAUDE.md` 로 주입하고 **검사를 쓴 뒤 일부러 망가뜨려 그 검사가 정말 잡는지 확인**하는 절차로 일했습니다 |
| **"AI 번역이 실제로 도나요?"** | **아직 안 붙였습니다.** 외부 요청 0건 규칙 때문이고, 더 중요하게는 **검증 없이 번역만 붙이면 오역이 그대로 사고**가 되기 때문에 **검증 쪽(역번역 대조·판정 권한 분리)을 먼저** 만들었습니다 |
| **"이거 따라 하기 쉽지 않나요?"** | 아이디어는 따라 할 수 있습니다. **다만 검수된 다국어 문구와 언어별 오답 데이터는 시간이 지날수록 쌓이고, 복제하려면 같은 검수 비용을 다시 치러야 합니다.** 그리고 몇 가지는 **일부러 사업주에게 불편하게** 만들어서(미이수 숨김 불가, 인사 목적 내보내기 없음) 영업 논리로는 따라 하기 어렵습니다 |
| **"왜 서버가 없나요?"** | 핵심 주장을 증명하는 데 필요 없었고, **붙일 자리는 만들어 뒀습니다.** 브라우저 저장소를 부르는 코드가 `store.js` 한 곳뿐인지 자동 검사가 매번 확인합니다. 서버가 생기면 그 안쪽만 바꾸고 **화면 11개는 그대로**입니다 |
| **"검사 1,219건은 무엇을 보나요?"** | 동작뿐 아니라 **제품 원칙**을 봅니다 — 신고에 식별값이 없는지, 미이수자를 숨기는 경로가 생기지 않았는지, 증빙에 "면책"이 없는지. **CSS 한 줄로 정보 위계가 뒤집히는 것까지** 검사합니다 |
| **"가장 어려웠던 게 뭐였나요?"** | QR 을 외부 라이브러리 없이 만든 것이 가장 컸지만, **가장 무서웠던 것은 답이 어느 문항의 것인지가 어긋날 수 있다는 걸 발견한 때**입니다. 대시보드가 "끼임 항목 정답률"이라고 말하면서 다른 문항의 숫자를 보여 줄 수 있었습니다. **틀린 곳을 못 잡는 것보다 엉뚱한 곳을 가리키는 쪽이 나쁩니다** |
| **"수익 모델은요?"** | 이번 범위에서 다루지 않았습니다. 참고할 만한 것은 민간 안전보건교육 SaaS 가 **사업주의 법정 의무 이행**을 팔고 있다는 점입니다 |
