# 02. 아키텍처와 플로우차트

**그림 7장. 슬라이드에 그대로 옮겨 쓸 수 있게 만들었습니다.**

> **왜 mermaid 로 적었나** — GitHub 에서 바로 그림으로 보이고, 필요하면
> 캡쳐해서 슬라이드에 붙이면 됩니다. 기존 문서의 도해는 전부 ASCII 라
> 슬라이드에 붙이면 깨져 보입니다.
>
> **★ 발표에서 아키텍처를 오래 설명하지 마세요.** 심사위원이 보고 싶은 것은
> 구조의 아름다움이 아니라 **"이 팀이 자기가 만든 걸 아는가"** 입니다.
> 그림 1·2 만 쓰고 나머지는 질문받을 때 꺼내는 것을 권합니다.

## 그림 1. 시스템 구조 — 3층

**발표용 1순위.** 이 한 장으로 "빌드 없는 정적 웹" 과 "서버 붙일 자리" 가 동시에 설명됩니다.

```mermaid
flowchart TB
    subgraph L1["화면 13개 — HTML + JS 한 쌍씩"]
        direction LR
        W["노동자 6개<br/>홈 · 수강 · 검증<br/>신고 · 소통 · 마이"]
        A["관리자·운영자 5개<br/>사업장 · 콘텐츠 · 대시보드<br/>증빙 · 문구 라이브러리"]
        G["로그인 · 회원가입"]
    end

    subgraph L2["공용 assets — 11개 화면이 전부 씀"]
        direction LR
        AU["auth.js<br/>세션·화면 가드"]
        UI["ui.js<br/>화면 부품 + 음성"]
        I18["i18n.js<br/>화면 다국어 6언어"]
        RV["review.js<br/>역번역 대조"]
        DG["diagrams.js<br/>설비 그림 SVG"]
        QR["qr.js<br/>QR 직접 생성"]
    end

    ST["Store — 데이터 통로 10칸<br/>★ 서버는 여기만 바꾸면 됩니다"]
    LS[("브라우저 localStorage<br/>약 5MB")]
    SW["sw.js<br/>오프라인 캐시"]

    L1 --> L2
    L1 --> ST
    L2 --> ST
    ST --> LS
    L1 -.->|"화면 파일을 담아 둠"| SW

    style ST fill:#1f6feb,color:#fff,stroke-width:0px
    style LS fill:#8b5cf6,color:#fff,stroke-width:0px
    style SW fill:#0f766e,color:#fff,stroke-width:0px
```

> **말할 것** — *"화면 11개가 데이터를 직접 만지지 않습니다.
> 전부 `Store` 한 곳을 지나갑니다. 그래서 서버를 붙일 때
> **화면은 한 줄도 안 고칩니다.** 지금 저 파란 상자 안쪽만 바꾸면 됩니다."*

## 그림 2. 전체 흐름 — 개선 루프가 도는 것이 핵심

**발표용 2순위.** ⑤가 제품의 심장이고, **⑥ → ③ 으로 돌아오는 화살표**가 차별점입니다.

```mermaid
flowchart TD
    S1["① 담당자<br/>사업장·공정·설비·언어 등록"] --> S2
    S2["② 운영자<br/>안전 문구 번역 검수"] --> S3
    S3["③ 담당자<br/>검수된 문구로 교육 생성 + 문항"] --> S4
    S4["④ 노동자<br/>내 언어 음성으로 수강"] --> S5
    S5["⑤ 노동자<br/>이해했는지 그림으로 확인"]
    S5 --> S6["⑥ 담당자<br/>어느 언어의 누가 무엇에서 막혔나"]
    S6 -->|"교육을 고친다"| S3
    S6 --> S7["⑦ 감독기관 제출 증빙 인쇄"]

    R1["상시 · 노동자<br/>위험요소 익명 신고"] --> S6
    R2["상시 · 현장 공지·질문"] -.-> S6

    style S5 fill:#dc2626,color:#fff,stroke-width:0px
    style S6 fill:#1f6feb,color:#fff,stroke-width:0px
    style S2 fill:#0f766e,color:#fff,stroke-width:0px
```

> **말할 것** — *"②에서 검수를 지나지 않은 문구는 어느 화면에도 안 나옵니다.
> ⑤가 저희가 만든 것이고, **⑥에서 ③으로 돌아가는 화살표가 다른 서비스에 없는 것**입니다.
> 남들은 ④에서 끝납니다."*

## 그림 3. 이해도 검증 — 글자 없이 판정하는 길

```mermaid
flowchart LR
    Q["문항"] --> T{"유형"}
    T -->|hotspot| H["설비 그림에서<br/>위험 지점 짚기 👆"]
    T -->|choice| C["올바른 작업 고르기 ☑"]
    T -->|match| M["보호구 연결하기 🔗"]

    H --> SC["채점"]
    C --> SC
    M --> SC

    SC --> RES{"결과"}
    RES -->|맞음| OK["왜 맞는지<br/>+ 사고 결과 설명"]
    RES -->|틀림| NG["★ 어떤 사고가 되는지<br/>바로 말해 준다"]

    OK --> P{"전체 통과?"}
    NG --> P
    P -->|통과| DONE["교육 완료로 기록<br/>증빙에 남음"]
    P -->|미통과| FAIL["★ 미통과는<br/>교육의 실패로 표기<br/>노동자 평가 아님"]
    FAIL --> ORD["담당자가 재교육 지시"]
    ORD --> Q

    style NG fill:#dc2626,color:#fff,stroke-width:0px
    style FAIL fill:#b45309,color:#fff,stroke-width:0px
```

> **말할 것** — *"세 유형 전부 손가락으로만 합니다. **문항이 글로 돌아가는 순간
> 이건 기존 필기시험**이 되기 때문입니다. 그리고 틀렸을 때 정답만 알려 주지 않고
> **그 선택이 어떤 사고가 되는지**를 말해 줍니다. 안 그러면 다음에 또 같은 선택을 합니다."*

## 그림 4. 안전 문구가 노동자에게 닿기까지 — 검수 게이트

**"검수되지 않은 번역은 안전 지시로 쓰지 않는다"** 가 구조로 어떻게 지켜지는지.

```mermaid
flowchart TD
    NEW["새 안전 문구 등록"] --> W["status: waiting<br/>검수 대기"]
    W --> RVW{"운영자 검수<br/>+ 역번역 대조"}
    RVW -->|"부정 뒤집힘 경고"| BACK["반려"]
    BACK --> W
    RVW -->|승인| OKS["status: reviewed<br/>언어별로 판정"]

    OKS --> LANG{"노동자의 언어로<br/>Store.phraseOk"}
    LANG -->|"그 언어 승인됨"| SHOW["교육에 나간다"]
    LANG -->|"그 언어만 중지"| HIDE["그 언어에서만 빠진다<br/>★ 다른 언어는 계속 나간다"]

    FLAG["오역 신고<br/>어느 언어의 신고인지 남긴다"] -->|"접수 즉시 중지"| HIDE

    style W fill:#b45309,color:#fff,stroke-width:0px
    style SHOW fill:#15803d,color:#fff,stroke-width:0px
    style HIDE fill:#dc2626,color:#fff,stroke-width:0px
```

> **말할 것** — *"크메르어 번역만 뜻이 뒤집혔으면 **크메르어만 내립니다.**
> 문구 전체를 내리면 인도네시아어 노동자도 그 안전 지시를 못 듣게 되는데,
> 그건 오역보다 나은 상태가 아닙니다."*

## 그림 5. 음성 판정 — 조용히 실패하지 않게

**가장 최근에 만든 것이고, 깊이를 보여주기 좋습니다.** 질문받으면 꺼내세요.

```mermaid
flowchart TD
    TAP["노동자가 🔊 를 누른다"] --> B{"브라우저가<br/>소리를 낼 수 있나"}
    B -->|"못 낸다<br/>(카톡 인앱 등)"| BLK["🔇 + '다른 브라우저로<br/>열어 주세요'<br/>그 사람 언어로"]
    B -->|낼 수 있다| V{"이 기기에 그 사람<br/>언어 음성이 있나"}

    V -->|있다| PLAY["★ 그 사람의 언어로 읽는다"]
    V -->|없다| KO{"한국어 사용자인가"}

    KO -->|"그렇다"| PLAYKO["한국어로 읽는다<br/>(한국어도 노동자의 언어)"]
    KO -->|아니다| PREF{"마이에서 무엇을<br/>골라 뒀나"}

    PREF -->|"소리 안 냄 (기본)"| SIL["🔇 + '이 기기에 OO 음성이<br/>없어 소리가 나지 않습니다.<br/>마이에서 한국어로 들을 수 있습니다'"]
    PREF -->|"한국어로 듣기"| KOF["한국어로 읽고<br/>★ 그 사실을 화면에 계속 적어 둔다"]

    style PLAY fill:#15803d,color:#fff,stroke-width:0px
    style SIL fill:#dc2626,color:#fff,stroke-width:0px
    style BLK fill:#dc2626,color:#fff,stroke-width:0px
```

> **말할 것** — *"음성이 없을 때 한국어로 대신 읽어 주던 것을 **일부러 그만뒀습니다.**
> 크메르어 노동자에게 한국어 소리는 뜻이 닿지 않는데, **소리는 나는데 아무것도
> 전달되지 않으면 사람은 '들었다'고 생각하고 그대로 검증을 통과합니다.**
> 저희가 막으려는 상황이 정확히 그겁니다.
> 그래서 기본은 소리를 안 내고, **왜 안 내는지를 그 사람의 언어로 화면에 적습니다.**"*

## 그림 7. 검증 파이프라인 — 무엇이 무엇을 지키나

```mermaid
flowchart TD
    CODE["코드를 고친다"] --> RUN["node tests/run-all.js"]
    RUN --> BUNDLE["묶음 14개 · 단정 1,463건"]

    BUNDLE --> T1["동작 검사<br/>화면이 실제로 도는가"]
    BUNDLE --> T2["★ 제품 원칙 검사<br/>익명성 · 미이수 숨김 금지<br/>검수 게이트 · '면책' 금지"]
    BUNDLE --> T3["코드 규칙 검사<br/>외부 요청 0건 · innerHTML 금지<br/>localStorage 직접 호출 금지"]
    BUNDLE --> T4["문서 검사<br/>끝난 기능이 할 일로 남아 있지 않은가"]

    T1 --> PASS{"전부 통과?"}
    T2 --> PASS
    T3 --> PASS
    T4 --> PASS

    PASS -->|"아니다"| CODE
    PASS -->|그렇다| SAB["★ 일부러 망가뜨려 본다<br/>검사가 잡는지 확인"]
    SAB -->|"안 잡힘"| FIX["그 검사는 아무것도 지키지 않는다<br/>→ 검사를 고친다"]
    FIX --> SAB
    SAB -->|잡힘| HAND["폰·브라우저로 손 확인"]
    HAND --> DEPLOY["main 에 push → 자동 배포"]
    DEPLOY --> VERIFY["★ 실제 주소를 열어서 확인<br/>push 됐다고 배포된 것이 아니다"]

    style T2 fill:#dc2626,color:#fff,stroke-width:0px
    style SAB fill:#b45309,color:#fff,stroke-width:0px
    style VERIFY fill:#0f766e,color:#fff,stroke-width:0px
```

> **말할 것** — *"검사가 동작만 보지 않습니다. **제품 원칙이 코드에 남아 있는지**도 봅니다.
> 신고에 신고자를 식별할 값이 들어오면 검사가 깨집니다.
> 증빙에 '면책'이라는 단어가 들어오면 검사가 깨집니다.
> 그리고 **검사를 믿지 않으려고 일부러 망가뜨려 봅니다.** 안 잡히면 그 검사는
> 아무것도 지키지 않는 것이니까요."*
