# 07. 디자인 · UI/UX 의사결정

> **발표에서 디자인을 "예쁘다" 로 말하면 잃습니다.**
> 심사위원은 미적 감각을 평가하지 않습니다. **"이 결정에 이유가 있는가"** 를 봅니다.
>
> 이 화면들은 예쁘게 만든 것이 아니라 **장갑 낀 손 · 글자를 못 읽는 눈 ·
> 흑백으로 인쇄되는 증빙**을 기준으로 만든 것입니다. 그게 할 이야기입니다.

---

## 1. ★ 한 문장으로

> *"저희 화면의 기준은 **'보기 좋은가'** 가 아니라
> **'장갑 낀 손으로 눌리는가 · 글자를 못 읽어도 뜻이 남는가 · 흑백으로 인쇄해도 읽히는가'** 였습니다."*

---

## 2. ★ 이모지를 그만두고 선 아이콘으로 바꿨습니다 (2026-08-30)

**받은 피드백** — *"실제 프로그램에서는 이모지보다 아이콘으로 더 진지하게 예쁘게 (톤앤매너)"*

바꿨습니다. 화면 13개에 **선 아이콘 294개**가 들어가고 **이모지는 0개** 남았습니다.

### 왜 이모지가 문제였나 — 세 가지

| | |
|---|---|
| **기기마다 다르게 그려집니다** | 같은 ⚠ 가 안드로이드와 다른 기기에서 다른 모양입니다. **안전 지시를 하는 화면이 기기마다 달라 보이면 안 됩니다** |
| **말투가 가볍습니다** | 둥글고 알록달록합니다. 현장에서 쓰는 **안전보건 픽토그램은 전부 단색 선 그림**입니다 |
| **흑백 인쇄에서 무너집니다** | 증빙은 흑백으로 나갑니다. 색으로 그려진 이모지는 회색 덩어리가 됩니다 |

### 어떻게 만들었나

- **`assets/icons.js` — 아이콘 47개.** 전부 24×24 좌표계, 선 굵기 1.7, 색은 글자색을 따라갑니다
- **외부 요청 0건을 지켰습니다.** 아이콘 폰트도 SVG 파일도 안 씁니다 — **좌표만 든 인라인 SVG**입니다
- **`innerHTML` 을 안 씁니다.** `createElementNS` 로 만듭니다 (`diagrams.js` 와 같은 방식)

### ★ 이 작업에서 판단한 것 세 가지 — 발표에서 쓸 값이 있습니다

**① 저장된 데이터를 고치지 않았습니다**

담당자가 등록한 설비 아이콘은 `localStorage` 에 **이모지로** 들어 있습니다.
그 값을 바꾸면 **이미 등록해 둔 사업장이 깨집니다.**
→ 저장은 그대로 두고 **그릴 때만** 바꿉니다. 마이그레이션 0건입니다.

**② HTML 의 이모지를 지우지 않았습니다**

> *"JS 가 멈추면 하단 탭이 통째로 비어 보입니다.
> 그래서 HTML 에는 이모지를 남겨 두고, **화면이 뜰 때 더 좋은 그림으로 바꿔 끼웁니다.**
> 화면 글자를 번역할 때 한국어 원문을 남겨 둔 것과 같은 대비책입니다."*

**③ 모르는 값은 글자로 그대로 내보냅니다**

담당자가 직접 넣은 그림문자가 **조용히 사라지면 안 됩니다.**
아이콘 표에 없는 값은 글자 그대로 나갑니다.

### 그리고 검사로 박았습니다 — 검사 95건

**`tests/test-icons.js` 가 화면 13개를 실제로 그려 보고, 이모지가 하나라도 남아 있으면 깨집니다.**

> *"아이콘은 한 곳에서 바꿀 수 있는 게 아니라 30개 파일에 흩어져 있습니다.
> 새 버튼에 이모지를 그대로 넣기가 아주 쉽고, 그러면 화면 말투가 다시 섞입니다.
> 그래서 **화면을 그려 보는 검사**를 붙였습니다."*
>
> 그리고 **일부러 9가지를 망가뜨려 9가지 전부 잡히는 것을 확인**했습니다 —
> 버튼에 이모지 넣기 · 아이콘 매핑 빼기 · 스크립트 순서 바꾸기 ·
> 배지 두 개를 같은 그림으로 · 오프라인 목록에서 빼기 …

### 색

기존 색은 **대비를 맞춰 고른 것**이라(WCAG) 글자색은 손대지 않았습니다.
대신 **카드에 옅은 깊이(box-shadow)** 를 넣었습니다 — 테두리 하나로만 구분하면
화면이 납작해 보입니다. 저사양 안드로이드를 생각해 번짐은 얕게 썼고,
**인쇄에서는 그림자를 뺍니다** (흑백에서 회색 얼룩이 됩니다).

---

## 3. 세 겹으로 정보를 줍니다 — 색만으로 구분하지 않습니다

**모든 상태 표시가 아이콘 + 글자 + 색 세 가지를 동시에** 씁니다.

| 상태 | 아이콘 | 글자 | 색 |
|---|---|---|---|
| 완료 | ✓ | "이수" | 초록 |
| 대기 | ● | "검수 대기" | 주황 |
| 중지 | ● | "중지됨" | 빨강 |

**왜** — 색약인 사람이 있고, **증빙은 흑백으로 인쇄됩니다.**
색이 사라져도 뜻이 남아야 합니다.

> **★ 이건 검사가 지킵니다.** `UI.okBadge` `waitBadge` `stopBadge` `neutralBadge` 를
> 거치지 않고 색만 바꾸는 코드가 들어오면 잡힙니다.

---

## 4. 터치 타깃 — 노동자 화면은 전부 60px

| 어디 | 크기 | 왜 |
|---|---|---|
| 노동자 화면 전부 | **60px 이상** | **장갑 낀 손**으로 조작합니다 |
| 관리자 주요 버튼 | 60px | |
| 관리자 표 안 보조 조작 | 40px | 사무실 PC 에서 마우스로 씁니다 |

**두 벌로 나눈 이유** — 담당자는 사무실 PC, 노동자는 현장 폰입니다.
같은 규격을 강요하면 한쪽이 불편해집니다.

---

## 5. ★ 실제 시행착오 — 발표에서 쓰기 좋은 것 6개

### ① 저시력 사용자에게 "한 번 깜빡임" 은 안 보이는 화면입니다

글자 크기를 문서 **끝**에서 적용했더니, **기본 크기로 한 번 그려졌다가 커졌습니다.**
멀쩡해 보이지만 저시력 사용자에게는 그 한 번이 "안 보이는 화면" 입니다.
→ `<head>` 에서 적용하도록 옮겼습니다.

### ② 고르는 칸의 "가" 가 실제로 그 크기입니다

**"작게 / 보통 / 크게" 라는 글자를 읽어야 고를 수 있으면,
글자가 안 보여서 여기 온 사람에게는 소용이 없습니다.**
→ 칩에 적힌 "가" 를 각각 실제 그 크기로 그렸습니다. **눈으로 고를 수 있습니다.**

### ③ 글자 크기를 계정이 아니라 기기에 붙였습니다

계정에 넣으면 **로그인해야 글자가 커집니다.**
그런데 **로그인 화면 글자가 안 보이는 사람은 거기서 막힙니다.**
→ `Store.prefs` 는 기기 설정입니다. 예시 데이터를 채워도 안 되돌아갑니다.

### ④ 배지를 붙이고 소리를 빠뜨릴 뻔했습니다

*"익명으로 접수"* 배지를 **눈에만 보이게** 뒀습니다.
**글을 못 읽는 사람에게는 없는 정보입니다.**
→ 안내 음성에도 넣었습니다 (아이콘은 빼고 글자만 읽습니다).

### ⑤ 튕기는 것과 돌아가는 것은 다릅니다

관리자 화면에 노동자 하단 탭바가 떠 있어서, 누르면 **튕겼습니다.**
**사람은 튕기는 것을 고장으로 읽습니다.**
→ 역할에 맞는 탭바만 그리도록 고쳤습니다.

### ⑥ 버튼을 조용히 없애지 않습니다

받아쓰기가 안 되는 브라우저에서 **버튼을 감추는 게 깔끔해 보였습니다.**
그런데 **조용히 없어지면 사람은 고장으로 읽습니다.**
→ 버튼은 남기고, **왜 안 되는지와 손으로 쓰는 길을 그 사람의 언어로** 적습니다.

> ### 발표에서 쓸 한 수
> *"이 여섯 개의 공통점은 **화면이 조용히 실패하지 않게** 만든 것입니다.
> **가장 위험한 고장은 화면이 멀쩡한 얼굴을 하고 있는 고장입니다.**"*

---

## 6. 정보 위계 — CSS 한 줄로 뒤집힐 수 있어서 검사까지 걸었습니다

대시보드에서 **취약 항목 타일이 이수율 타일보다 커야** 합니다.

**왜** — 이수율은 이 제품이 부정하는 지표입니다.
그게 화면에서 더 크면 **제품이 자기 주장을 배신합니다.**

> **★ CSS 를 글로 읽어서 검사합니다.** *"CSS 한 줄로 정보 위계가 뒤집힐 수 있어서"* 입니다.
> 발표에서 *"디자인을 검사한다"* 는 말은 흔치 않습니다. 쓸 값이 있습니다.

---

## 7. 그림을 이미지로 안 넣고 코드로 그렸습니다

설비 그림(프레스·도장 부스·배전반)은 **이미지 파일이 아니라 `diagrams.js` 가 SVG 로 그립니다.**

| 왜 | |
|---|---|
| 외부 요청 0건 | 이미지 파일도 요청입니다 |
| **hotspot 좌표를 퍼센트로 저장** | 폰 화면 크기가 달라도 정답이 안 어긋납니다 |
| 오프라인 | 담을 것이 하나 줄어듭니다 |

**QR 도 같은 이유로 직접 만들었습니다** (`assets/qr.js`).
그리고 **가짜 QR 그림은 안 그렸습니다** — *"붙여 놓고 안 찍히는 것이 가장 나쁩니다."*

---

## 8. 일부러 안 만든 UI — 이게 디자인 이야기의 정점입니다

| 안 만든 것 | 왜 |
|---|---|
| 증빙에서 **미이수자 걸러 보기 · 결과순 정렬** | **정렬만 바꿔도 밀어내는 통로**가 됩니다 |
| 증빙 **수정 기능** | 저장하는 코드가 **아예 없습니다**. "수정 불가" 를 규칙이 아니라 **구조**로 |
| 개인 점수의 **인사·평가 목적 내보내기** | 있으면 현장이 등을 돌리고 **신고가 멈춥니다** |
| **"재교육 n회" 누적** | 그건 인사 평가 자료입니다 |
| **"오프라인 가능" 고정 배지** | 목업에 있었지만 안 붙였습니다. **실제 판정 결과만** 보여 줍니다 — 화면이 거짓말을 하면 안 됩니다 |
| 목업의 **"사진 보기"** | 지금 안 되는 일입니다 |

> ### 발표에서 쓸 한 수
> *"시안에 있다고 다 옮기지 않았습니다. **지금 안 되는 일을 화면에 그리면
> 화면이 거짓말을 합니다.** 어떤 것을 안 옮겼는지도 기록해 뒀습니다."*

---

## 9. 디자인을 물으면 — 30초 답

> *"미적으로 잘 만들었다고 말씀드리긴 어렵습니다. 저는 개발자고 디자이너가 없었습니다.
> 대신 **모든 화면 결정에 이유를 붙였습니다.**
> 색만으로 상태를 구분하지 않는 것, 버튼을 60px 로 한 것, 글자 크기 고르는 칸의
> '가' 를 실제 그 크기로 그린 것 — 전부 **누가 이걸 쓰는가**에서 나왔습니다.
> 그리고 몇 개는 **검사로 박아 뒀습니다.** 정보 위계가 CSS 한 줄로 뒤집히는 걸 봤기 때문입니다."*

**이게 "예쁘다" 보다 강합니다.**
