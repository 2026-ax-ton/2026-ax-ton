## 2. ★★ 문서를 자동 검사가 지킵니다 — 이게 가장 안 알려진 무기입니다

`tests/test-docs.js` — **단정 96건.** 코드가 아니라 **문서를 검사합니다.**

### 무엇을 보나

| 검사 | 무엇을 막나 |
|---|---|
| `CLAUDE.md` 의 세션 시작 절차가 **새 문서로 이어지는가** | 안내가 옛 문서를 가리켜 다음 세션이 엉뚱한 걸 읽는 것 |
| 할 일마다 **"어디" 와 "됐는지" 가 있는가** | 실행할 수 없는 할 일이 목록에 남는 것 |
| 문서가 가리키는 **파일이 실제로 존재하는가** | 없는 파일을 가리키는 문서 |
| 문서가 가리키는 **함수 이름이 코드에 실제로 있는가** | 이름이 바뀐 함수를 문서가 계속 부르는 것 |
| 문서가 가리키는 **CSS 클래스가 실제로 있는가** | 같은 이유 |
| 문서끼리 걸어 놓은 **링크가 다 살아 있는가** | 죽은 링크 |
| **상태 표기가 문서끼리 어긋나지 않는가** | 한쪽은 끝났다고, 다른 쪽은 할 일이라고 말하는 것 |
| 끝낸 기능이 **화면의 "여기부터 채우시면 됩니다" 칸에 남아 있지 않은가** | 이미 있는 기능을 또 만들려고 하는 것 |

### 왜 이게 드문가

**문서는 보통 아무도 검사하지 않습니다.** 그래서 문서는 반드시 낡습니다.
그리고 **낡은 문서는 없는 문서보다 나쁩니다** — 사람이 그걸 믿고 움직이니까요.

> ### 발표에서 쓸 한 수
> *"저희는 **문서가 거짓말을 하면 검사가 깨지게** 만들어 놨습니다.
> 문서가 없는 파일을 가리키거나, 이름이 바뀐 함수를 부르거나,
> 이미 끝난 기능을 아직 할 일이라고 적고 있으면 **검사 96건 중 하나가 빨간불이 됩니다.**
> 저희가 문서를 관리했다는 증거는 문서의 분량이 아니라 **이 검사**입니다."*

### ★ 그런데 정직하게 — 그 검사도 놓친 것이 있습니다

**이 검사는 링크와 파일·함수의 존재를 봅니다. 숫자는 안 봅니다.**

그래서 실제로 이런 일이 났습니다 — `docs/발표/2026-09_아이디어톤/presentation/` 은 검사 **1,278건**,
`docs/11-evaluation.md` 는 **1,219건** 이라고 적고 있는데, 실제는 **1,463건** 입니다.
발표 문서를 쓴 뒤에 세 덩어리를 더 만들면서 벌어졌습니다.

> **이걸 숨기지 말고 말하는 게 낫습니다.**
> *"저희 문서 검사도 완벽하지 않습니다. **존재는 검사하는데 숫자는 검사하지 않아서**,
> 발표 문서의 검사 건수가 낡아 있는 걸 사람이 눈으로 찾았습니다.
> 그래서 다음에 붙일 검사가 정해졌습니다 — **문서에 적힌 숫자와 실제를 대조하는 검사**입니다."*

**이게 왜 좋은 답인가** — "우리 검사는 완벽합니다" 보다
**"검사가 놓친 것을 찾았고 그래서 다음 검사가 정해졌다"** 가 훨씬 믿을 만합니다.
그리고 이 프로젝트가 실제로 그렇게 돌아갔다는 증거이기도 합니다.

## 3. 세션이 끊겨도 이어졌습니다 — 실제로 일어난 일

Claude Code 는 대화창이 바뀌면 맥락을 잃습니다. 그래서 **저장소 안 문서를 기억 장치로** 썼습니다.

| 문서 | 역할 |
|---|---|
| `docs/07-next-tasks.md` 맨 위 **"★ 지난 세션이 끝난 자리"** | 지금 상태 + 다음 한 걸음. **이것만 보면 이어갈 수 있음** |
| `docs/09-handover.md` **함정 모음** | **같은 데서 두 번 다치지 않게** |
| `docs/devlog/byeonsoyun.md` | 왜 이 코드가 이렇게 생겼는지 |

**실제 사례 둘**

1. **2026-08-27 세션이 작업 도중 한도로 끊겼습니다.** 다음 세션이 `07-next-tasks.md` 와
   작업대에 남은 코드만 보고 그대로 이어갔습니다
2. **2026-08-30 세션은 작업대에 커밋 안 된 코드가 남아 있는 것을 발견했습니다.**
   문서에는 "작업대 비어 있음" 으로 적혀 있었는데 실제로는 공용 파일 4개가
   반쯤 고쳐진 채 **검사 20건이 깨진 상태**였습니다.
   → 그것부터 마무리했고, **문서와 실제가 어긋난 것 자체가 기록으로 남았습니다**

> **말할 것** — *"새 대화창을 열고 **'docs 보고 바로 진행해줘'** 라고만 치면 이어집니다.
> 그게 되게 만드는 것이 이 프로젝트에서 제가 한 일의 절반입니다."*

## 4. AI 가 잡아낸 결함 — 7·8·9번 (최신)

[`../presentation/04-Claude-활용.md`](../presentation/04-Claude-활용.md) §3 에 **6건**이 있습니다.
그 뒤에 셋이 더 생겼고, **셋 다 같은 종류**라서 이야기가 됩니다.

| # | 무엇을 잡았나 | 왜 위험했나 |
|---:|---|---|
| **7** | **코드 주석이 없는 검사 파일을 가리키고 있었음** — *"이 표가 사전과 어긋나면 검사가 잡는다 (test-voice.js)"* 라고 적혀 있는데 **그 검사가 없었음** | **주석이 지키는 척만 하고 아무것도 지키지 않았음.** 다음 사람은 그 주석을 믿고 표를 고침 → 검사를 실제로 쓰고, **주석이 가리키는 파일 이름 자체도 검사**하게 만들었음 |
| **8** | **설정을 바꿔도 버튼 그림이 안 바뀌는데, 검사가 "우연히" 통과할 상태였음** | 고쳐야 할 버튼이 **그 화면에는 없어서** 통과했음. 버튼이 있는 다른 화면에서 조용히 안 바뀔 것이었음 → 우회하지 않고 통로를 열어 고쳤음 |
| **9** | **한국인 노동자 계정을 넣자 화면이 "내 언어 번역 준비 중" 이라고 거짓말을 시작** | 한국어 사용자에게는 **원문이 곧 그 사람의 언어**고 한국어 번역은 앞으로도 안 생기므로 **그 배지가 영원히 남음** |

> ### ★ 셋의 공통점 — 이게 발표에서 할 이야기입니다
> **셋 다 "동작은 하는데 화면이나 주석이 사실과 다른" 종류입니다.**
>
> *"저희가 가장 무서워하는 고장은 멈추는 고장이 아닙니다.
> **멀쩡한 얼굴을 하고 있는 고장**입니다.
> 글자를 못 읽는 사람에게는 '조용히 아무 일도 안 일어나는 것'이
> 오류 메시지보다 훨씬 위험합니다."*

**그리고 이 셋을 어떻게 찾았나** — 새 기능을 만든 뒤 **10가지를 일부러 망가뜨려 봤고,
10가지 전부 잡히는 것을 확인한 다음에** 그 검사를 믿었습니다.

## 5. 개발 리듬 — "한 덩어리" 를 어떻게 정했나

`CLAUDE.md` 에 적혀 있고, **27편의 개발일지가 그 리듬의 기록**입니다.

```
한 덩어리 = 화면 하나가 동작하거나, 기능 하나가 붙은 시점 (완벽하지 않아도 됨)
        │
        ├─ 1. 개발일지에 한 줄 (한 것 / 막혔던 것 / 남는 한계 / 다음에 할 것)
        ├─ 2. 07-next-tasks.md 의 - [ ] 를 - [x] 로
        ├─ 3. "★ 지난 세션이 끝난 자리" 표 갱신
        ├─ 4. 회귀 검사 (공용 파일을 고쳤으면 반드시)
        ├─ 5. 고친 파일만 git add — git add . 금지
        └─ 6. commit + push
```

> **왜 `git add .` 를 금지했나** — *"무엇을 고쳤는지가 커밋에 그대로 남아야
> 나중에 되짚을 수 있습니다."* 실제로 이 규칙 덕에 커밋 86개가 다 읽힙니다.

## 6. 30초 대본 — 이 축을 물으면

> *"저희는 AI 에게 코드를 시킨 게 아니라, **AI 가 지켜야 할 규칙과
> 스스로를 의심하는 절차를 먼저 만들고** 그 안에서 일하게 했습니다.*
>
> *규칙은 `CLAUDE.md` 에 적어서 **매 세션 자동으로 읽게** 했고,
> 원칙은 문서에만 두지 않고 **검사 1,463건으로 박았습니다.**
> 그중 **96건은 문서 자체를 검사합니다** — 문서가 없는 파일을 가리키거나
> 끝난 기능을 아직 할 일이라고 적고 있으면 검사가 깨집니다.*
>
> *그리고 검사를 쓴 뒤에는 **항상 일부러 망가뜨려 봅니다.**
> 안 잡히면 그 검사는 아무것도 지키지 않는 거니까요.*
>
> *개발일지 27편에는 잘한 것보다 **막혔던 것**이 더 많이 적혀 있습니다.
> 그게 며칠 뒤의 저에게 가장 쓸모 있었습니다."*

## 7. 물으면 이렇게

| 질문 | 답 |
|---|---|
| *"문서를 그렇게 많이 쓸 필요가 있었나요?"* | **혼자 개발하면 원칙이 조용히 무너집니다.** 그리고 대화창이 바뀌면 AI 는 맥락을 잃습니다. 문서는 **다음 세션의 기억**이었습니다 |
| *"문서가 낡지 않았나요?"* | **낡았습니다.** 숫자 몇 개가 실제와 어긋난 걸 찾았습니다. 그래서 **문서를 검사하는 검사 96건**을 붙였고, 다음에 붙일 것(숫자 대조)도 정해졌습니다 |
| *"AI 가 쓴 검사를 어떻게 믿나요?"* | **안 믿습니다.** 일부러 망가뜨려 잡히는지 봅니다. 최근 것은 10가지 중 10가지가 잡혔습니다. QR 검사에서는 **규격 상수와 대조**했습니다 — 그 값은 우리가 정할 수 있는 게 아니니까요 |
| *"이게 다 사람이 시킨 건가요?"* | 규칙과 절차, **무엇을 만들지 않을지**는 사람이 정했습니다. `04` §3 의 "안 만든 것" 표가 그 결과입니다 |
