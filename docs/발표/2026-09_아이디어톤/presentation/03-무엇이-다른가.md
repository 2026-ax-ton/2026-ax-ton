## 2. 차별점 9가지

**✅ = 지금 실제로 됩니다.** 하나도 "예정" 이 아닙니다.

| # | 차별점 | 왜 남들이 쉽게 못 따라오나 | 지금 |
|---|---|---|:---:|
| **1** | **문해력을 전제하지 않는 이해도 검증** — 문항 3유형이 전부 손가락 조작 (👆위험 지점 짚기 · ☑올바른 작업 · 🔗보호구 연결) | 기존 서비스의 평가는 **객관식 필기**가 기본. 바꾸려면 **콘텐츠 제작 방식 전체**를 바꿔야 함 | ✅ |
| **2** | **이해도 결과가 그대로 법정 증빙** — 서명부가 아니라 "무엇을, 어느 언어로, 얼마나 이해했는지" | 증빙 서식과 검증 데이터가 **같은 시스템 안**에 있어야 함. 교육사와 관리 SaaS 가 나뉘어 있으면 붙이기 어려움 | ✅ |
| **3** | **언어별 검수 판정** — 크메르어 오역이 인도네시아어 노동자의 안전 지시를 뺏지 않음 | 대부분 "번역본 하나 = 문서 하나". **언어를 문서의 속성이 아니라 판정의 단위**로 두는 것은 데이터 모델부터 다름 | ✅ |
| **4** | **오역을 사고로 취급하는 파이프라인** — 신고 접수 **즉시 중지**, 역번역 대조로 **부정 뒤집힘만 크게** 경고 | "확인한 뒤 내린다" 가 자연스러운 순서인데 그걸 뒤집음. **오역이 한 시간 더 붙어 있는 것이 더 위험**하다는 판단이 있어야 나옴 | ✅ |
| **5** | **미이수·미통과를 숨길 수 없는 구조** — 증빙에 걸러 보기도 결과순 정렬도 없고, **증빙에는 저장하는 코드가 아예 없음** | 관리 SaaS 의 판매 포인트는 보통 **"과태료 위험 알림"**, 즉 사업주 편의. **사업주가 불편해지는 설계는 영업상 하기 어려움** | ✅ |
| **6** | **위험요소 익명 신고를 선행지표로** — `reports` 에 식별값이 **한 개도** 없음. "내가 낸 신고" 조차 안 만듦 | 익명을 **화면 규칙이 아니라 데이터 구조**로 만든 것. 나중에 붙이면 **이미 저장된 식별값이 남음** | ✅ |
| **7** | **미통과 = 교육의 실패** — 개인 점수의 인사·평가 목적 내보내기를 **아예 안 만듦** | 이 기능이 없는 것이 **팔기에 불리**. 그런데 있으면 현장이 등을 돌리고 신고가 멈춤 | ✅ |
| **8** | **설비 앞 QR → 그 설비 교육** — 외부 라이브러리 없이 QR 을 직접 만들고, 로그인을 거쳐도 목적지를 안 잃음 | 기술이 어렵진 않으나 **"작업 직전, 그 설비 앞에서"** 라는 **교육 시점**을 잡은 설계 | ✅ |
| **9** | **오프라인 우선 · 외부 요청 0건** — 인터넷이 끊겨도 열림 | *"현장 인터넷이 약하다"* 를 **처음부터** 전제로 넣어야 나오는 구조. 나중에 넣기 어려움 | ✅ |

### ★ 발표에서 고를 셋

시간이 없으면 **1 · 5 · 3** 만 말합니다.

**① 문해력 비전제** — *"한국어를 못 읽어서 생긴 문제를, 한국어를 읽어야 푸는
시험으로 확인하고 있었습니다."*

**⑤ 숨길 수 없는 구조** — *"저희는 사업주를 일부러 불편하게 만들었습니다.
증빙에는 데이터를 쓰는 코드가 아예 없습니다. 사본이 없으니 고칠 경로도 없습니다.
**'수정 불가'를 규칙이 아니라 구조로 만든 것**입니다."*

**③ 언어별 판정** — *"지금은 오역 하나가 발견되면 그 문구가 통째로 내려갑니다.
크메르어 번역만 잘못됐는데 **인도네시아어 노동자도 그 안전 지시를 못 듣게**
됩니다. 저희는 그 언어만 내립니다."*
→ **시연 1·2번이 정확히 이 장면입니다.**

## 3. "따라 하기 쉽지 않나요?" 에 대한 답

**가장 아픈 질문입니다. 정면으로 인정하고 다음을 말합니다.**

> *"아이디어 자체는 따라 할 수 있습니다. 지금의 차별점은 대부분 **설계 철학**에서
> 옵니다. 다만 이 서비스가 돌수록 **복제하려면 같은 비용을 다시 치러야 하는 것**이
> 쌓입니다."*

| # | 무엇 | 왜 시간이 지날수록 강해지나 | 필요한 것 |
|---|---|---|---|
| **A** | **검수된 다국어 안전 문구 라이브러리** (목표 200개 × 6언어) | 번역 하나하나에 **사람의 검수**가 붙어 있음. 오역 신고가 쌓일수록 정확해짐. **경쟁자는 같은 검수 비용을 다시 치러야 함** | 시간 · 원어민 검수자 |
| **B** | **문항별·언어별 오답 데이터** | *"크메르어 노동자는 잔류 압력 개념에서 막힌다"* 같은 데이터는 **이 서비스 안에서만 생김**. 쌓이면 **어떤 설명이 어느 언어에서 통하는지**를 알게 됨 | 사용자 수 |
| **C** | **문항 난이도 자동 관측** (최초 통과율이 70~85% 밖이면 경고) | B 위에서만 돎. **콘텐츠가 스스로 좋아지는 루프** | B + 서버 |
| **D** | **감독기관 서식 연동 · 증빙 위조 검증** | 한 번 인정받으면 **바꾸기 어려운 표준**이 됨 | 기관 협의 |

> **그리고 하나 더** — 차별점 **5·7 은 따라 하기가 기술이 아니라 의지의 문제**입니다.
> 미이수자를 숨길 수 없게 만들고 인사 목적 내보내기를 안 만드는 것은,
> **팔기에 불리한 방향**입니다. 그쪽으로 가는 회사는 많지 않습니다.

## 4. 구현 수준 — "어느 정도 만들었나"

> **평가지표: *"교육 기간 내 시도한 수준에서 방향이 타당하고, 이후 발전
> 가능성이 보이는가"*** (12점)

### 4.1 한마디로

> **"프로토타입" 이 아니라 "서버가 빠진 완제품" 입니다.**
> **빠진 것은 기능이 아니라 서버입니다.**

### 4.2 숫자

| | |
|---|---|
| 기간 | **10일** (2026-08-19 ~ 08-28) |
| 화면 | **11개 전부 실동작** (+ 로그인 · 회원가입). 껍데기 없음 |
| 코드 | `src/` **15,301줄** |
| 검사 | **1,278건 · 11묶음 · 전부 통과** (검사 코드 **5,576줄**) |
| 커밋 | **81개.** 기능 단위로 나뉘고 **커밋 메시지에 "왜" 가 적혀 있음** |
| 개발일지 | **23편** |
| 배포 | **살아 있음** — https://2026-ax-ton.vercel.app · **오프라인에서도 열림** |
| 외부 의존성 | **0개.** `npm install` 도 `node_modules` 도 없음 |

### 4.3 전체 흐름이 끊기지 않고 이어집니다

```
운영자가 문구를 검수 (기능9)
  → 담당자가 교육을 만든다 (기능2)
    → 노동자가 듣는다 (기능3)
      → 이해했는지 확인한다 (기능4)
        → 담당자가 취약 항목을 본다 (기능6)
        → 증빙을 뽑는다 (기능5)
```

**여기에 위험요소 익명 신고(기능8) · 현장 소통(기능7) · 재교육 지시가 붙습니다.**

> **★ "한 화면만 잘 만든 데모" 가 아니라는 것이 이 항목의 핵심입니다.**
> 시연에서 이 흐름을 **끝에서 끝까지** 보여 줍니다 —
> [`06-발표-대본과-데모.md`](06-발표-대본과-데모.md).

## 5. 확장 가능성 — 서버를 붙이면

### 5.1 붙일 자리를 미리 만들어 뒀습니다

```
[화면 11개]  →  [ Store ]  →  지금: 브라우저 저장소
                    ↑
              여기 안쪽만 서버 호출로 바꿉니다.
              화면 11개는 한 줄도 안 고쳐도 됩니다.
```

**★ 그리고 이건 말이 아니라 검사로 지켜집니다.**
**브라우저 저장소를 직접 부르는 코드가 저장소 전체에 단 한 곳(`store.js`)뿐인지
자동 검사가 매번 확인합니다.** 이게 이 프로젝트에서 가장 값진 설계 결정입니다.

> **발표에서 쓸 문장** — *"확장 가능하다고 말로 하지 않고, **확장 가능한 상태가
> 무너지지 않는지 검사가 매번 확인**하게 만들었습니다."*

### 5.2 순서와 크기

| 순서 | 무엇 | 크기 |
|---|---|---|
| 1 | Vercel Functions (같은 배포 구조에 폴더 하나 추가) | 중간 |
| 2 | 관리형 PostgreSQL — 지금의 **10칸이 테이블 10개** | 중간 |
| 3 | **`store.js` 안쪽 교체** | **작음** ← 여기가 핵심 |
| 4 | 진짜 인증 (지금은 목업이라고 **화면에 밝혀 놓음**) | 중간 |
| 5 | 파일 저장소 (신고 사진 · 음성 메모) | 중간 |

### 5.3 그러면 비로소 되는 것

담당자 PC 에서 만든 교육이 **노동자 폰에서 바로** · 여러 사업장 · 데이터가 안 날아감
· 신고에 **사진** · 기한 알림 · **AI 초벌 번역 연동** · 실제 6개 언어 음성 검수
· 문항 난이도 자동 관측

### 5.4 ★ 그때 잃는 것 — 미리 알아 둡니다

**이걸 함께 말하면 "생각해 봤구나" 가 됩니다.**

- **더블클릭으로 여는 확인 방법이 사라집니다** (지금 가장 빠른 검증 수단)
- 개인정보를 서버에 담게 되므로 **보안·법적 책임이 실제로 발생**합니다

> **지금 서버를 안 붙인 것은 게을러서가 아닙니다.**
> 서버 없이도 **제품의 핵심 주장(이해도 검증)을 전부 증명할 수 있고**,
> 붙일 자리는 미리 만들어 뒀습니다.
> *"사진이 필요해지는 시점이 곧 서버가 필요해지는 시점"* 이 이 프로젝트의 기준선입니다.

## 6. 알고 있는 한계 — 전부

**질문받기 전에 먼저 말하는 편이 낫습니다.**

| 한계 | 무엇을 하면 풀리나 |
|---|---|
| 기기 사이 데이터 공유 안 됨 | 서버 |
| **오프라인은 이 기기 안에서만** (끊긴 동안 쌓인 기록이 담당자에게 저절로 안 감) | 서버 |
| AI 초벌 번역이 아직 안 돎 (사람이 손으로 입력) | 서버 |
| 사업장 하나 전제 (증빙 표지) | 다중 사업장 모델 |
| 댓글은 수정·삭제 못 함 (글은 됨) | 작은 작업 |
| 재교육 지시 메모가 한국어 | 지시 문구도 라이브러리에서 고르게 |
| 문항 문구가 검수를 안 거침 | 문항 검수 |
| **번역·역번역을 같은 사람이 입력** | **사람 절차 문제라 화면으로 못 막음** |
| 브라우저 음성이라 발음이 어색할 수 있음 | 서버 + 음성 검수 |
| 노동자에게 교육 기한이 안 보임 | 작은 작업 |
| **"글자 없이 끝까지" 실증 안 됨** | **사람에게 폰 건네 보기** |
