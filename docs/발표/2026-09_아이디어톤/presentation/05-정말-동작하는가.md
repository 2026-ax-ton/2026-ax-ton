### 1.2 데이터가 끊기지 않고 흐릅니다

```
운영자가 문구를 검수 (기능9)
  → 담당자가 교육을 만든다 (기능2)
    → 노동자가 듣는다 (기능3)
      → 이해했는지 확인한다 (기능4)
        → 담당자가 취약 항목을 본다 (기능6)
        → 증빙을 뽑는다 (기능5)
```

**★ 이게 "한 화면만 잘 만든 데모" 와 다른 점입니다.**
운영자가 인도네시아어 번역을 내리면 **그 순간** 인도네시아어 노동자의 수강 화면에서
그 문구가 빠지고, 크메르어 노동자는 계속 봅니다. **시연 1~2번이 그 장면입니다.**

## 2. ★ 어떻게 확인했나 — 4겹

> **이 장이 15점짜리 항목의 본체입니다.**
> *"동작합니다"* 가 아니라 *"이렇게 확인했습니다"* 를 말합니다.

### 겹 1 — 자동 검사 1,278건 (11묶음, 전부 통과)

**브라우저를 열지 않고 11개 화면을 실제로 실행해서** 확인합니다.
가짜 구현이 아니라 **배포되는 그 `worker/quiz.js` 를 jsdom 에서 그대로 돌립니다.**

| 묶음 | 건수 | 무엇을 보나 |
|---|---:|---|
| 노동자 화면 4개 (홈·신고·소통·마이) | 259 | 익명 · 음성 · 재교육 지시 · 공식 답변 |
| 기능2 교육 만들기 | 152 | 검수된 문구만 · 번역 길이 · 문항 수정 · QR |
| 기능9 문구 라이브러리 | 136 | 언어별 판정 · 즉시 중지 · 역번역 |
| 기능6 대시보드 | 122 | 취약 항목 · 기간 필터 · 재교육 지시 |
| 기능4 이해도 검증 | 119 | 문항 3유형 · 한 번만 답하기 · 결과 저장 |
| 회귀 (11화면 · 데이터 계약 · 코드 규칙 · 음성) | 111 | **제품 원칙이 코드에 남아 있는가** |
| 기능5 증빙 | 102 | **숨김 경로 없음** · 기간 묶음 |
| 문서 | 96 | 물어보기만 해도 다음 할 일을 찾을 수 있는가 |
| **QR 인코더** | 75 | **규격 상수 대조** + 되읽기 |
| **오프라인** | 54 | 담을 목록 대조 · `file://` 안 깨짐 · 거짓 배지 안 그림 |
| 기능3 수강 | 52 | 검수된 문구만 · QR 딥링크 |
| **합계** | **1,278** | |

**★ 특이한 점 — 동작만 보지 않고 제품 원칙을 봅니다.**

보통 검사는 "동작하는가" 만 봅니다. 이 검사들은 이런 것도 봅니다.

- 신고 데이터에 신고자를 식별할 값이 **없는지**
- **미이수자를 숨기는 경로**가 생기지 않았는지
- 증빙에 **"면책"** 이라는 표현이 없는지
- **PC 화면에서 취약 항목이 이수율 타일보다 작아지지 않는지** — CSS 를 글로 읽어서
- 문서와 화면의 "할 일" 칸이 **다른 말을 하지 않는지**

> **레이아웃 한 줄과 문서 한 줄로도 제품 원칙이 무너질 수 있어서** 거기까지 붙였습니다.

> 카톡 안에서 열린 브라우저는 음성 기능이 **있다고 대답하고**, 목소리 목록도 주고,

>
> **이 제품이 막겠다고 만든 상황이 정확히 그것이었습니다.**
>
> → 브라우저 이름으로 넘겨짚지 않고 **실제로 소리가 시작됐는지**를 보고 판정하게
> 고쳤습니다. 그래야 카톡이든 나중에 나올 무엇이든 같이 걸립니다.
> **폰을 꺼내지 않아도 되게 검사 14건도 붙였습니다.**

### 겹 3 — ★ 망가뜨려 보기

**검사를 쓰고 나면 항상 일부러 코드를 망가뜨려, 그 검사가 정말 잡는지 봅니다.**

가장 최근 예 (08-28 오프라인 기능):

| 어떻게 망가뜨렸나 | 잡혔나 |
|---|:---:|
| 담을 파일 목록에서 한 줄 빼기 | ✅ |
| QR 주소의 쿼리를 무시하는 옵션 빼기 | ✅ |
| `file://` 을 지키는 검사 빼기 | ✅ |
| 담기지도 않았는데 "오프라인 가능" 배지 그리기 | ✅ |
| **예외를 악용해 CDN 호출 몰래 넣기** | ✅ |

> **안 잡히면 그 검사는 아무것도 지키지 않는 것입니다.**
> 실제로 이 절차로 **"우연히 통과하고 있던 검사"** 를 여러 번 찾았습니다.

### 겹 4 — 배포 주소를 실제로 열어 보기

**push 가 됐다고 배포가 된 것이 아닙니다.**
2026-08-25 에 그걸로 한 번 다쳤습니다 — push 는 성공했는데 배포 주소만 옛날
것으로 남았습니다. (`develop` 을 먼저 올리면 Vercel 이 `main` 배포를 건너뜁니다.)

그 뒤로는 배포할 때마다 **주소를 열어 이번에 넣은 것이 실제로 나가는지** 확인합니다.
그 규칙이 `CLAUDE.md` 에 들어 있습니다.

## 3. ★ 확인 못 한 것 — 먼저 말합니다

**검사 1,278건이 못 보는 것이 있습니다.**

| 검사가 보는 것 | 검사가 **못 보는 것** |
|---|---|
| 데이터가 맞게 흐르는가 | **폰 카메라가 이 QR 을 읽는가** |
| 그 문장이 화면에 있는가 | **글을 못 읽는 사람이 실제로 끝까지 가는가** |
| CSS 규칙이 있는가 | **보기 좋은가 · 눌리는가** |
| 소리를 내라고 시켰는가 | **실제로 소리가 나는가 · 발음이 알아들을 만한가** |
| `sw.js` 에 규칙이 적혀 있는가 | **인터넷을 끊었을 때 진짜로 열리는가** |

### 3.1 가장 크게 비어 있는 것

> **"글자를 한 자도 안 읽고 끝까지 갈 수 있는가"** — 이 제품의 **핵심 주장**인데
> 아직 제대로 실증하지 못했습니다.

**왜 스스로 확인하기 어려운가** —
**만든 사람은 어디를 눌러야 할지 이미 알고 있습니다.**
화면이 눌리는 것과, *글을 못 읽는 사람이 끝까지 가는 것*은 다른 문제입니다.

**진짜 확인 방법은 하나입니다** —
**다른 사람에게 아무 설명 없이 폰을 건네고, 옆에서 아무 말도 하지 않는 것.**

> **★ 발표 전에 한 사람에게라도 해 보면 이 항목의 답이 완전히 달라집니다.**
> 평가지표에 *(주변 의견 수렴, 간단한 테스트 등)* 이 명시돼 있는데,
> **테스트 쪽은 넘치고 의견 수렴 쪽이 비어 있습니다.**
> 순서는 [`../10-checklist.md`](../../../10-checklist.md) A2 에 있습니다.

### 3.2 못 했다면 이렇게 말합니다

> *"폰으로 눌러 봤고 거기서 카톡 음성 문제를 찾았습니다.
> **다만 '글자를 한 자도 안 읽고 끝까지'는 아직 제대로 실증 못 했습니다.**
> 만든 사람은 어디를 눌러야 할지 이미 알기 때문에 스스로는 확인이 안 됩니다.
> 그래서 **다른 사람에게 아무 설명 없이 폰을 건네는 것**을 남은 과제로
> 문서에 적어 뒀습니다."*

**모른다고 말하는 것이 지어내는 것보다 훨씬 낫습니다.**
