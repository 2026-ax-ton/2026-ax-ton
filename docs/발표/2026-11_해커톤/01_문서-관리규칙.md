# 문서 관리 규칙 — 발표 자료를 만드는 동안

> **정한 날** 2026-11-17 · 변소윤
> **적용 범위** 해커톤 발표(11/28) 자료를 만들면서 참고하는 모든 문서
> **한 줄** 팀 문서는 **카톡으로 오는 것이 최신**이고 계속 갱신된다. 바뀐 내용이 발표 자료에 빠짐없이 반영되게 하는 방법을 정한다.

---

## 1. 왜 규칙이 필요한가

| 상황 | 그대로 두면 생기는 일 |
|---|---|
| 문서는 **카톡**으로 오가고, 발표 작업은 **저장소**에서 한다 | 받은 문서가 어디에도 안 남고, 며칠 뒤 「그때 그 파일」을 못 찾는다 |
| 문서가 **아직 작업 중**이라 내용이 계속 갱신된다 | 옛 판의 숫자로 장표를 만들어 두고 바뀐 줄 모른다 |
| 같은 값이 **문서마다 다르다** (지원 언어 4 vs 6 등) | 장표와 시연 영상이 서로 다른 말을 한다 |
| 개발 숫자는 **매일 바뀐다** | 마감 직전에 전부 다시 확인해야 한다 |
| 저장소가 **공개**라 팀 문서를 올릴 수 없다 | git 이 판을 기억해 주지 않으므로 **파일명과 기록표로 대신**해야 한다 |

**핵심은 하나다 — 숫자를 쓸 때마다 「어느 문서의 어느 판에서 왔는지」를 같이 적어 둔다.**
그래야 새 문서가 왔을 때 **무엇이 깨졌는지 바로 찾는다.**

## 2. 문서가 들어오는 길 — 받기부터 반영까지

```
카톡으로 받음
   ↓ ① 원본 그대로 저장      참고자료/미검증_문서/<받은날짜>_<원래이름>
   ↓ ② 받은 기록 한 줄        미검증_문서/README.md 2절 표
   ↓ ③ 옛 판을 지우지 않는다   ← 「무엇이 언제 바뀌었는지」가 여기서 남는다
   ↓ ④ 기존 값과 대조         4절 「정답 우선순위」 · 5절 「값 추적표」
   ↓ ⑤ 발표 자료에 반영       00_발표-고려사항-목록.html 의 해당 항목 갱신
        └ 의견이 필요하면 → docs/팀문서/<문서명>_피드백.md
```

> **★ 팀 문서는 저장소에 올리지 않는다.** 이 저장소는 **공개(public)** 라
> 사업성 계산표·팀원 문서 원본·내부 검토 의견을 올릴 자리가 아니다
> (`.gitignore` 8·9절이 막는다). 그래서 **git 이 판을 대신 기억해 주지 않는다.**

**그 대신 ①②③이 이력을 만든다.** 카톡은 파일이 쌓이기만 하고 무엇이 언제 바뀌었는지
알려주지 않으므로, **받은 날짜를 파일명 앞에 붙이고**(`2026-11-17_사업성계산표.xlsx`)
**옛 판을 남겨 두고** 2절 표에 한 줄을 적는다. 이 셋이 git 로그를 대신한다.

**파일 수정 시각을 믿지 않는다** — 그것은 다운로드한 시각이지 작성된 시각이 아니다.

## 3. 폴더가 뜻하는 것

| 폴더 | 뜻 | 공개 | 손대도 되나 |
|---|---|---|---|
| `참고자료/미검증_문서/` | **방금 받은 것.** 아직 안 읽었거나 대조 전 | ❌ 차단 | 읽기만. **고치지 않는다** |
| `참고자료/03_팀원자료/` | **대조를 마치고 쓰기로 한 것** | ❌ 차단 | 읽기만. 원본은 팀원에게 있다 |
| `참고자료/01_대회규정/` | 대회 공지 원문과 정리 문서 | ✅ 올림 | 읽기만 |
| `참고자료/02·04·05·06_…/` | 이전 발표·검증·사업·개발 근거 (대부분 저장소에 원본이 따로 있다) | ❌ 차단 | 읽기만 |
| `docs/팀문서/` | 팀 문서 원본 + **내 검토 의견** | ❌ 차단 | 피드백 문서만 내가 쓴다 |
| `2026-11_해커톤/` 바로 아래 | **내가 만드는 것** — 고려사항 목록·이 규칙·대본·목차·초안 | ✅ 올림 | 내가 쓴다 |

**옮기는 기준** — `미검증_문서` 에서 `03_팀원자료` 로 옮기는 것은 **대조를 끝냈을 때**다.
옮길 때 **옛 판을 지우지 않는다.** 같은 문서의 판이 둘이면 파일명 뒤에 받은 날짜를 붙인다.

## 4. 문서끼리 값이 다를 때 — 무엇이 정답인가

**아래 순서로 본다. 위에 있는 것이 이긴다.**

| 순위 | 무엇 | 왜 |
|---|---|---|
| 1 | **대회 공지 원문** (`01_대회규정/공지원문_…_개정_최신.html`) | 운영진이 정한 것. 해석의 여지가 없다 |
| 2 | **법령 원문과 그것을 인용한 자료** | 틀리면 바로 지적받는다 |
| 3 | **동작하는 코드와 배포본** | 문서와 코드가 다르면 **코드가 사실**이다 |
| 4 | **실측값** (AI 비용, 검사 결과 등) | 잰 것이 추정보다 강하다 |
| 5 | **카톡으로 받은 최신 팀 문서** | 팀원이 최신이라고 명시했다 |
| 6 | `S02 수치-근거대장` 의 판정 | 숫자를 쓸 수 있는지 없는지의 기준 |
| 7 | 저장소의 다른 문서 | 위와 어긋나면 **저장소 쪽을 고친다** |

> **예외 — 숫자를 「써도 되는가」는 언제나 `S02` 가 정한다.**
> 팀 문서에 있는 숫자여도 `S02` 가 ⛔ 로 판정했으면 발표에 쓰지 않는다.
> 새 근거가 생기면 `S02` 의 판정을 먼저 바꾸고 나서 쓴다.

## 6. 작성 유의 사항 — 발표 내용을 쓸 때

### 6.1 숫자

- **측정 조건을 떼지 않는다.** 「AI 비용 월 ₩41」이 아니라 **「월 ₩41 — 2026-11-16, 공개 시연 전이라 사용량이 적은 상태」**
- **`S02` 가 ⛔ 로 판정한 숫자는 쓰지 않는다.** 이전 장표에 있어도 마찬가지다
  (9,571건 · 2.4배 · 3.4% · 62.2% · TAM 1.2조)
- **추정·예상 숫자를 만들지 않는다.** 이전 장표의 「2026년도 예상 약 10,000」 같은 것
- **가정이 곱해진 숫자는 대표로 쓰지 않는다.** 가정이 하나뿐인 값을 앞에 둔다
- **변동값은 자리만 비워 둔다.** 확정본을 받아 마지막에 채운다

### 6.2 출처 표기

- **장표마다 데이터 블록 아래에 작은 글씨로** 적는다 (이전 장표와 같은 방식)
- 형태는 **「기관 · 자료명 · 연도」**. 매체명만 적지 않는다
- 자체 측정값은 **「자체 실측, 날짜, 조건」**

### 6.3 인용

- **원문 그대로** 쓴다. 다듬으면 인용이 아니다
- 인터뷰 인용은 **누가 한 말인지**를 밝힌다 (개인 식별 정보는 넣지 않는다)

### 6.4 표현

- `개인작업폴더/00_표현-규칙.md` 를 따른다 — **비유·결과 암시·감정 표현을 제목에 쓰지 않는다**
- 항목 이름은 **그것이 무엇인지**로 적는다

### 6.5 말하면 안 되는 것

| 쓰지 않는 표현 | 왜 | 대신 |
|---|---|---|
| 「법정 교육을 대체한다」 | 2027년 외국인 기초안전보건교육은 **공단·등록기관**이 하는 교육이다 | 「사업장 **자체교육**의 실시 도구」 |
| 「면책」 | 증빙은 교육 실시의 기록일 뿐 법적 책임을 대신하지 않는다 | 「교육 실시와 이해 확인의 기록」 |
| 「AI 가 번역한다」 (단정) | 승인은 사람이 한다 | 「AI 가 번역하고 역번역으로 대조한 뒤, **사람이 승인한 문구만** 나간다」 |
| 「그런 서비스는 없다」 | 확인 범위 밖을 단정하는 것 | 「확인한 범위에서는 찾지 못했다」 |

## 7. 불일치를 찾았을 때 — 처리 순서

1. **4절 우선순위**로 어느 쪽이 정답인지 정한다
2. 정답이 안 정해지면 **`미검증_문서/README.md` 5절 불일치 목록에 올린다**
3. **팀원에게 물어야 하는 것이면 질문을 만든다** — 아래 8절 형식
4. 발표에 영향이 있으면 **`00_발표-고려사항-목록.html`** 의 해당 항목 상태를 `확인필요` 로 바꾼다
5. **해결되면 저장소 문서를 고친다** — 틀린 채로 두면 다음에 또 같은 것을 찾게 된다

## 8. 팀원에게 물을 때의 형식

카톡은 긴 글을 읽기 어려운 자리다. 아래처럼 **짧고 답하기 쉬운 형태**로 묻는다.

```
[확인 부탁] 지원 언어 수
- 지금 문서마다 다릅니다: 제품 설명 6개 / 11-17 기록 4개
- 발표 장표와 시연 영상에 들어갑니다
- 11/19까지 알려주시면 반영하겠습니다
```

- **범위가 모호하면 번호로 바꿔 되돌린다** — 「(가) … / (나) … 중 어느 쪽일까요」
- **기한을 같이 적는다** — 「11/20까지 주시면 반영합니다」
- **파일은 톡방에 직접 올려 달라고 한다** — 링크로 받으면 어느 판인지 구분이 어렵다

## 9. 작업을 시작할 때 — 매번 확인하는 3줄

1. `미검증_문서/` 에 새 파일이 있나 → 있으면 2절 순서대로 처리
2. **5절 값 추적표**의 「변동」 값 중 오늘 바뀐 것이 있나
3. `00_발표-고려사항-목록.html` 에서 오늘 처리할 항목을 고른다

**커밋하기 전에 한 번 더** — `git status` 에 팀 문서·인터뷰·계산표가 섞여 있지 않은지 본다.
`.gitignore` 가 막고 있지만, 새 자리에 파일을 만들면 규칙 밖일 수 있다.
