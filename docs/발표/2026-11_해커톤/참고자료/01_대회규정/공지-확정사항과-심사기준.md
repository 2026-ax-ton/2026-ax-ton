## 3. 심사 기준 — 항목마다 세부 질문이 2개씩, 모두 12개

공지의 평가표는 6개 항목이지만, **각 항목이 세부 평가 내용 2줄로 나뉘어 있다.**
목차는 6개가 아니라 **이 12개 질문에 답하도록** 짜야 한다.

| 배점 | 항목 | 세부 질문 ① | 세부 질문 ② |
|---:|---|---|---|
| **25** | 서비스 완성도 | AI를 활용한 서비스가 **실제로 작동하는 수준**으로 구현되었는가 | 핵심 기능이 완성도 있게 구현되고, **UX/UI**를 잘 갖추었는가 |
| **20** | 비즈니스 모델 | 도입 시 **기대 효과가 구체적**이고, 다른 지역·대상으로 **확장**할 수 있는가 | 서비스를 **지속적으로 운영할 수 있는 구조**를 갖추었는가 |
| **15** | 문제 이해도 | 지역·사회 문제와 대상의 **페인포인트를 정확히 파악**하였는가 | **문제에서 해결책까지 논리적으로 연결**되는가 |
| **15** | 검증 | 사용자 인터뷰·MVP 테스트 등 **실제 검증 활동을 진행**하였는가 | **검증 결과를 바탕으로 서비스나 사업 방향을 개선**하였는가 |
| **15** | 발표 및 전달력 | 발표 **흐름과 논리 구성**이 명확한가 | **시연**(현장 또는 영상)을 통해 서비스를 완성도 있게 보여주었는가 |
| **10** | 팀워크 및 성장 가능성 | **AI 도구를 활용해 아이디어를 결과물로 만들어 간 성장 과정**이 드러나는가 | **팀원 간 역할 분담 및 역량**이 잘 드러나는가 |

**목차를 짤 때 쓰는 방법** — 장을 다 뽑은 뒤, 위 12개 질문 옆에 그 질문에 답하는 장 번호를 적는다.
**번호가 안 붙는 질문이 있으면 그 점수는 못 받는다.**

**놓치기 쉬운 질문 네 개**

| 질문 | 왜 놓치기 쉬운가 |
|---|---|
| 서비스 완성도 ② **UX/UI** | 기능 설명만 하고 화면 설계 의도를 말하지 않게 된다. 우리는 말할 것이 많다 — 글을 못 읽어도 끝까지 가는 구조, 터치 영역 60px, 색만으로 상태를 구분하지 않음 |
| 비즈니스 모델 ① **다른 지역·대상 확장** | 수익 구조만 말하고 확장을 빼먹기 쉽다 |
| 검증 ② **결과로 개선** | 「인터뷰 몇 건」만 말하면 절반만 답한 것이 된다. **무엇을 바꿨는지**가 있어야 한다 |
| 팀워크 ① **AI 도구로 만들어 간 과정** | 결과물만 보여 주고 과정을 안 보여 주면 비는 항목이다 |

## 4. 시연 — 공지가 준 선택지와 우리 결정

| 공지 내용 | 우리 |
|---|---|
| 현장 시연·영상 시연 중 **하나 또는 둘 다** 가능 | **영상 시연만** (C06 D-036) |
| **"현장 시연과 영상 시연 사이에 점수 차등은 없습니다"** | 영상만 해도 불리하지 않다 |
| "시연 없이 발표만 진행하는 것도 가능합니다. 다만 **심사 기준에 시연 완성도가 포함**되어 있습니다" | 시연을 빼면 발표·전달력 15점의 세부 질문 ②가 통째로 빈다 |

**★ 영상 시연 장표 표기 — 방법이 두 가지다**

> "영상 시연을 진행하는 팀은 발표 장표 중 **영상을 재생할 페이지에 `[영상 시연]`이라고 표기**하거나,
> **장표 내에 영상을 포함**해야 합니다."

| 방법 | 장점 | 주의 |
|---|---|---|
| (가) 장표에 `[영상 시연]` 표기 + 영상 파일을 따로 재생 | PPTX 용량이 작다 | 무대에서 **창 전환이 필요**하다. 전환 시간도 7분에 들어간다 |
| (나) **장표 안에 영상을 삽입** | 창 전환이 없다. 슬라이드 넘기면 바로 재생 | PPTX 가 커진다(25MB 넘으면 드라이브 링크). 운영 PC 코덱 문제 가능 |

**(나)가 무대에서 더 안전하다.** 다만 리허설(11/28 09:00~11:30)에서 반드시 확인해야 한다.
어느 쪽을 택하든 **영상 파일은 따로 제출한다**(제출 목록의 필수 항목).

## 5. 2026-11-03 개정으로 추가된 것 — 현장 시연 HTML 규정

우리는 현장 시연을 하지 않기로 했으므로 **지금은 해당 없다.** 다만 결정이 바뀔 경우를 위해 적어 둔다.

- 판단 기준: **"마감 이후 팀이 시연 내용이나 기능을 변경할 수 있는지"**
- **iframe 방식: 불가** — 화면·기능이 외부 서버에 있어 마감 후 수정 가능
- **프론트엔드 HTML + 팀이 직접 운영하는 백엔드: 불가** — 서버 측 기능 수정 가능
- **단독 실행 HTML: 허용**
- **AI 모델 API(예: Claude API)·공공데이터 API 등 팀이 수정할 수 없는 외부 서비스를 HTML 에서 직접 호출: 허용**
- 애매하면 **마감 전 채널톡 문의 필수.** 운영진이 최종 판단
- 제출 후 시연 내용이 변경된 것이 확인되면 **실격**, 수상 후에도 취소 가능

- **발표 순서 = 자료 제출 역순.** 가장 늦게 낸 팀이 가장 먼저 발표한다
- 기준 시각: **"필요한 파일을 모두 갖춘 첫 메일의 수신 시각"** — 빠뜨린 파일이 있으면 그 메일은 기준이 안 된다
- 순서 공지: 11월 24일(화) 오후, 오픈채팅방

**계산** — 20팀 × 10분 = 200분이고 발표 시간이 12:40~16:00(200분)이다. 쉴 틈 없이 채워진다.
일찍 내면 뒤쪽(16시 가까이), 늦게 내면 앞쪽(12:40 가까이) 발표다.

## 9. 요약 — 목차를 짤 때 적용되는 규칙 다섯

1. **말하는 시간은 5분**이다 (영상 2분 기준). 장 수를 여기서 역산한다
2. **3절의 12개 질문**에 전부 답이 붙어야 한다. 안 붙는 질문이 비는 점수다
3. **중요한 내용을 뒤에 두지 않는다.** 7분이 지나면 즉시 끊긴다
4. **영상 재생 장표에 `[영상 시연]` 표기** 또는 장표 내 영상 삽입 — 둘 중 하나는 반드시
