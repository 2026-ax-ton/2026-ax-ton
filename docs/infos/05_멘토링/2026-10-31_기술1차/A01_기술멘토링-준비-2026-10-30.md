## 3. 결정이 필요한 것 — 선택지 비교 (표 1)

| 결정 | 선택지 | 장점 | 걸림 |

**비용 어림 (표 3, S02 N-63) — 🔷 가정 위의 계산**

> 가정: 호출 1회 = 입력 500토큰 + 출력 150토큰. 문구 1개 × 5개 언어 × (번역 + 역번역) = 10회, 재시도까지 최대 20회.
> 크메르어·네팔어 등은 같은 문장도 토큰이 더 많이 나올 수 있다. 실제 측정으로 바꿔야 한다.

| 모델 | 호출 1회 | 문구 1개 (10~20회) | 문구 100개 |
|---|---|---|---|
| Sonnet 5.5 | 약 0.0025달러 | 약 0.025~0.05달러 | **약 2.5~5달러** |
| Haiku 5.5 | 약 0.000125달러 | 약 0.00125~0.0025달러 | **약 0.13~0.25달러** |

→ 해커톤 시연 규모에서는 **AI 비용보다 Vercel 요금제(F-7)와 검수 인건비**가 원가의 중심이다 ([S04 §5.5](../2026-10-10_사업1차/S04_멘토링1차-과제-정리.md) 원가 표의 AI 사용료 칸 근거).

## 5. 질문 (우선순위 순) — ★ = 시간이 짧아도 묻는다

### ★ 1. 서버리스 함수와 데이터 저장 범위 (Q10 + Q12)
- **배경**: AI 키를 숨기려면 `/api/*`가 필요하다. 지자체에 팔려면 로그인·DB·기기 간 공유도 필요하다(S01 §9).
- **묻는 것**: 해커톤에서 서버리스 AI 호출만 붙이고 DB는 로드맵으로 둬도 되나요? 심사에서 "실제 서비스 구조"는 얼마나 보나요?
- **우리 생각**: AI 호출만 서버리스로, 저장은 localStorage 유지, DB는 로드맵.
- **답에 따라 바뀌는 것**: D-005, 2차 스프린트 범위(D05), Root Directory 변경 승인 요청 시점.

### ★ 2. 에이전트 루프 위치와 "도구" 정의 (Q7 + D-006)
- **배경**: 순서는 코드가 제어하고 모델은 단계마다 한 가지 일만 하게 하려 한다. 서버 시간 제한(300초)은 장벽이 아니다(F-6).
- **묻는 것**: 모델의 도구 호출(tool use)로 에이전트가 스스로 순서를 정하게 하는 것과, 코드가 순서를 정하는 것 중 무엇이 "에이전트"로 더 인정받나요? (Q4 연결)
- **우리 생각**: 코드가 순서 제어 + 모델이 "다시 할지/사람에게 넘길지"를 판단하는 단계 하나를 둔다.
- **답에 따라 바뀌는 것**: D-006, D06 §3.4 API 명세.

### ★ 3. AI가 AI를 검증하는 구조의 신뢰도 (Q5)
- **배경**: 같은 계열 모델이 번역·역번역하면 같은 오류를 놓칠 수 있다. 지금 비교 로직은 한국어 부정 표현 개수만 본다(F-2).
- **묻는 것**: 번역과 역번역을 다른 모델로 나누는 것이 의미가 있나요? 크메르어처럼 모델 품질이 낮은 언어는 어떻게 다루나요? 비교도 모델에게 맡길까요, 규칙으로 둘까요?
- **우리 생각**: 번역·역번역 모델 분리 + 규칙 비교(`negationFlipped`) 유지 + 최종은 사람 승인.

### 4. 평가표 공지 전에 공통 기반을 먼저 만들어도 되나 (Q3 + D-003) — **해결됨, 묻지 않는다**
- **2026-10-23 해결**: 운영 공지로 평가표가 나와 D-003을 해제했다. 「서비스 완성도」 25점이 AI가 실제로 작동하는지 본다 ([C08 §4](../../../documentations/00_개발컨벤션/C08_해커톤-규정과-대응.md)). 아래는 기록으로 남긴다.
- **배경**: "주제·평가표 공지 전에는 에이전트 코드를 쓰지 않는다"(D-003)고 정했다. 주제는 확정됐고 평가표만 남았다. 멘토링은 11/20까지, 자료 제출은 11/23, 오프라인 해커톤은 11/28이다.
- **묻는 것**: 어떤 에이전트를 고르든 필요한 기반(서버 함수 골격, AI 호출 래퍼, 실패 시 수동 복귀, 경계 테스트)을 지금 시작해도 될까요?
- **우리 생각**: 공통 기반(US-25~US-27, US-37)은 지금 시작한다. 에이전트 선택(A/B/C)만 평가표를 기다린다.
- **답에 따라 바뀌는 것**: D-003 수정 여부, 2차 스프린트 시작 시점.

### 5. 에이전트 개수와 후보 선택 (Q1 + Q2)
- **묻는 것**: 하나를 깊게(A: 번역·검수) 만드는 것과 A + C 일부를 얹는 것 중 어느 쪽이 심사에서 낫나요?
- **우리 생각**: A 하나를 끝까지. C는 로드맵.

### 6. 에이전트 평가 지표 (Q9 + Q22)
- **묻는 것**: 번역 품질을 무엇으로 보여 줄까요? 후보: 운영자가 고친 비율, 승인까지 걸린 시간 전/후, 재시도로 해결된 비율, "사람에게 올림" 비율.

### 7. 비용·실패 대비 (Q13 + Q14)

### ★ 12. 현장 시연에서 AI를 어떻게 부르나 (신규, 2026-10-23 공지)
- **배경**: 현장 시연은 운영 PC에서 **제출한 HTML 파일을 크롬 더블클릭**으로만 한다. 다른 URL을 열면 실격이다 ([C08 §5·§7](../../../documentations/00_개발컨벤션/C08_해커톤-규정과-대응.md)). `file://`로 연 화면이 배포된 `/api`를 부르면 `Origin: null`이 된다.
- **묻는 것**: 시연 기간에만 `null` 출처를 허용(CORS + `OPTIONS`)하는 방식이 괜찮을까요? 더 안전한 방법이 있을까요?
- **우리 생각**: `ALLOW_FILE_ORIGIN`으로 시연 기간만 켜고, 통과 문구·일일 상한·공급사 예산을 그대로 둔다. AI 부분은 영상으로 백업 ([A02 §5.2](../../../documentations/20_기술명세/A02_기술-개발-명세서.md), C06 D-019).

### 13. 제출 HTML이 폴더일 때 (신규)
- **배경**: 우리 앱은 HTML 13개 + JS·CSS 폴더다. 운영진에게 zip 제출 가능 여부를 묻는다 (C08 §8).
- **묻는 것**: 한 파일로 묶어야 한다면, 화면 이동이 있는 여러 페이지 앱을 한 HTML로 묶는 가장 덜 위험한 방법은 무엇일까요?

### 14. 남은 멘토링 일정 (신규, 운영)
