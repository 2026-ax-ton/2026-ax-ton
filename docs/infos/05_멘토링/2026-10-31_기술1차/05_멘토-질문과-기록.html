1. 질문 8개 — 묻는 순서 (표 1)

형식: "우리는 이렇게 정했다 → 이 판단에서 놓친 위험이나 더 나은 전략이 있나". ★ = 시간이 없어도 묻는다.

#주제우리가 정한 것멘토에게 묻는 것
Q1 ★준비도범위 필수 5개(🆕 DB 포함), 결정 11개, 마일스톤 M0~M3 (02·04)지금 준비 수준을 어떻게 보나? 해커톤까지 가장 먼저 메워야 할 빈칸은 무엇인가?
Q2 ★AI 시연 전략에이전트 1개를 깊게, 현장(file:// + 배포 API) + 영상 시연「AI가 실제로 작동」을 심사위원에게 가장 설득력 있게 보여 주는 방법은? 현장 시연에서 AI를 부르는 것과 영상만 쓰는 것 중 무엇이 위험 대비 효과가 큰가?
Q3 ★일정 현실성1인 개발, M1 11/8 · 동결 11/16, 버리는 순서 표 4이 일정이 현실적인가? 버리는 순서가 심사 관점에서 맞나? (예: 화면 보완보다 다른 것을 먼저 해야 하나)
Q4에이전트 깊이규칙 대조 + 재시도 + 사람에게 올림. 판정은 AI에게 맡기지 않는다심사에서 "이게 에이전트냐, 번역 API 호출이냐"는 질문이 나오면 지금 설계로 충분한가? 더 보여 줘야 할 에이전트 요소가 있나?
Q5검증 15점최소선: 인터뷰 3명 + MVP 테스트 3회 + 개선 1건팀원 참여가 낮을 때 「실제 검증」으로 인정받는 최소 수준은? 개발자가 직접 해도 되나?
Q6발표 비중7분 중 문제 1.5 · 해결·시연 3 · 사업 1.5 · 검증·팀 1 (제안)기술 이야기를 얼마나 넣어야 하나? 1인 개발을 약점이 아니라 강점으로 말하는 방법은?
Q7 ★수료계획상 멘토링 5회 (사업 10/10·10/24·11/14, 기술 오늘·다음 1회)기술 회차가 이전에 집계된 것이 있나? (기술 멘토가 10/22에 6단계 할 일을 보냈다) 6회가 안 되면 어떻게 잡나?
Q9 ★🆕 DB 범위AI(11/8) 뒤 11/9~11/13에 Neon Postgres·진짜 로그인·기기 간 동기화를 붙이고, 화면 보완 H2·H3·H7·H9를 미룬다 (C06 D-023)해커톤에 DB까지 넣는 것이 심사 관점에서 득인가? 두 기기 시연을 영상으로만 보여 줘도 되나? 1인 개발로 무리라면 무엇부터 줄일까?
Q8 ★다음 회차M1(11/8) 뒤 11/10~11/12에 동작하는 에이전트를 보여 주고 시연·발표 전략 점검날짜와 형식(시연 리허설로 해도 되나)
  • 개인 질문 (시간이 남으면): AI Agent 개발자 포트폴리오로 이 프로젝트를 쓸 때 무엇을 강조하나? 후보: 에이전트 경계 설계(waiting 고정·사람 승인), 가짜 응답 경계 테스트, 실패 시 손 입력 복귀, 의존성 0 구조.
