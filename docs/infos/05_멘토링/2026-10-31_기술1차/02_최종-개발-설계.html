02 · 최종 개발 설계 — 해커톤에서 무엇을 어떻게 만드나

원본 A02 기술 개발 명세서 (API·프롬프트·환경변수 전문) · PRD-AD-03 (요구 FR-AD-03-01~15) · SPEC-FE · SPEC-BE
이 문서가 답하는 질문 최종적으로 무엇을 만드나 · 왜 그것이 AI Agent인가 · 구조·흐름·API·데이터를 어떻게 바꾸나 · 무엇으로 검증하나 · 시연은 어떻게 하나 · 무엇을 이미 정했나

1. 한 문장

운영자가 안전 문구를 넣으면, AI 에이전트가 5개 언어로 번역하고 → 스스로 다시 한국어로 되돌려 → 뜻이 뒤집혔는지 검사하고 → 뒤집혔으면 고쳐 다시 번역하고 → 그래도 안 되면 사람에게 넘긴다. 사람이 승인한 번역만 노동자에게 나간다.

  • 지금(v1.0)은 이 일을 운영자가 손으로 한다: 번역문과 역번역을 직접 입력하고, review.js가 부정 뒤집힘을 표시한다.
  • 해커톤에서는 번역·역번역·대조·재시도를 에이전트가 하고, 사람은 판정만 한다. 판정 규칙(review.js)과 승인 화면은 그대로 재사용한다.
  • 🆕 그리고 실제 서버·DB 위에서 돈다. 노동자 폰에서 푼 결과가 담당자 PC에 나타나고, 진짜 로그인과 사업장 분리가 된다 (2026-10-31 결정, C06 D-023).

3. 왜 이것이 "AI Agent"인가 (표 2)

심사 「서비스 완성도 25점」은 AI가 실제로 작동하는가를 본다. 우리 에이전트는 한 번 묻고 끝나는 번역 호출이 아니다.

에이전트 요소우리 구현
목표"사람이 검수할 수 있는, 뜻이 뒤집히지 않은 번역 초안"을 언어마다 만든다
도구① translate (Gemini) ② backtranslate (다른 모델, 원문을 보지 않음) ③ compare (Review.negationFlipped·newWordCount, 규칙)
스스로 검사자기 번역을 되돌려 원문과 대조한다
피드백 반영뒤집혔으면 "앞 번역을 되돌렸더니 '<역번역>'이 되었다. 부정과 금지를 다시 확인하라"를 붙여 다시 번역한다
멈춤 조건재시도 최대 2회 (언어당 최대 3번 시도). 문구 1개당 호출 상한 = 언어 수 × 2 × 3
사람에게 넘김상한까지 못 풀면 "사람에게 올림". 그 언어는 AI 번역문 그대로 승인할 수 없고, 사람이 직접 입력해야 승인된다
넘지 않는 선결과는 항상 waiting. 승인은 사람만. 실패하면 손 입력 경로
  • 판정을 AI에게 맡기지 않는 이유: AI가 AI를 채점하면 같은 실수를 같이 놓친다. 규칙 대조는 결과가 매번 같고, 테스트로 고정할 수 있고, 왜 걸렸는지 화면에 보여 줄 수 있다. 규칙이 못 잡는 미묘한 오역은 사람 승인 단계가 잡는다.

7. 이미 정한 것 — 결정 11개 (표 5) ★

#결정이유이렇게 되면 바꾼다
1에이전트는 1개(A 번역·검수)를 깊게 만든다. B·C는 설계 장표만개발자 1명. 「AI가 실제로 작동」은 개수보다 끝까지 도는 것이 중요하다. A는 우리 핵심 원칙(검수된 번역만)과 바로 이어진다11/8에 A가 끝나고 시간이 남을 때만 B 최소판
2루프는 브라우저(agent.js)가 지휘하고 함수는 한 단계씩만 한다기존 review.js를 그대로 재사용한다. 단계별 진행을 화면에 보여 줄 수 있다(시연). 함수가 짧아 시간 초과 위험이 작다운영자 창이 닫혀 멈추는 문제가 실제로 생기면 서버 루프(B안)
3/api는 저장소 루트 api/에 둔다 — Root Directory = 저장소 루트, 출력 폴더 = src (🆕 10/31 수정: DB 드라이버가 필요해져 src/와 분리)src/(브라우저)는 의존성 0을 그대로 지킨다. 서버 의존성은 루트 package.json에만11/3 미리보기에서 docs/·tests/가 노출되면 출력 설정을 다시 확인
4Gemini generateContent, 키는 x-goog-api-key 헤더, 모델 코드는 환경변수한 번 묻고 한 번 답하는 호출이라 상태가 필요 없다. 모델을 코드 수정 없이 바꿀 수 있다공급사 공지로 중단 일정이 나오면 Interactions API
5역번역은 번역과 다른 모델로, 원문을 보여 주지 않고 한다같은 모델은 같은 실수를 같이 놓친다. 원문을 주면 "맞춰서 고친다". 시연 규모에서 비용 차이는 문구 100개당 수 달러 이하 (S02 N-65, 계산값)할당량·품질 문제면 같은 모델 + 다른 프롬프트 (환경변수만 변경)
6재시도 2회 → 사람에게 올림. 올림 언어는 직접 입력 뒤에만 승인무한 재시도는 비용·시간을 태운다. AI가 못 푼 것은 사람의 일이다— (PRD 결정)
7AI 결과는 항상 waiting으로 저장, 데이터에 agent·judged 추가제품 원칙 8. 누가 승인했는지가 안전 지시의 책임 기록이다— (원칙)
8남용 방지 4층: 출처 검사 · 운영자 통과 문구(X-Agent-Pass, sessionStorage) · 일일 상한(메모리 근사) · Google 예산 알림로그인이 목업이라 서버가 운영자를 알아볼 수 없다. 해커톤 기간에 충분한 수준이다판매 단계에서 서버 세션 인증으로 대체
9시연은 현장 + 영상 둘 다. 현장은 제출 HTML(file://)이 API_BASE로 배포된 /api를 부르고, 제출~11/28에만 null 출처를 허용한다현장 인터넷·운영 PC를 통제할 수 없다. 영상이 보험이다운영진이 외부 호출을 금지하면 현장은 AI 없는 흐름, AI는 영상으로만. zip 제출이 안 되면 한 HTML로 묶는 스크립트
10품질 체계: IMP-1 해결 → GitHub Actions CI → 경계 테스트 → 기능 동결(11/16) 뒤 버그 수정만1인 개발에서 사람 대신 테스트가 리뷰어다. 심사 「팀워크·성장」에서 "어떻게 만들었나"의 증거가 된다—
11🆕 DB를 붙인다 — Neon Postgres(싱가포르), 진짜 로그인(scrypt·토큰·잠금), Store 서버 모드/로컬 모드, 사업장 분리, 익명 신고 별도 테이블 (C06 D-023)「노동자 폰 → 담당자 PC」가 실제 서비스의 증거다. 화면은 Store 한 창구라 거의 안 바꾼다11/13 두 기기 시험이 안 되면 서버 모드를 끄고 로컬 모드로 제출

4담당자 교육 만들기 → 노동자 홈승인된 문구가 크메르어 음성으로 나간다. 승인 전에는 나가지 않는다
5노동자 그림 문제 → 담당자 대시보드이해 확인과 기록
🆕 6노동자 폰에서 풀기 → 담당자 PC 대시보드서버·DB를 거쳐 다른 기기에 나타난다 (영상 시연 필수 — 현장 운영 PC는 file:// 로컬 모드)
  • 재시도·올림은 실제 호출에서 나올 때만 보여 준다. 안 나오면 경계 테스트 결과(가짜 응답) 로 설명한다. 시연에서 결과를 조작하지 않는다.
  • 운영 PC는 빈 브라우저다 → 시작 화면에서 예시 데이터 채우기를 먼저 누른다.

9. 하지 않는 것

  • 🆕 노동자 화면은 제3자 서버를 부르지 않는다 (같은 출처 우리 /api만).
  • 노동자 화면에서 AI를 부르지 않는다. 노동자 데이터·신고 데이터를 AI에 보내지 않는다.
  • AI가 승인하지 않는다. AI 판정 점수로 사람 검수를 건너뛰지 않는다.
  • 외부 라이브러리·프레임워크·빌드를 넣지 않는다 (src/ 의존성 0).
