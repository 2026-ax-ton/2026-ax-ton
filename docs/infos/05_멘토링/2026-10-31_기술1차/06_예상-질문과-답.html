06 · 예상 질문과 답 — 멘토·심사위원

기준일 2026-10-31 · 작성 byeonsoyun
이 문서가 답하는 질문 기술 멘토링과 해커톤 심사에서 나올 질문에 무엇을 근거로 어떻게 답하나
규칙 답에 쓰는 숫자는 S02 수치 근거 대장에 있는 것만 쓴다 (N-nn). 모르는 것은 모른다고 하고 언제 확인할지 말한다.

1. 제품·AI

Q1. 그냥 구글 번역이나 AI 번역을 쓰면 되지 않나요?

  • 번역은 누구나 한다. 우리가 하는 것은 번역이 안전 지시로 나가도 되는지 검사하고, 사람이 승인한 것만 내보내는 것이다.
  • 안전 문구는 "손을 넣지 마세요"가 "손을 넣어도 됩니다"로 뒤집히면 사고가 난다. 에이전트는 자기 번역을 다시 한국어로 되돌려 부정이 사라졌는지 검사하고, 고쳐 다시 번역하고, 못 풀면 사람에게 넘긴다.

Q2. 이게 에이전트인가요, API 한 번 부르는 건가요?

  • 목표·도구 3개(번역·역번역·대조)·자기 검사·피드백 반영 재시도·멈춤 조건·사람에게 넘김이 있다 (02 §3).
  • 단계마다 다음 행동을 결과를 보고 정한다. 화면에 "번역 중 → 역번역 중 → 대조 → 재시도 1/2 → 올림"이 실시간으로 보인다.

Q3. 판정도 AI에게 시키면 더 똑똑하지 않나요?

  • AI가 AI를 채점하면 같은 실수를 같이 놓친다. 규칙 대조는 매번 같은 결과를 내고 테스트로 고정할 수 있고, 왜 걸렸는지 화면에 보여 줄 수 있다.
  • 규칙이 못 잡는 미묘한 오역은 사람 승인이 잡는다. AI는 사람이 볼 곳을 좁혀 줄 뿐, 승인하지 않는다.

Q4. 역번역 대조가 정확한가요? 한계는?

  • 지금 규칙은 ① 부정 표현이 한쪽에만 있는지 ② 원문에 없던 낱말 수 두 가지다. 뜻이 미묘하게 바뀐 것까지 잡지는 못한다.
  • 그래서 "통과"가 아니라 "사람이 볼 곳 표시"로 쓴다. 모든 번역은 waiting으로 저장되고 사람이 승인해야 나간다.

Q5. 크메르어·네팔어 같은 소수 언어 번역 품질은요?

  • 아직 모른다. 11/3 첫 실물 호출에서 5개 언어를 실측해 기록한다.
  • 품질이 낮으면 "사람에게 올림"이 많아진다. 그것도 설계대로의 동작이다 — AI가 못 하면 사람에게 넘긴다.

Q6. AI가 틀린 번역을 내보내면 책임은?

  • AI는 내보낼 수 없다. 결과는 항상 waiting이고, 노동자 화면은 reviewed만 쓴다 (Store.phraseOk). 누가 언제 승인했는지 judged로 남긴다.
  • 노동자가 이상하다고 느끼면 홈에서 오역 신고 → 그 언어만 즉시 중지된다 (H1).

2. 기술 선택

Q7. 서버·DB는 어떻게 되어 있나요? 실제로 서비스할 수 있나요?

  • 🆕 해커톤에서 Vercel 서버리스 함수 + Neon Postgres를 붙입니다 (2026-10-31 결정). 진짜 로그인(비밀번호 해시·토큰·잠금), 사업장별 분리, 노동자 폰 → 담당자 PC 동기화, 계정 없는 익명 신고까지 합니다.
  • 모든 화면이 Store 한 모듈로만 저장하도록 처음부터 만들어 두어서, 화면은 거의 그대로 두고 Store 안쪽만 서버 모드로 바꿉니다. 현장 시연(file://)은 기기 안에서만 도는 로컬 모드로 그대로 됩니다.
  • "공장 한 곳의 시범 운영이 가능한 수준"입니다. 정식 서비스 전에는 원어민 검수 인력, 개인정보 절차, 유료 요금제가 남아 있고 체크리스트로 정리했습니다 (A04).

Q7-B. 🆕 노동자 개인정보는 어디에 저장되나요?

  • DB는 Neon의 싱가포르 리전에 있습니다 (Neon에 서울 리전이 없습니다). 그래서 국외 이전 고지가 필요하다는 것을 알고 있고, 처리방침·동의 초안을 써 두었습니다 (A05). 법률 검토 전이라 해커톤은 예시 데이터로만 시연합니다.
  • 외국인등록번호·여권번호는 받지 않고, 신고는 계정 정보 없이 저장되며, AI에는 안전 문구만 보냅니다.

Q8. 프레임워크·라이브러리를 안 쓰는 이유는?

  • 노동자 화면은 외부 요청 0건이어야 하고, 인터넷이 약한 공장과 저사양 폰에서 빨라야 하고, 현장 시연이 제출 HTML을 더블클릭(file://)해서 여는 방식이다. 빌드·모듈 없이 열리는 구조가 이 조건을 모두 만족한다.

Q9. 왜 Gemini인가요? 비용은?

  • 2026-10-23에 공급사를 Gemini로 정했다 (C06 D-018). 키는 서버 환경변수에만 있다. 공급사를 바꿔도 함수 안쪽만 바꾸면 된다 — 화면과 API 계약은 같다.
  • 문구 100개를 5개 언어로 돌리면 약 1.1~3.3달러다 (재시도 없음~최대, 계산값 S02 N-65). 일일 호출 상한과 예산 알림을 둔다.

Q10. 1명이 개발하는데 품질은 어떻게 보장하나요?

  • 🆕 서버는 사업장 분리·역할 검사·익명 신고를 테스트로 고정합니다 (A 사업장 토큰으로 B 사업장 데이터 요청 → 차단 등 14건, D07 STC-E25).
  • 자동 테스트 1,619건이 화면을 실제로 돌리고, 제품 원칙(익명 신고·검수된 문구만·외부 요청 0건)이 코드에 남아 있는지까지 검사한다.
  • 에이전트는 가짜 응답 경계 테스트로 "AI가 reviewed를 보내도 waiting으로 저장" 같은 선을 고정한다. PR마다 CI가 돈다 (11/1부터).

3. 일정·팀

Q11. 코드가 아직 0줄인데 시간이 되나요?

  • 무엇을 만들지는 다 정했다 (PRD 15개 요구, API 계약, 데이터 변경, 테스트 목록). 남은 것은 구현이다.
  • M1(11/8)에 AI가 돌지 않으면 화면 보완을 전부 버리고 에이전트만 한다 (04 §4).

Q12. 팀원 3명은 무엇을 하나요?

  • 개발은 1명이 하고, 팀원은 사용자 인터뷰·MVP 테스트(검증), 발표 장표·대본·시연을 맡는다. 개발자가 안을 내고 팀원이 기한 안에 피드백한다 (D-022 제안).

Q13. 사용자 검증은 했나요?

  • 아직 0건이다. 11/16까지 인터뷰 3명 이상, MVP 테스트 3회 이상, 결과로 고친 것 1건 이상을 목표로 한다 (S07).

4. 사업 (기술 멘토링에서 짧게)

Q14. 누가 돈을 내나요?

  • 노동자는 0원이다. 지자체(주무관)·산업단지 관리 기관이 이용권을 사서 50인 미만 사업장에 나눠 주는 구조가 1순위다. 외국인 취업자의 78.9%가 50인 미만 사업장에서 일한다 (N-04).
  • 2027-01-08 외국인 노동자 기초안전보건교육 의무화(N-20) 뒤에는 사업주 직접 구독이 두 번째다. 단, 법정 교육을 대신한다고 하지 않는다 (D-021).

Q15. 데이터로도 돈을 버나요?

  • 노동자 개인 데이터는 팔지 않는다. 사람이 검수한 소수 언어쌍 안전 문구(한국어-크메르어 등)는 자산이 될 수 있다 — 2차 창업 멘토가 좋게 본 부분이다 (D-015 제안).

Q16. 다른 지역·대상으로 넓힐 수 있나요?

  • 언어를 더하는 것은 i18n 사전과 검수 문구를 늘리는 일이다. 같은 구조를 농축산업·건설 현장의 외국인 노동자 교육으로 넓힐 수 있다. 에이전트 B(문항 출제)·C(현장 신호)가 다음 단계다.
