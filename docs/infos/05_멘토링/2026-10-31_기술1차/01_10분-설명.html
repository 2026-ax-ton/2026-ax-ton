01 · 10분 설명 — 처음에 말할 것

기준일 2026-10-31 · 말하는 사람 byeonsoyun · 화면 이 페이지를 위에서부터 한 절씩 내려가며 말한다 (절 하나 = 약 1분)

🆕 2026-10-31 21시 업데이트 — 2차 개발 완료. T1~T9 전부 끝, M0·M1 달성(계획 11/8 → 10/31, 8일 빠름), 운영 배포에서 실제 AI 번역 동작, 테스트 18묶음 1,943건 통과, CI 가동, 실측 150/150 (100%)·재시도율 0.7%·평균 2.9초. 새 결정 D-024(역번역 같은 모델·다른 프롬프트)·D-025(제3자 요청 0건). 다음은 3차 DB(T10~). 상세는 전체 스펙 설명서 §0.

1. 오늘 드리고 싶은 것 (30초)

  • 오늘은 해커톤까지 어떻게 개발할지 최종안을 가져왔습니다. 범위·설계·일정은 정해 왔습니다.
  • 멘토님께는 놓친 위험, 심사 관점의 전략, 일정이 현실적인지를 점검받고 싶습니다.

2. 무엇을 만드나 (1분)

  • 이주노동자 안전교육 이해도 검증 플랫폼입니다.
  • 지금 안전교육은 출석부 서명으로 끝납니다. 서명은 참석의 증거일 뿐 이해의 증거가 아닙니다.
  • 노동자가 자기 나라 말 음성으로 듣고, 그림 문제로 이해를 확인받아야 교육이 끝납니다. 결과는 증빙이 됩니다.
  • 6개 언어(크메르어·인도네시아어·베트남어·네팔어·태국어·한국어), 노동자는 글자를 읽지 않고도 끝까지 쓸 수 있습니다.

4. 해커톤에서 붙이는 것 — AI 번역·검수 에이전트 (2분)

 운영자: 안전 문구 입력 → [AI 번역 받기]
   에이전트 (언어마다):  번역 → 다시 한국어로 역번역 → 원문과 대조
                         ├ 뜻이 그대로 → 승인 대기
                         ├ 부정이 사라짐 → 고쳐서 다시 번역 (최대 2번)
                         └ 그래도 안 됨 → "사람에게 올림"
 운영자: 확인하고 승인 → 승인된 번역만 노동자에게 나간다
  • 왜 이것인가: 안전 문구는 "하지 마세요"가 "해도 됩니다"로 뒤집히면 사고가 납니다. 지금은 사람이 손으로 하는 이 일을 에이전트가 맡고, 사람은 판정만 합니다.
  • 넘지 않는 선: AI 결과는 항상 승인 대기, 승인은 사람만, AI가 실패하면 지금의 손 입력으로 돌아갑니다. 노동자 화면은 외부 요청 0건을 유지합니다.

4-B. 🆕 그리고 실제 서비스로 — DB를 붙입니다 (1분)

  • 지금은 데이터가 폰마다 따로라서 "노동자 폰에서 푼 결과를 담당자가 본다"가 안 됩니다. 실제 서비스라고 말할 수 없는 부분입니다.
  • 그래서 오늘 Vercel 함수 + Neon Postgres로 DB를 붙이기로 정했습니다. 진짜 로그인(비밀번호 해시·토큰), 사업장별 분리, 기기 간 동기화, 계정 없는 익명 신고까지 합니다.
  • 화면은 데이터를 Store 한 창구로만 다루게 만들어 두어서, 화면은 거의 안 바꾸고 Store 안쪽만 서버 모드로 바꿉니다. 현장 시연(file://)은 지금처럼 기기 안에서 돌아가는 로컬 모드입니다.
  • 정식 서비스 전에 남는 것(원어민 검수자, 개인정보 절차, 유료 요금제)은 운영 준비 체크리스트로 정리했습니다.

5. 어떻게 만드나 (1분 30초)

  • 운영자 화면의 agent.js가 단계를 지휘하고, Vercel 함수 2개(/api/translate, /api/backtranslate)가 Gemini를 부릅니다. 키는 서버에만 둡니다.
  • 역번역은 다른 모델이, 원문을 보지 않고 합니다. 같은 실수를 같이 놓치지 않게 하려고서입니다.
  • 대조는 이미 있는 규칙 코드(review.js)를 재사용합니다. 판정을 AI에게 맡기지 않습니다.
  • 결정 11개는 정해 두었습니다 → 02 §7.
