05 · 멘토링 — 회차별 기록과 남은 회차

기준일 2026-10-31 · 원본 C08 §2·§3 (회차 현황) · C01 §6 (1차) · S08 (2차) · A03 (기술, 10/31) · 원문 기록 자료_멘토링-원본기록/ (저장소 밖)
이 문서가 답하는 질문 멘토링을 몇 번 받았고 각 회차에서 무엇을 들었나 · 무엇을 정했나 · 남은 회차는 언제고 무엇을 들고 가나 · 수료 조건은 무엇인가

1. 수료 조건 (C08 §2)

  • 팀당 멘토링 6회 (기술개발 3 + 사업개발 3), 회당 2시간, 기간 9/28~11/20.
  • 회차마다 팀원 전원이 카메라를 켜고 얼굴이 보여야 참석으로 인정된다. 멘토가 화면 캡처로 확인한다.
  • 해커톤 당일(11/28)도 전원 참여. 하나라도 빠지면 수료증이 안 나온다 (8월 1단계 교육분까지).

❓ 위 표대로면 5회다. 수료 조건 6회에 하나가 모자란다. 사용자 확인(2026-10-31): 남은 멘토링은 기술 1 + 사업 1로 끝이다. 이전에 집계된 기술 회차가 있었는지는 모른다.

  • 단서: 기술 멘토가 2026-10-22에 「할 일 6단계」를 전달했다 (P00). 이것이 회차로 집계됐는지 확인한다.
  • 10/31 멘토에게 묻는다 (A03 §5 K7). 모자라면 11/20 전 1회를 더 잡는다.

3.2 사업 2차 — 2026-10-24 (창업 멘토링)

  • 좋게 본 것: 소수 언어쌍(한국어-태국어 등) 번역 데이터의 자산 가치. 데이터가 필요한 기업을 지불 고객군으로 넣어라.
  • 지적: 수익 구조 숫자가 과장돼 보인다. AI가 낸 숫자는 사람이 따로 재검증하라 → D-020 (보수 시나리오 기본, 제안).
  • 지불 고객: 사업주·위험관리 담당자(Risk Management Manager) / 지자체 주무관 / 산업단지 관리 기관 / 데이터 필요 기업. KPI로 구매 동기를 분석하라. B2B는 최종 결정권자(사장)와 지역 커뮤니티 입소문을 고려하라.
  • 광고·송금: 현실적으로 어렵다 → 제외 확정 (D-013·D-014).
  • 과제: 지불·이용 고객 구체화, 사업 모델·비즈니스 모델을 팀 하나의 의견으로 통합 → 11/14 발표. 원재료 S09.

3.3 기술 — 2026-10-31(토) 22:00

  • 들고 가는 것: A03 (범위·일정 컨펌, 처음 3분 요약 + K1~K8) · A01 (선택지 비교) · A02 (기술 명세).
  • 시간이 짧으면 K1 범위 → K2 /api 위치 → K5 일정 → K7 멘토링 횟수만 묻는다.
  • 최종 설명 자료 폴더: 2026-10-31_기술1차/ — 10분 설명 · 최종 개발 설계(결정 11개) · 현재 수준 · 일정 · 멘토 질문과 답 기록 · 예상 질문. 이 회차부터 멘토에게 결정을 묻지 않고, 우리가 정한 안을 점검받는다.
  • 결과: (멘토링 뒤 여기에 요약을 적는다. 상세는 05 질문과 기록)
