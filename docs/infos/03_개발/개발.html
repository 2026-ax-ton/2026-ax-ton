2. 브랜치와 git (표 1)

브랜치용도규칙
main배포 전용, 보호됨작업 커밋 금지. 배포할 때만 develop → main --ff-only. src/가 안 바뀐 커밋은 올리지 않는다. push는 main 먼저 (Vercel 빌드 건너뜀 방지)
develop기준 브랜치, 깃허브 기본작업 브랜치를 PR로 머지
feat/agent-prd-v1해커톤 작업 브랜치 (아직 없음)CLAUDE.md 진행 루틴 1번이 만든다. 혼자여도 PR을 쓴다
feature/byeonsoyun아이디어톤 작업그대로 둔다. 지금 작업 트리가 여기에 있다
feature/yesool 등 옛 팀 브랜치보존지우지 않는다 (feature/yesool은 Next.js+Supabase 별개 구현, 서버 참고용)
  • 커밋 제목: feat: fix: docs: style: refactor: chore: + 한글로 무엇을 했는지.
  • 금지: git push --force, git reset --hard, --no-verify, git add . (고친 파일만 add).
  • 이 사용자의 지시 (2026-10-31): 문서 작업 세션에서는 Claude가 커밋·푸시하지 않는다. 필요하면 사용자가 한다. 개발 루틴(아래)은 CLAUDE.md대로 커밋·push한다.

규칙이유

상태는 아이콘 + 글자 + 색 3중 (UI.okBadge 등). 새 이모지 금지흑백·색약에서도 뜻이 남게. test-icons.js가 본다
