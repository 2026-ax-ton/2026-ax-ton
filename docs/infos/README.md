1. **[02 현재 진행](02_현재-진행/현재-진행.md)** — 지금 할 일과 막힌 것을 먼저 본다

## 3. 이 폴더와 다른 문서의 관계 — 정답은 원본에 있다

- 이 폴더는 **요약과 색인**이다. 사실의 정답은 원본 문서에 있다 ([C03 §3 단일 출처](../documentations/00_개발컨벤션/C03_문서체계와-ID규칙.md)).
  - 할 일·상태 → [C01 §7](../documentations/00_개발컨벤션/C01_프로젝트-한눈에.md) · 개발 할 일 → [`07-next-tasks.md`](../07-next-tasks.md)
  - 코드 규칙 → 저장소 `CLAUDE.md` · 결정 → [C06](../documentations/00_개발컨벤션/C06_결정기록.md) · 숫자 → [S02](../documentations/10_사업화/S02_수치-근거대장.md)
- 이 폴더와 원본이 다르면 **원본이 맞다.** 코드와 문서가 다르면 **코드가 맞다.** 발견하면 이 폴더를 고친다.

---

## 4. 갱신 규칙

1. **원본을 먼저 고친다** (C01·C06·07-next-tasks 등). 그다음 이 폴더의 해당 md를 고친다
2. 고친 md 맨 위 **기준일**을 바꾸고, 맨 아래 「변경 기록」에 한 줄을 남긴다
3. html을 다시 만든다 — 저장소 루트에서 `node docs/infos/_build.js` (의존성 0, Node만 있으면 된다). 링크 검사는 `node docs/infos/_check-links.js` (깨진 링크 0개)
   - 개발 세션에서는 `CLAUDE.md` 마무리 루틴의 **「개발 후 문서 갱신 표」** 가 고칠 문서를 정한다
4. html을 손으로 고치지 않는다. 다음 빌드 때 덮어써진다

| 언제 | 고칠 곳 |
|---|---|
| 작업 하나를 끝냈을 때 | 02 현재 진행 |
| 멘토링을 받았을 때 | 05 멘토링 → 02 → (결정이면) 08 |
| 기술 결정이 났을 때 | 04 기술 스택 → 08 |
| 운영 공지가 나왔을 때 | 06 대회 규정 → 02 |
| 개발 규칙·구조가 바뀌었을 때 | 03 개발 |
