## 1. 한 문장으로

**외국인 노동자가 자기 나라 말 음성으로 안전교육을 듣고, 그림 문제로 "정말 이해했는지" 확인받는 웹 서비스.** 이름은 **SAFE-LANG**이다.

- 핵심 문장: **"이해했는지 확인되지 않으면 교육이 끝나지 않는다."**
- 해커톤에서는 여기에 **AI 번역·검수 에이전트**를 붙인다. AI가 안전 문구를 여러 나라 말로 번역하고 스스로 검사하지만, **최종 승인은 사람이 한다.**
- 🆕 그리고 **실제 서버·DB**를 붙인다 (2026-10-31 결정). 노동자 폰에서 푼 결과가 담당자 PC에 바로 나타나는, 진짜로 돌아가는 서비스가 된다.

## 2. 왜 만드나 — 문제와 해결

| 지금 공장의 안전교육 | 우리가 바꾸는 것 |
|---|---|
| 한국어로 설명하고 출석부에 **서명**하면 "교육 완료" | 내 나라 말 **음성**으로 듣고 **그림 문제**를 통과해야 "교육 완료" |
| 서명은 **참석했다는 증거**일 뿐 **이해했다는 증거가 아니다** | 이해했는지가 기록으로 남는다 |
| 사고가 나면 "교육했다"는 서명만 남는다 | 못 알아들은 부분이 대시보드에 보여서 **교육을 고칠 수 있다** |

- 외국인 취업자의 **78.9%가 50인 미만 사업장**에서 일한다 (수치 근거 대장 S02 N-04). 이런 작은 공장은 안전 담당자가 따로 없고, 생산팀장이 겸직한다.
- 2027-01-08부터 사업주는 외국인 노동자의 기초안전보건교육 이수를 챙겨야 한다 (S02 N-20).

## 3. 누가 쓰나 — 사용자 4종류

| 사용자 | 누구 | 이 서비스에서 하는 일 | 화면 색 |
|---|---|---|---|
| **노동자** (주 사용자) | 한국어가 서툰 외국인 제조업 노동자. 크메르어(캄보디아)·인도네시아어·베트남어·네팔어·태국어·한국어 6개 언어 | 교육 듣기 → 그림 문제 풀기 → 위험 신고·질문 | 코랄(빨강 계열) |
| **담당자** | 작은 공장의 안전 담당자 (보통 생산팀장이 겸직) | 공장·설비 등록 → 교육 만들기 → 결과 보기 → 증빙 인쇄 | 보라 |
| **운영자** | 번역이 맞는지 검사하는 사람 | 안전 문구의 번역을 **승인 / 대기 / 중지**로 판정. 해커톤에서는 AI 에이전트를 부르는 사람 | 보라 |
| **돈을 내는 사람** (화면은 안 씀) | 지자체 공무원(주무관), 산업단지 관리 기관, 사업주 | 이용권을 사서 공장들에 나눠 준다 | — |

> 🔑 **노동자는 돈을 내지 않는다.** 실제로 쓰는 사람(노동자)과 돈을 내는 사람(지자체·기관)이 다르다 — 1차 멘토링에서 멘토가 강조한 부분이다.

## 4. 기능 — 무엇을 할 수 있나

### 4.1 노동자 화면 6개

| 화면 | 하는 일 |
|---|---|
| **홈** | 오늘의 안전 문구, 내가 들어야 할 교육, 재교육 안내 |
| **수강** | 안전 문구를 **내 언어 음성**과 함께 한 장씩 본다. 설비 앞 **QR을 찍으면** 바로 열린다 |
| **이해도 검증** ★ | **글을 읽지 않고 손가락으로** 푸는 그림 문제 3종류 — ① 그림에서 위험한 곳 짚기 ② 올바른 작업 고르기 ③ 보호구 짝 맞추기. 틀리면 어떤 사고가 나는지 바로 보여 준다 |
| **위험 신고** | 위험한 곳을 그림이나 음성으로 **익명** 신고 |
| **현장 소통** | 궁금한 것을 글·댓글로 묻는다. 이름을 숨길 수 있다 |
| **마이** | 내 교육 이력, 언어 바꾸기, 글자 크기 |

### 4.2 관리 화면 5개 (담당자·운영자)

| 화면 | 하는 일 |
|---|---|
| **사업장 등록** | 공장 규모, 쓰는 언어, 공정·설비, 노동자 등록 |
| **문구 라이브러리** (운영자) | 안전 문구의 언어별 번역을 승인·대기·중지로 판정. 🆕 해커톤에서 **[AI 번역 받기]** 버튼이 생긴다 |
| **교육 만들기** | **승인된 문구만** 골라 교육과 그림 문제를 만들고 QR과 함께 발급 |
| **대시보드** | 언어별·위험유형별 정답률, 신고 처리, 재교육 지시 |
| **증빙** | 감독기관에 낼 교육 증빙 인쇄. **미이수자도 빠짐없이** 들어간다 |

### 4.3 🆕 해커톤에서 더하는 기능 — AI 번역·검수 에이전트

운영자가 한국어 안전 문구 하나를 넣고 [AI 번역 받기]를 누르면:

1. AI가 5개 언어로 **번역**한다
2. 다른 AI가 그 번역을 **다시 한국어로 되돌린다** (역번역)
3. 원래 문장과 비교해 **뜻이 뒤집혔는지** 검사한다 — 예: "손을 넣지 **마세요**"가 "손을 넣어도 **됩니다**"가 됐는지
4. 뒤집혔으면 **고쳐서 다시 번역**한다 (최대 2번)
5. 그래도 안 되면 **"사람에게 올림"** 표시를 붙인다
6. 모든 결과는 **"대기"** 상태로 저장되고, **운영자가 승인해야** 노동자에게 나간다

> 🔑 **왜 사람이 승인하나?** 안전 지시가 잘못 번역되면 그대로 사고가 난다. AI는 사람의 일을 "번역 입력"에서 "확인·판정"으로 줄여 줄 뿐, 책임은 사람이 진다.

### 4.4 🆕 해커톤에서 더하는 기능 — 진짜 로그인과 기기 간 공유 (DB)

| 지금 | DB를 붙인 뒤 |
|---|---|
| 데이터가 그 폰에만 있다. 노동자가 풀어도 담당자 PC에서 안 보인다 | **노동자 폰에서 풀면 담당자 PC 대시보드에 20초 안에 나타난다** |
| 로그인이 시연용이다 (비밀번호가 그대로 저장) | **진짜 로그인** — 비밀번호를 알아볼 수 없게 바꿔(해시) 저장, 5번 틀리면 10분 잠금 |
| 공장 하나 기준 | 공장마다 공간이 나뉜다. **다른 공장 데이터는 볼 수 없다** |
| 브라우저 데이터를 지우면 사라진다 | 서버에 남는다 |

- 담당자가 공장을 등록하면 **가입 코드**를 받고, 노동자는 그 코드와 자기 사번(식별번호)으로 가입한다.
- **익명 신고는 그대로 익명이다.** 서버에 저장할 때도 누가 보냈는지 버린다.
- 공장에서는 폰 한 대를 여럿이 쓸 수 있어서, 문제를 다 풀면 **자동으로 로그아웃**된다.
- 인터넷이 끊겨도 폰에 쌓아 두었다가 다시 연결되면 올린다.

## 5. 비기능 — 기능은 아니지만 꼭 지키는 것

"무엇을 하나"가 기능이라면, 비기능은 **"어떻게 해야 하나"**다. 우리 서비스는 공장 현장을 전제로 한다.

| 지키는 것 | 왜 |
|---|---|
| **글을 한 자도 안 읽고 끝까지 쓸 수 있다** — 모든 안내에 음성 | 노동자가 한국어도, 자기 나라 글도 잘 못 읽을 수 있다 |
| **버튼이 크다** (60px 이상) | 장갑 낀 손으로 누른다 |
| **인터넷이 끊겨도 화면이 열린다** | 공장 안은 인터넷이 약하다 |
| **노동자 화면은 다른 회사 서버에 요청을 보내지 않는다** (🆕 DB 도입 뒤에는 우리 서버하고만 주고받는다) | 빠르고, 개인 정보가 엉뚱한 곳으로 새지 않는다 |
| **승인된 번역만 안전 지시로 쓴다** | 오역이 그대로 사고가 된다 |
| **신고는 익명이다** — 누가 신고했는지 저장하지 않는다 | 익명이 깨지면 아무도 신고하지 않는다 |
| **미이수자를 숨기지 않는다**, 인사평가용 순위를 만들지 않는다 | 감시 도구가 되면 현장이 등을 돌린다 |
| 통과 못 하면 **노동자 탓이 아니라 교육의 실패**로 본다. **"면책"이라는 말을 쓰지 않는다** | 우리 기록은 책임을 대신해 주지 않는다 |
| 외국인등록번호·여권번호를 받지 않는다 | 필요 없는 개인정보는 받지 않는다 |
| 색만으로 상태를 구분하지 않는다 (아이콘 + 글자 + 색) | 색약·흑백 화면에서도 뜻이 남는다 |

> 이 원칙들은 **자동 테스트가 매번 검사**한다. 누가 실수로 원칙을 어기는 코드를 넣으면 테스트가 실패한다.

## 6. 사용 기술 — 무엇으로 만들었나

> 웹 서비스는 보통 **프론트엔드(화면) + 백엔드(서버) + DB(저장소)** 로 나뉜다. 우리는 일부러 **아주 가볍게** 만들었다.

| 구분 | 우리가 쓰는 것 | 쉽게 말하면 | 왜 이렇게 했나 |
|---|---|---|---|
| **프론트엔드** (화면) | **HTML + CSS + 순수 JavaScript** · React 같은 프레임워크 **없음** | 레고 세트(프레임워크) 없이 기본 블록으로 직접 지은 집 | 설치·빌드가 필요 없어서 **파일을 더블클릭만 해도 열린다.** 해커톤 현장 시연이 "제출한 HTML 파일을 더블클릭"하는 방식이라 딱 맞는다. 싼 폰에서도 빠르다 |
| **백엔드** (서버) | **지금은 없다.** 🆕 해커톤에서 **Vercel 서버리스 함수**를 만든다 — AI 심부름 2개 + 로그인·데이터 저장·신고 받기 | 서버 = 가게 주방. 우리는 큰 주방을 차리지 않고, **필요할 때만 와서 일하는 직원들**(서버리스)을 둔다 | AI·DB의 **비밀 열쇠**를 화면 코드에 두면 누구나 훔쳐 간다. 그래서 열쇠는 서버에만 두고, 서버가 "이 사람이 이 공장 담당자가 맞나"를 확인한다 |
| **DB** (데이터 저장소) | 지금은 각 폰의 작은 저장 공간(**localStorage**). 🆕 해커톤에서 **Neon Postgres**(클라우드 DB, 싱가포르)를 붙인다 | 지금 = **각 폰에 달린 서랍** → 🆕 **모두가 함께 쓰는 창고**. 서랍은 창고의 사본(캐시)으로 남는다 | 여러 폰·PC가 같은 데이터를 본다. 인터넷이 끊겨도 서랍으로 계속 쓴다. 현장 시연(파일 더블클릭)에서는 서랍만 쓴다 |
| **AI** 🆕 | **Google Gemini** | 번역 담당 AI와 검사 담당 AI를 **서로 다른 모델**로 쓴다 | 같은 AI가 번역하고 검사하면 같은 실수를 같이 놓친다 |
| **오프라인** | **Service Worker** | 화면 파일을 폰에 미리 복사해 두는 기능 | 인터넷이 끊겨도 열린다 |
| **음성** | 브라우저에 들어 있는 **음성 합성·받아쓰기** | 폰이 원래 가진 "읽어 주기" 기능 | 외부 음성 서비스를 쓰면 외부 요청이 생긴다 |
| **배포** (인터넷에 올리기) | **Vercel** + **GitHub** | GitHub = 코드 보관함, Vercel = 그 코드를 인터넷 주소로 열어 주는 곳 | 코드를 올리면 자동으로 https://2026-ax-ton.vercel.app 에 반영된다 |
| **테스트** | 자동 테스트 **1,619건** (2026-10-31 전부 통과) | 로봇이 화면 13개를 직접 눌러 보며 1,619가지를 확인 | 개발자가 1명이라 **사람 대신 테스트가 검사관** 역할을 한다 |

> 📌 **"DB를 어떻게 붙였나?"** 라는 질문이 나올 수 있다. 답: 처음부터 모든 화면이 데이터를 `Store`라는 **한 창구로만** 다루게 만들어 두어서, 화면은 거의 그대로 두고 **창구 안쪽만 서버와 통하게** 바꿨다. 그래서 짧은 기간에 붙일 수 있었다.

## 7. 동작 흐름 — 안에서 어떻게 돌아가나

### 7.1 큰 흐름 (사람 기준)

```
 ① 담당자: 공장·설비·노동자 등록
        ↓
 ② 운영자: 안전 문구 입력 → (🆕 AI 번역 받기) → 언어별로 확인하고 [승인]
        ↓
 ③ 담당자: 승인된 문구만 골라 교육 + 그림 문제 만들기 → 설비 앞에 QR 붙이기
        ↓
 ④ 노동자: QR 찍기 → 내 언어 음성으로 듣기 → 그림 문제 → 통과해야 "완료"
        ↓
 ⑤ 담당자: 대시보드에서 "베트남어 노동자들이 끼임 위험 문제를 많이 틀림" 확인
           → 재교육 지시 · 교육 고치기 · 증빙 인쇄
        ↓
 (다시 ②·③으로 — 교육이 점점 좋아지는 순환)
```

### 7.2 시스템 구조 (화면·서버·AI 기준)

| 층 | 무엇이 있나 | 하는 일 |
|---|---|---|
| ① 사용자 기기 — 노동자 화면 6개 | 홈·수강·그림 문제·신고·소통·마이 | 인터넷 밖으로 요청을 **보내지 않는다** |
| ① 사용자 기기 — 관리 화면 5개 | 사업장 등록·문구 라이브러리·교육 만들기·대시보드·증빙 | 🆕 문구 라이브러리에만 [AI 번역 받기]가 있다 |
| ② 데이터 창구 `Store` | 모든 화면이 데이터를 넣고 꺼내는 **단 하나의 창구** | 실제 저장은 그 기기의 **localStorage(서랍)** |
| ③ 🆕 AI 에이전트 `agent.js` | 운영자 화면 안에서 도는 지휘자 | 번역 → 역번역 → 검사 → 재시도 순서를 정한다 |
| ④ 🆕 Vercel 서버리스 함수 | `/api/translate` · `/api/backtranslate` · `/api/auth` · `/api/store` · `/api/reports` | **비밀 열쇠**를 갖고 AI·DB에 대신 요청한다. 로그인한 사람이 누구인지, 어느 공장 사람인지 확인한다 |
| ⑤ 🆕 Google Gemini | 번역 AI · 검사 AI (서로 다른 모델) | 번역문과 되돌린 한국어를 돌려준다 |
| ⑥ 🆕 Neon Postgres (DB) | 공장·계정·교육·이수 기록·신고·문구 | 모두가 함께 쓰는 창고. 서버 함수만 열 수 있다 |

```
 운영자가 [AI 번역 받기]
   → ③ agent.js
      → ④ Vercel /api/translate      → ⑤ Gemini (번역 AI)       → 번역문
      → ④ Vercel /api/backtranslate  → ⑤ Gemini (다른 검사 AI)  → 되돌린 한국어
      → ③ 규칙 검사 (뜻이 뒤집혔나?)
   → ② Store에 "대기"로 저장
   → 운영자 [승인]
   → ① 노동자 화면에 나간다

 🆕 노동자가 폰에서 문제를 풀면
   → ② Store가 폰 서랍에 저장 + 보낼 목록에 넣음
   → ④ Vercel /api/store (이 사람이 이 공장 노동자 맞나 확인)
   → ⑥ Neon DB에 저장
   → 담당자 PC 대시보드가 20초마다 새로 받아 와서 표시
```

- **노동자 화면은 Vercel이나 AI를 부르지 않는다.** AI를 부르는 것은 운영자 화면 하나뿐이다.
- AI 결과는 다시 브라우저로 돌아와 **"대기"** 상태로 서랍에 저장된다. 운영자가 승인해야 노동자 화면에 나간다.

### 7.3 AI 에이전트 한 바퀴 (언어 하나 기준)

```
 "회전 중인 롤러에 손을 넣지 마세요"
   → [번역 AI] 크메르어로 번역
   → [검사 AI] 그 크메르어를 한국어로 되돌림 (원문은 안 보여 줌)
   → [규칙 검사] "마세요"(부정)가 살아 있나?
        ├ 살아 있다 → 완료 (대기 상태로 저장)
        └ 사라졌다 → "뜻이 바뀌었으니 부정을 다시 확인해" 힌트를 주고 재번역 (최대 2번)
                     → 그래도 안 되면 "사람에게 올림"
```

## 11. 용어 풀이

| 용어 | 뜻 |
|---|---|
| 프론트엔드 | 사용자가 보는 화면 쪽 코드 |
| 백엔드 / 서버 | 화면 뒤에서 일을 처리하는 컴퓨터 쪽 코드 |
| DB (데이터베이스) | 데이터를 모아 두는 큰 저장소 |
| localStorage | 브라우저 안의 작은 저장 공간. 기기마다 따로 |
| 🆕 Neon Postgres | 우리가 쓰는 클라우드 DB 서비스. 싱가포르에 있다 |
| 🆕 서버 모드 / 로컬 모드 | 서버 모드 = DB에 저장해 여러 기기가 함께 봄. 로컬 모드 = 그 기기에만 저장 (현장 시연용) |
| 🆕 가입 코드 | 담당자가 받는 우리 공장 전용 번호. 노동자는 이걸로 가입한다 |
| 🆕 해시 | 비밀번호를 거꾸로 되돌릴 수 없게 바꾸는 것. 서버 관리자도 원래 비밀번호를 못 본다 |
| 프레임워크 | React처럼 화면을 쉽게 만들게 도와주는 큰 도구 세트. 우리는 안 쓴다 |
| 서버리스 함수 | 서버를 직접 운영하지 않고, 요청이 올 때만 잠깐 실행되는 작은 서버 코드 |
| API | 프로그램끼리 주고받는 창구. "번역해 줘"라고 요청하면 결과를 돌려준다 |
| API 키 | API를 쓸 수 있는 비밀 열쇠. 새면 남이 우리 돈으로 AI를 쓴다 |
| AI 에이전트 | 한 번 답하고 끝나는 AI가 아니라, **목표를 위해 스스로 여러 단계를 하고 결과를 검사하고 다시 시도하는** AI |
| 역번역 | 번역한 문장을 다시 원래 언어로 번역해 보는 것. 뜻이 바뀌었는지 확인하는 방법 |
| 검수 / 승인·대기·중지 | 번역이 맞는지 사람이 판정하는 것. **승인**만 노동자에게 나가고, **대기**는 아직 안 봄, **중지**는 오역이라 내림 |
| 오프라인 / Service Worker | 인터넷 없이 동작 / 그걸 가능하게 하는 브라우저 기능 |
| 배포 | 만든 코드를 인터넷 주소로 열 수 있게 올리는 것 |
| 자동 테스트 | 프로그램이 프로그램을 검사하는 것. 사람이 일일이 눌러 보지 않아도 된다 |
| PRD | 기능별 기획서 ("무엇을 왜 만드나") |
| MVP 테스트 | 최소 기능 버전을 실제 사용자에게 써 보게 하는 시험 |
| QR | 폰 카메라로 찍으면 주소가 열리는 네모 코드. 설비 앞에 붙인다 |
