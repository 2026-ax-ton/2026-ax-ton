2. 새 세션(사람·Claude)이 읽는 순서

  1. 02 현재 진행 — 지금 할 일과 막힌 것을 먼저 본다
  2. 01 프로젝트 개요 §3 제품 원칙 — 어떤 작업이든 이 원칙을 어기면 안 된다
  3. 작업 종류에 맞는 폴더 하나 — 개발이면 03·04, 멘토링 준비면 05·06, 사업이면 07
  4. 더 자세한 내용이 필요하면 각 문서의 「원본」 링크를 따라간다

이 폴더에 답이 없으면 그때 사용자에게 묻고, 답을 받은 뒤 이 폴더에 적는다. 같은 질문을 두 번 하지 않는 것이 이 폴더의 목적이다.

3. 이 폴더와 다른 문서의 관계 — 정답은 원본에 있다

  • 이 폴더는 요약과 색인이다. 사실의 정답은 원본 문서에 있다 (C03 §3 단일 출처).
    • 할 일·상태 → C01 §7 · 개발 할 일 → 07-next-tasks.md
    • 코드 규칙 → 저장소 CLAUDE.md · 결정 → C06 · 숫자 → S02
  • 이 폴더와 원본이 다르면 원본이 맞다. 코드와 문서가 다르면 코드가 맞다. 발견하면 이 폴더를 고친다.

4. 갱신 규칙

  1. 원본을 먼저 고친다 (C01·C06·07-next-tasks 등). 그다음 이 폴더의 해당 md를 고친다
  2. 고친 md 맨 위 기준일을 바꾸고, 맨 아래 「변경 기록」에 한 줄을 남긴다
  3. html을 다시 만든다 — 저장소 루트에서 node docs/infos/_build.js (의존성 0, Node만 있으면 된다). 링크 검사는 node docs/infos/_check-links.js (깨진 링크 0개)
    • 개발 세션에서는 CLAUDE.md 마무리 루틴의 「개발 후 문서 갱신 표」 가 고칠 문서를 정한다
  4. html을 손으로 고치지 않는다. 다음 빌드 때 덮어써진다
