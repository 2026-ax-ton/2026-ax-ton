영세사업장 위험기계 안전콘텐츠 조사 — 기계별 결과

지금까지 실제로 조사한 기계 2개의 과정과 찾은 내용을 그대로 적는다. **재사용 가능한 규칙·체크리스트는 2026-11-09_기계조사-규칙.md에 따로 있다** — 다음 기계를 조사할 땐 그 문서를 먼저 읽고, 지난 조사가 실제로 어떻게 진행됐는지 참고가 필요할 때 이 문서를 본다.

기계 1 — C형 유압프레스

0. 출발점 — 질문

"산업단지·영세사업장에서 가장 많이 쓰는 유압프레스 기계는 뭔가? 이해도 검증 콘텐츠(퀴즈·hotspot)를 그 기계 기준으로 만들고 싶다."

1. 기종 좁히기 — 브랜드가 아니라 구조로

  • 먼저 "브랜드/제조사 점유율"로 검색했으나 공식 통계 자체가 없음 (영세 금형업체 83%가 10인 미만이라 통계가 안 잡힘).
  • 그래서 기준을 "브랜드"에서 "구조방식(기종 유형)"으로 바꿨다. 검색어 예: 산업단지 영세사업장 많이 사용하는 유압프레스 제조사 기종 순위, 국내 프레스기 제조사 점유율 중소 금속가공 영세사업장
  • 결론: C형(갭)프레스가 구조방식 기준 1순위 — 개방형이라 영세 판금·부품가공 현장 표준, 끼임사고 최다 유형. (근거: KOSHA 재해통계·업계 설명 종합, 단일 출처 숫자표는 없음 — 이 부분은 "합리적 추정"이지 "공식 통계 인용"이 아니라고 매번 사용자에게 밝혔다.)

2. 공식 안전기준 문서 찾기 — KOSHA Guide

  • 검색어: KOSHA 프레스 안전작업지침 매뉴얼 PDF 안전보건기준
  • 1차 실패: 검색엔진이 "M-122-2012"라는 번호를 요약해서 내놓았는데 틀린 번호였다. kosha.or.kr 의 공식 다운로드 URL은 접속은 되지만(HTTP 200) 내용이 0자로 비어 응답 — 검색 스니펫을 실제 원문 확인 없이 믿으면 안 된다.
  • 해결: 공식 사이트 직링크 대신, 그 문서를 미러링한 민간/공공 게시판을 찾아 (eshc.kr 게시글) 첨부 PDF 원본(moel.go.kr 다운로드 링크)을 받아 Read 도구로 PDF를 직접 열어 표지의 진짜 코드번호를 확인했다. → 진짜는 KOSHA CODE M-30-2002「프레스 방호장치의 선정·설치 및 사용 기술지침」.
  • 교훈: PDF/문서 링크는 검색 요약만 믿지 말고 반드시 실제로 열어서 표지·코드번호·발행처를 확인한다. 특히 정부기관 사이트의 "다운로드" 엔드포인트는 200을 반환해도 내용이 빈 경우가 있다.

3. 구조 고유 특성 찾기 — "공통 기준"과 "이 기종만의 특징"을 나눔

사용자가 "포괄적 주의사항 말고 이 기계 특유의 특징도 필요하다"고 명확히 요구함. M-30-2002 는 모든 프레스 공통 기준(가드식/양수조작식/광전자식 등)이라 C형만의 특징은 아니었다 — 그래서 별도로 찾았다.

  • 검색어: C형 프레스 프레임 변형 디플렉션 편심하중 단점 특징 O형 비교
  • 영어 자료(ADH Machine Tool 블로그)에서 구조공학적 설명을 찾음: C형은 3면 중 앞면만 열려 있어 편심하중(중심에서 벗어난 위치에서 가압) 시 위아래 팔이 벌어지는 각도 디플렉션이 O형/H형보다 심함.
  • 실제 사고 사례도 함께 찾아 영세사업장 연관성을 확인: 검색어 C형 프레스 끼임사고 사례 산업안전보건공단 재해조사 측면 개방 → 검색엔진 요약이 "2020년 평택, 스크랩 제거 중 끼임"이라고 틀리게 요약함. 실제 URL(moel.go.kr/policy/policydata/view.do?bbs_seq=4842)을 직접 열어보니 전혀 다른 사건(2004년 서울, 재생업체, 근로자 2명, 압축작업 중 협착사망)이었음. → 여기서도 검색 요약을 그대로 믿지 않고 원문 대조가 필수였다.

4. 기계 종류(유압 vs 기계식) 고유 특성 — 블로그 기사

사용자가 "유튜브나 블로그도 찾아봐 달라"고 추가 요청.

  • 검색어: C형 유압프레스 사용 주의사항 블로그 후기 안전수칙 현장, C형 프레스 작업 유튜브 안전교육 끼임 조작법
  • 기계설비신문(업계 전문지) 기사를 찾음 — "유압프레스의 특성과 안전관리의 핵심 수칙" (노정진, 포스코 안전환경 리더 기고, 2026.04.06). C형을 "가장 일반적인 형태"로 명시하고, 유압 고유 위험(배관·호스 누유, 유압유 고압 분출 화상·감전, 금형 미고정/과압 시 파편비산, 안전장치 임의해제)을 구체적으로 서술 — 이건 기계식 프레스 기준인 M-30-2002 에는 없는 내용이었다.
  • YouTube 영상([재해사례] 프레스 정비 작업 중 작업자 끼임)도 검색에 걸렸으나 자막/본문 내용을 가져올 방법이 없어 제목·존재만 확인하고 내용은 인용하지 않았다. → 영상은 "참고용으로 존재를 알려줄 뿐 인용 근거로는 못 쓴다"가 맞는 처리.

5. 모델명(제조사·기종) 확정 — 끝까지 불확실로 남은 부분

  • 검색으로 남양기공(주) C형 유압프레스 NCP-20/NCP-30 (20톤/30톤, 1975년 설립, 약 3,000대 공급 실적)을 찾음 — 여러 검색 스니펫과 komachine.com(제3자 카탈로그)이 일치해서 회사 실존은 신뢰.
  • 그러나 제조사 공식 홈페이지(nypress.co.kr)는 SSL 자체서명 인증서 오류로 실제 fetch 접속 자체가 실패 — 제품페이지 원문은 끝까지 못 열었다.
  • 전용 사용설명서(취급설명서) PDF도 공개된 곳을 못 찾음 — 검색에 걸린 "NCP Series" 매뉴얼은 전혀 다른 회사(일본 나치후지코시, 유압펌프 제조사)의 동명이인 제품이었다. 모델명이 같다고 같은 제품이 아니다 — 제조사까지 대조해야 함.
  • 결론 처리: 모델명(NCP-20/NCP-30)은 "참고용 예시"로만 쓰고, 콘텐츠의 근거는 "구조 유형(C형 유압프레스)"에만 걸었다. 특정 모델 단정은 하지 않음.

6. 콘텐츠로 변환 — Store.library 반영

  • 조사한 문장을 그대로 콘텐츠에 넣지 않고, 노동자에게 주는 한 줄 지시문으로 바꿔 src/assets/seed.js 의 LIBRARY 배열에 추가했다 (ph-7~ph-12).
  • 전부 status: 'waiting' — 이 프로젝트 규칙상 AI가 조사·작성한 문구는 사람이 검수(admin/library.html)하기 전까지 실제 지시문으로 못 쓴다. 번역(translations)도 아직 안 돌렸으므로 빈 객체로 둠.
  • 출처(URL·기사명·KOSHA 코드번호)는 코드 주석으로 남겨, 나중에 검수자가 "이 문장이 어디서 왔는지" 추적할 수 있게 했다.
  • 세부 데이터(예시 데이터)를 바꾸면 그 개수를 세는 테스트들이 함께 깨진다 (tests/test-smoke.js, test-content.js, test-db.mjs, test-library.js) — 실패 목록을 보고 "개수 기대값"만 새 값으로 고쳤다. 기존 로직을 바꾼 게 아니라 시드 데이터가 늘어난 것이므로, 테스트를 고치는 게 맞는 대응이다.

기계 2 — 사출성형기 (같은 절차를 "다른 종류"에 재현)

기계 1 에서 세운 1~6단계를 그대로 다시 돌렸다. 구조(프레스는 압착, 사출성형기는 가열+사출+형체결)가 완전히 다른 기계라 절차가 설비 종류를 안 타는지를 검증하는 자리였다.

1. 기종 좁히기

  • 검색어: 영세사업장 많이 사용하는 사출성형기 종류 횡형 수형 톤수
  • 공식 점유율 통계는 역시 없었음. 대신 업계 설명 종합으로 횡형(수평형)이 "전 세계적으로 가장 널리 쓰이는 형태"(사출+형체 장치가 일직선 수평 배치, 취출 쉬움·자동화 용이·고속·생산성)임을 확인. 톤수는 30~268T 범위로 다양함 — 이번엔 톤수·브랜드까지 좁히지 않고 "횡형"이라는 구조까지만 확정.

2. 공식 안전기준 문서 찾기

  • 검색어: KOSHA 사출성형기 방호장치 기술지침 끼임 안전수칙 PDF
  • 이번엔 두 개가 걸림 — M-187-2016 사출성형기 방호조치에 관한 기술지침, M-56-2020 사출성형기의 안전작업에 관한 기술지침.
  • M-187-2016 을 미러링한 게시판(insdoit.co.kr)의 페이지 본문(목적·적용범위)은 직접 열어 확인함 — "산업안전보건기준에 관한 규칙 제121조(사출성형기 등의 방호장치)"에 근거한다는 것까지 확인됐다. 단 첨부 PDF 자체의 다운로드는 실패(세션/쿠키가 필요한 다운로드 방식으로 보임, HTML 오류 페이지만 돌아옴). → 여기서는 "본문까지만 확인되고 PDF 세부조항은 확인 못 함"을 그대로 인정하고, 세부조항 인용 없이 존재·근거법령만 쓰는 선에서 멈췄다. (기계 1 의 "검색 요약 말고 원문 확인" 원칙을 지키되, 원문조차 못 받으면 못 받은 한계를 숨기지 않고 밝히는 것도 같은 원칙의 연장.)

3~4. 전용 특성 + 실제 자료 — 공식 "근로자용 교육자료"를 바로 찾은 경우

  • 검색 중 esafetykorea.or.kr 에 올라온 고용노동부·안전보건공단 공동 제작 OPS(One Point Sheet) "사출성형기 작업안전" (문서번호 2023-교육혁신실-859)를 발견. PDF를 Read 도구로 직접 열어 전체 내용(2페이지)을 확인함 — 이번엔 기계 1 의 "표지만 확인"보다 더 나아가 본문 전체(사고사례 2건 + 10항목 안전점검표)를 통째로 읽었다.
  • 원문 그대로 확인된 내용:
    • 위험요인 3가지: 금형 사이 손 끼임(제품 취출), 이젝터-금형 사이 신체 끼임 (점검 중), 분쇄기 스크랩 제거 중 손가락 감김
    • 실제 사고 2건 — ① 안전문 연동장치(리미트 스위치)를 무효화하고 노즐을 뚫다가 끼임, ② 반자동 운전 중 금형 내부에서 작업하다 안전도어가 외부 충격으로 닫히며 끼임
    • 안전점검표 10항목 — 안전인증/안전검사, 안전문 연동장치 정상작동, 가열 실린더 히터 방호덮개, 수리·점검 시 전원차단+잠금+"작업중" 표시, 비상정지버튼, 노즐 충전부 절연캡 등
  • 이번엔 블로그/유튜브를 따로 더 찾지 않았다 — 공식 교육자료 자체가 이미 "이 기계만의 특징 + 실제 사고 + 점검표"를 다 갖추고 있어서, 기계 1 처럼 공식기준(공통)과 블로그(전용특성)를 따로 찾아 조합할 필요가 없었다. → 교훈 추가: 항상 공식기준→전용특성→블로그 순서를 기계적으로 반복할 필요는 없다. 공식 "근로자용 OPS/교육자료"가 있으면 그게 더 품질이 높고(실제 사고 기반, 노동자 눈높이) 그걸로 충분할 때가 있다 — 매 단계를 채워야 한다는 강박 없이, 찾은 자료의 품질을 보고 단계를 생략해도 된다.

5. 모델명 확정 — 처음엔 생략했다가, 사용자가 "기계 1 과 동일한 깊이로" 요구해 다시 함

  • 처음엔 "비용 대비 효과 적다"고 판단해 생략했었다. 그런데 사용자가 "사출성형기도 모델명까지 조사해줘, 다른 모델이 읽어도 똑같이 조사해야 한다"고 명시적으로 대칭을 요구했다 — 이 경우 생략 판단을 접고 다시 조사했다. → 교훈: "비용 대비 효과로 생략해도 된다"는 기본값일 뿐이고, 사용자가 다른 조사 건과 같은 깊이를 명시적으로 요구하면 그 지시가 우선한다.
  • 검색어: 국내 중소 영세사업장 많이 사용하는 사출성형기 제조사 모델 우진플라임 엘에스엠트론 동신유압, 우진플라임 TB시리즈 사출성형기 모델 톤수
  • 우진플라임(Woojin Plaimm) — 국내 사출성형기 전문 제조사, 30여 개국 6,000여 회사에 공급, 2000년 국내 최초 전동식 사출성형기 개발. 제품군 중 TB-G5 시리즈("글로벌 절전형 하이브리드 토글식", 90~880톤)가 영세·중소 현장에서 흔한 범용 유압(토글)식에 해당.
  • 공식 홈페이지(woojinplaimm.com)를 실제로 열어 확인 — 기계 1 의 nypress.co.kr 과 달리 SSL 인증서 문제 없이 정상 로드됨. 제품소개 → TB-G5 페이지(/page/product_new/product.php?pd_id=5&me_code=2020)에서 소개문구 "90톤부터 880톤까지의 형체력을 제공하는 절전형 하이브리드 사출성형기"를 원문 그대로 확인.
  • 톤수별 스펙표(형체력·스크류직경·사출압력 등)는 이 페이지에 없음 — 기능 설명(센터프레스 일체형 형판, L/M가이드, 서보펌프 시스템, 컨트롤러 IMC710 등)만 텍스트로 있고 표는 JS 렌더링이라 fetch 로 못 가져옴.
  • 카탈로그 페이지(/page/prcenter/catalogue.php?me_code=4040)도 실제로 열어 확인 — "TB-G5" 카탈로그 항목 자체는 목록에 있으나, 실제 PDF 다운로드 링크는 JS(onclick)로 처리돼 fetch 로는 못 얻음. 썸네일 이미지 URL만 확인됨 — "자료실은 있지만 그 안의 파일은 못 받았다"는 한계를 그대로 남긴다.
  • 기계 1 과 비교한 핵심 차이: 기계 1(남양기공)은 회사 홈페이지 자체가 인증서 오류로 못 열려 "회사 실존만 간접 확인"에 그쳤다. 기계 2(우진플라임)는 홈페이지가 정상적으로 열려 제품라인·소개문구까지 1차 출처로 직접 확인했고, 막힌 지점은 그보다 한 단계 더 안쪽인 "스펙표·PDF 파일 자체"였다. → 같은 "모델명 조사" 단계도 막히는 지점이 설비마다 다를 수 있다. 어디까지 열리고 어디서부터 막혔는지를 구체적으로 적어야 다음 조사자가 어디를 다시 시도해야 할지 알 수 있다.
