01 — 왜 새로 안 만들고 이어가나

이미 있는 것 위에 쌓는 이유

이미 잘 만들어져 있음

화면 11개가 실제로 동작하고, 자동 검사 1,200건 이상을 통과했고, 실제 주소로 배포까지 끝난 상태입니다. 이 완성도를 새로 만들면 그것만으로 해커톤 기간이 다 갑니다.

다음 단계가 이미 정해져 있었음

아이디어톤 발표를 준비하며 "다음엔 뭘 할지" 로드맵을 이미 짜뒀습니다. 이번 해커톤은 그 다음 단계를 실제로 실행하는 자리입니다.

평가표와 정확히 맞음

AI 활용이 핵심 기능에 실질적으로 기여했는가가 배점 10점으로 명시돼 있습니다. 우리는 "AI 자리는 설계했지만 아직 안 돌아간다"를 이미 스스로 진단해뒀고, 이번에 그 자리를 채웁니다.

02 — 원래 있던 확장 로드맵

아이디어톤 때 이미 짜둔 다음 단계

서버 없이 며칠 안에 할 수 있는 것부터, 쌓일수록 진짜 강점이 되는 것까지 4단계로 정리해뒀습니다. 이번 해커톤은 P2 단계 중 AI로 채울 수 있는 두 가지를 실행합니다.

P0 · 지금 당장
서버 없이 며칠
  • 실제 사람에게 보여주기
  • QR 폰 촬영 확인
  • iOS 확인
P1 · 서버 붙이기
저장 공간 확보
  • 기기 간 데이터 공유
  • 기한 알림
  • 여러 사업장 지원
P2 · 이번 해커톤
AI 에이전트로 채움
  • 번역 검수 파이프라인 → 에이전트
  • 위험 신고 대응 → 에이전트
  • 현장 실사진 문제 출제 (발표에서 다음 계획으로)
P3 · 쌓이면 강점
시간이 필요한 자산
  • 검수 문구 200개 × 6개 언어
  • 언어별 오답 데이터
  • 문항 난이도 자동 분석
P2 안에서도 서버·인프라가 크게 필요한 항목(현장 사진, 6개 언어 실음성)은 발표에서 "다음 계획"으로만 보여주고, 지금 당장 구현하는 건 데이터 흐름만으로 실제로 작동시킬 수 있는 두 에이전트입니다.
03 — 이번에 새로 만드는 것

AI 에이전트 두 가지

1

안전 문구 번역 검수 에이전트

지금까지 번역과 역번역 대조를 전부 사람이 손으로 합니다. "AI를 쓰면 좋겠다"고 자리는 설계해뒀지만, 실제로 AI가 이 일을 한 적은 없습니다.
바뀌는 것
  1. 한국어 문구를 여러 언어로 초벌 번역
  2. 다시 한국어로 역번역해 뜻이 뒤집혔는지 스스로 대조
  3. 이상하면 운영자에게 검토 요청
왜 중요한가 — 이 프로젝트의 핵심 메시지가 "오역이 그대로 사고로 이어진다"였습니다. 그 위험한 지점에 AI가 1차 안전판이 되는 거라, 메시지와 정확히 맞습니다.
2

위험 신고 대응 에이전트

지금까지 노동자가 위험 요소를 신고하면 담당자 화면에 뜨기만 하고, 그 다음 대응은 전부 사람 몫입니다.
바뀌는 것
  1. 신고 내용으로 관련 안전 매뉴얼 스스로 검색
  2. 위험도를 판단해 우선순위 부여
  3. 대응 절차 자동 안내 (실행은 사람 승인 후)
왜 중요한가 — 신고가 접수되고 끝나는 게 아니라, 그 다음 판단까지 시스템이 도와준다는 걸 데모에서 눈으로 보여줄 수 있습니다.
04 — 한 번만 짚고 갈 것

AI 에이전트가 정확히 뭔가

"질문에 답하는 챗봇"과 "여러 단계를 스스로 판단해 행동까지 이어가는 에이전트"는 다릅니다. 같은 상황을 두 방식이 어떻게 다르게 처리하는지 비교하면 이렇습니다.

일반 챗봇이라면
1"위험 신고가 들어왔어요"라고 답하고 끝
에이전트라면
1상황을 파악한다
2관련 매뉴얼을 스스로 검색한다
3담당자에게 알린다
4필요하면 사람 승인을 받고 조치까지 이어간다
안전장치 (사람 승인) — 되돌리기 어려운 조치(작업 중단 지시, 재교육 강제 지정 등)는 에이전트가 마음대로 실행하지 않습니다. 반드시 사람이 확인 버튼을 눌러야 진행됩니다. AI가 잘못 판단해도 큰 사고로 이어지지 않게 하는 장치입니다.
05 — 역할 분담

누가 무엇을 맡나

지난 프로젝트처럼 개발은 한 사람이 맡되, 이번엔 팀원 세 분이 코드 없이도 결과물 품질에 직접 영향을 주는 역할을 맡습니다.

역할담당하는 일
전체 기획·개발 본인 에이전트 설계·구현, 화면 연결, 배포 전체
위험 시나리오 조사 메카트로닉스 2명 현장에서 실제로 어떤 상황이 위험한지, 어떤 신고에 어떤 대응이 적절한지 사례·시나리오 정리 — 전공 지식이 그대로 쓰입니다
테스트 및 검증 메카트로닉스 2명 완성된 에이전트를 직접 써보며 이상한 답변·놓친 상황을 찾아 리포트
발표자료 제작 컴공 2학년 피치덱, 데모 시연 대본
발표 당일 대응 논의 후 결정 발표, 질의응답
06 — 확장성 이야기는 이렇게

다 만들지 않고, 그림으로 보여줍니다

평가항목에 "구현 및 확장 가능성"(12점)이 있고, LMS 연결 같은 확장 그림도 중요합니다. 다만 2개월 안에 전부 실제로 만들지는 않습니다.

실제로 작동하게 만드는 것

번역 검수 에이전트, 위험 신고 대응 에이전트 — 데모에서 직접 눌러서 보여줄 수 있는 것

발표에서 "다음 계획"으로만 보여주는 것

현장 사진으로 위험 요소를 인식해 맞춤 퀴즈를 만드는 것 — 슬라이드 한 장이면 충분, P2·P3 로드맵을 그대로 근거로 사용

실제 구현 범위를 넓히면 완성도가 떨어지고 "AI 에이전트가 핵심"이라는 메시지가 흐려집니다. 그래서 범위를 의도적으로 좁힙니다.
