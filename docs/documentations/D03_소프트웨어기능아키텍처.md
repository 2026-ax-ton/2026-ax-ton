## 2. 기능 아키텍처

### 2.1 액터 목록

| 액터명 | 역할 | 참고 |
|---|---|---|
| 노동자 | 내 언어로 교육을 듣고 그림 문제를 풀며 위험을 익명으로 신고·질문한다 | 주 액터 (코드 `worker`) |
| 담당자 | 사업장·설비를 등록하고 교육을 만들어 발급하며 결과·증빙을 다룬다 | 주 액터 (코드 `admin`) |
| 운영자 | 안전 문구의 언어별 번역을 검수(승인·대기·중지)한다 | 주 액터 (코드 `operator`) |
| 브라우저 음성 서비스 | 글을 소리로 읽고(음성합성) 음성을 글로 받아쓴다 | 외부 시스템. 받아쓰기는 브라우저가 인식 서버를 부른다 |
| 호스팅·배포 서비스 (Vercel, GitHub) | 화면 파일을 배포하고 주소를 제공한다 | 외부 시스템 |
| AI 모델 서비스 | 번역·역번역·문제 초안·분석 요청을 처리한다 | 외부 시스템 · **후보** (T-09) |
| 감독기관 | 증빙 문서를 제출받는다 | 시스템 밖 수신자 (연동 없음) |

### 2.2 사용사례 다이어그램

그림 1. 사용사례 다이어그램 (텍스트 표기)

```
                    ┌───────────────────────── 시스템 경계 ─────────────────────────┐
 [노동자] ──────────┼─ T-04 수강과 이해도 검증                                       │
    │               ├─ T-05 현장 신고와 소통                                         │
    │               ├─ T-08 공통 기반 (다국어·접근성·오프라인)                        │
                    │                                                               │
 [담당자] ──────────┼─ T-01 사업장·설비 등록                                         │
    │               ├─ T-03 교육 생성·발급                                           │
    │               ├─ T-06 현황 파악과 개선 ◄── 노동자 결과 (T-04, T-05)             │
    │               ├─ T-07 교육 증빙 ─────────► [감독기관] (제출은 시스템 밖)        │
                    │                                                               │
 [운영자] ──────────┼─ T-02 안전 문구 검수 ──► 검수된 문구 ──► T-03                   │
                    │                                                               │
                    │  T-09 AI 에이전트 지원 (후보) ◄──► [AI 모델 서비스]             │
                    │     · 대상 화면: 운영자(T-02)·담당자(T-03, T-06)               │
                    │     · 결과는 항상 'waiting' → 사람이 판정                       │
                    └───────────────────────────────────────────────────────────────┘
 [브라우저 음성 서비스] ◄── T-04, T-05, T-08        [호스팅·배포 서비스] ◄── 전체 배포
```

흐름: **운영자 검수(T-02) → 담당자 교육 발급(T-03) → 노동자 수강·검증(T-04) → 담당자 대시보드·증빙(T-06, T-07) → 교육 수정(T-03)** 의 개선 루프.

| T-05 | 현장 신고와 소통 | 노동자, 담당자 | 위험 요소를 익명으로(음성 포함) 신고하고, 글·댓글로 질문하며, 담당자가 공식 답변을 단다 | ✅ 완료 (기능7·8) |
| T-06 | 현황 파악과 개선 | 담당자 | 언어×위험유형 정답률과 취약 항목을 보고 신고를 처리하며 재교육을 지시한다 | ✅ 완료 (기능6) |
| T-07 | 교육 증빙 | 담당자 | 교육 1건 또는 기간 묶음의 증빙을 대상자 전원 포함해 인쇄한다 | ✅ 완료 (기능5) |

## 3. 기타 요구사항

- **비기능 · 현장 환경** — 노동자 화면은 외부 요청 0건(예외 2: `sw.js` 동일 오리진 전달, 신고 화면 받아쓰기), 오프라인 동작, 터치 영역 60px, 문해력 비전제(음성 병행), 색만으로 상태 구분 금지.
- **비기능 · 보안·개인정보** — 신고자 식별값 저장 0, 외국인등록번호·여권번호 미수집, AI 키 브라우저 노출 금지, AI 출력은 `textContent` 로만 표시.
- **비기능 · 배포** — 빌드 없음, 의존성 0(`src/`), 배포마다 `sw.js` VERSION 상향.
- **제품 원칙** — [C05 §2](00_개발컨벤션/C05_개발규칙.md) 넘지 않는 선 21개 항목.
- **제약** — 데이터는 브라우저 저장소에 있어 기기·오리진마다 별개이다. 기기 간 공유는 서버 도입 후 가능하다(범위 밖, 후보).
- **범위 밖(하지 않는 것)** — 인사·평가용 점수 내보내기, 신고자 식별·"내가 낸 신고" 목록, 미이수자 필터·정렬, 노동자 개인 데이터 판매([C06 D-009](00_개발컨벤션/C06_결정기록.md)).
