### 3.2 핵심 알고리즘 명세

**[1] `phraseOk(p, lang)` @ `src/assets/store.js`**

| 항목 | 내용 |
|---|---|
| 목적 | 문구 `p`가 `lang` 노동자에게 안전 지시로 쓰일 수 있는지 판정한다 |
| 입력 | 문구 객체(전체 `status` + `translations[lang].status`), 언어 코드 |
| 출력 | 참/거짓 (참 = 해당 언어 판정이 완료 `reviewed`) |
| 왜 필요한가 | 한 언어의 오역이 다른 언어 노동자의 안전 지시를 지우지 않도록 **언어 단위**로 판정한다 |
| 주의 | 문구 전체와 언어별 판정이 다르면 **엄한 쪽**(중지 > 대기 > 완료)을 따른다. `p.status`를 직접 읽지 않는다 |

**[2] `qtext(q, lang, field)` @ `src/assets/store.js`**

| 항목 | 내용 |
|---|---|
| 목적 | 문항의 문구·선택지를 노동자 언어로 읽는다 |
| 입력 | 문항, 언어 코드, 필드명(문자열: `prompt` `why` / 배열: `options` `results` `pairs`) |
| 출력 | 해당 언어 텍스트. 번역이 없거나 빈 문자열이거나 **번역 배열 길이가 다르면(짝 문항은 모양이 다르면) 한국어 원문** |
| 왜 필요한가 | `answer`는 `options`의 **인덱스**여서, 번역 배열 길이가 다르면 정답이 다른 선택지를 가리켜 **틀린 작업을 맞다고 가르친다** |
| 주의 | 화면에서 `q.i18n`을 직접 뒤지지 않는다. 길이 검사는 이 함수 한 곳에만 둔다 |

**[3] `askedQuestion(course, quizRow, i)` @ `src/assets/store.js`**

| 항목 | 내용 |
|---|---|
| 목적 | `progress[].quiz.answers[i]`가 `course.quiz` 중 **어느 문항의 답인지** 찾는다 |
| 입력 | 교육, 풀이 기록, 답 위치 |
| 출력 | 그 문항 (기록에 `asked`가 있으면 그 id로, 없는 옛 기록은 자리로) |
| 왜 필요한가 | 문항을 내리면(retired) 그 뒤에 푼 사람의 답이 한 칸씩 밀린다 |

**[4] `UI.badgeText()` @ `src/assets/ui.js`**

| 항목 | 내용 |
|---|---|
| 목적 | 배지에서 글자 부분만 꺼낸다 (아이콘 제외) |
| 왜 필요한가 | 이전에는 "한글이 아니면 아이콘"으로 걸러서, 번역한 크메르어 배지가 소리에서 통째로 빠졌다 (9/28 수정) |
| 주의 | 배지 글자는 노동자의 언어다. 글자 종류로 아이콘을 가르지 않는다 |

**[5] `UI.speak()` 음성 판정 @ `src/assets/ui.js`**

| 항목 | 내용 |
|---|---|
| 목적 | 낭독을 시킨 뒤 **실제로 소리가 났는지** 신호로 판정하고 안 났으면 화면에 알린다 |
| 입력 | 낭독할 글, 언어 |
| 출력 | 소리 시작 여부. 안 났으면 버튼을 🔊→🔇 로 바꾸고 안내 |
| 왜 필요한가 | 카카오톡 인앱 브라우저처럼 음성 API가 있다고 답하고도 소리가 안 나는 환경이 있다. 크메르어 노동자에게는 빈 화면이 된다 |
| 주의 | 브라우저 이름(userAgent)으로 넘겨짚지 않는다. **사람이 눌러서 시킨 것만** 판정한다(저절로 읽는 소리는 브라우저가 막는다). 소리가 났는데 안 났다고 하는 것보다 안 났는데 났다고 하는 쪽이 위험해 약 2초 기준으로 두었다 |

**[6] 후보 · `translateWithSelfCheck()` (이름 가칭) @ `agent-*` — 에이전트 A**

| 항목 | 내용 |
|---|---|
| 목적 | 한국어 문구를 언어별로 번역하고, 역번역 대조로 뜻이 뒤집혔는지 스스로 확인하며, 안 풀리면 사람에게 올린다 |
| 입력 | 문구 id, 한국어 원문, 대상 언어 목록 |
| 출력 | 언어별 `{text, back, 대조 결과, 시도 횟수, 상태: ok \| 사람에게 올림}`. 저장은 항상 `waiting` |
| 왜 필요한가 | 번역·검수 수작업을 줄이되 검수 게이트는 유지한다 |
| 주의 | `reviewed`를 쓰지 않는다. 재시도 상한을 둔다. 출력은 형식 검증 후 `textContent`로만 표시. 실패 시 수동 입력 경로 유지. **구현 위치는 C06 D-006 결정 후 확정** |

### 3.3 DB 스키마 명세

해당 없음 — 이 시스템에는 데이터베이스가 없다. 근거: 서버가 없고 데이터는 브라우저 `localStorage` 10칸에 저장한다(기기·오리진마다 별개, 약 5MB 한계). 서버 도입 시 `Store`의 안쪽만 서버 호출로 바꾸는 것이 설계 의도이며, 도입 여부는 `미정`(C06 D-005).

**데이터 계약 (저장소 10칸)**

|---|---|---|---|---|

| 2 | `session` | 로그인한 사람 | 로그인 | 모든 화면(가드) |

**후보 설계안 (D-005/D-006 결정 후 확정) — A안: 브라우저가 단계를 지휘**

|---|---|---|---|

## 5. 기타 구현 참고 사항

| # | 제약 | 어기면 |
|---|---|---|
| 1 | 문구는 `Store.phraseOk()`로만 판정한다 | 한 언어 오역 때문에 다른 언어 노동자가 안전 지시를 잃는다 |
| 2 | 문항 문구는 `Store.qtext()`로만 읽는다 | 정답이 다른 선택지를 가리킨다 |
| 3 | 새 문구·AI 결과는 `waiting`으로만 저장한다 | 검수를 거치지 않은 문장이 안전 지시가 된다 |
| 4 | `innerHTML`을 쓰지 않는다 (AI 출력 포함) | 설비 이름·AI 출력 한 줄로 화면이 깨지거나 스크립트가 실행된다 |
| 5 | 노동자 화면은 외부 요청 0건 | 현장 인터넷이 약할 때 교육이 끊긴다 |
| 6 | 배포마다 `sw.js`의 `VERSION`을 올린다 | 고쳤는데 옛 화면이 그대로 남는다 |
| 7 | `main`을 먼저 push한다 | 배포가 건너뛰어져 주소가 옛날 것으로 남는다 |
| 8 | 신고에 식별값을 저장하지 않는다 | 익명이 깨져 신고가 멈춘다 |
| 9 | 발급된 교육의 문항 순서·정답 번호를 바꾸지 않는다 | 옛 기록이 다른 선택지를 가리킨다 |
| 10 | 테스트에 작업자 PC의 절대 경로가 박혀 있다 (현재) | 다른 PC에서 테스트가 전부 실패한다 → TK-1-06 |
| 11 | 문서(`docs/12`)가 `Review.compare()` 를 말하지만 코드에는 없다 (`negationFlipped` 등만 있음) | 에이전트 설계가 없는 함수를 전제하게 된다 → 설계 시 실제 함수를 쓰거나 래퍼를 새로 정의한다 |
