## 2. 넘지 않는 선 (절대 규칙)

> 어기면 **제품의 전제가 무너진다.** 바꿔야 할 것 같으면 코드를 고치기 전에 [C06](C06_결정기록.md)에 사유를 쓰고 팀과 상의한다.

### 2.1 제품 원칙 (사람·데이터를 지키는 선)

| # | 선 | 왜 | 어디서 지켜지나 |
|---|---|---|---|
| P-1 | **검수 완료(`reviewed`) 문구만** 안전 지시로 쓴다 | 오역이 곧 사고 | `Store.phraseOk()` · 자동 테스트 |
| P-2 | 새 문구·AI 결과는 **항상 `waiting`** 으로만 들어간다 | 검수 없는 자동 번역은 오역이 안전 지시가 된다 | 폼·에이전트 경로 |
| P-3 | 위험 신고는 **익명** — 신고자를 알 수 있는 값을 저장하지 않는다 | 익명이 깨지면 신고가 멈춘다 | `Store.reports` 구조 |
| P-4 | **미이수·미통과를 숨기지 않는다** (필터·정렬로도) | 숨길 수 있는 증빙은 증빙이 아니다 | 증빙 화면 |
| P-5 | **인사·평가용 내보내기/줄 세우기를 만들지 않는다** (AI 계산 포함) | 감시 도구가 되는 순간 현장이 등을 돌린다 | 기능 설계 |
| P-6 | 미통과는 **교육의 실패**로 본다 (원인 가설은 번역·문항·교육을 먼저) | 노동자 탓이 아니다 | 문구·분석 |
| P-7 | **"면책" 표현 금지** | 증빙은 실시 기록일 뿐 법적 책임을 대신하지 않는다 | 모든 문장 (AI 출력 포함) |
| P-8 | **외국인등록번호·여권번호를 받지 않는다** | 사업장 내 식별번호로 충분 | 입력 폼 |
| P-9 | **그 언어 음성이 없으면 한국어로 대신 읽지 않는다.** 소리를 내지 않고 이유를 그 사람 언어로 적는다 | 뜻이 안 닿는 소리를 사람은 "들었다"고 믿는다 | `UI.voiceSilent` |

## 3. 폴더와 이름 규칙

### 3.1 폴더

```
2026-ax-ton/                      저장소 루트
├── CLAUDE.md                     AI(Claude Code)와 사람이 함께 읽는 규칙 원본
├── docs/                         문서 (배포되지 않음)
│   ├── documentations/           ★ D01~D08 + 00_개발컨벤션 (이 문서 세트)
│   └── devlog/                   개발일지
├── tests/                        자동 테스트 (배포되지 않음)
└── src/                          ★ 배포되는 코드. 이 폴더만 고친다
    ├── index.html signup.html    로그인·가입
    ├── sw.js                     오프라인 도우미 (배포 루트에 있어야 한다)
    ├── assets/                   공용 — 모든 화면이 쓴다 (고치면 전체 테스트 필수)
    ├── worker/                   노동자 화면 6개 (+ worker.css)
    ├── admin/                    담당자·운영자 화면 5개 (+ admin.css)
    └── (후보) /api               서버리스 함수 — 해커톤에서 처음 도입 검토 (C06 D-005)
```

> **1화면 = HTML 1개 + JS 1개.** 고칠 때 열 파일이 딱 둘이고, 같은 파일을 두 사람이 열지 않는다.
> 서버 코드가 생기면 `src/`와 **분리된 자리**에 두고, `src/`는 계속 의존성 0을 유지한다.

## 4. 코드 규칙 요약

```js
// ✅ 이렇게
var el = UI.el('div', 'card', 설비.name);       // 안전한 요소 만들기
var ok = Store.phraseOk(문구, '크메르어코드');    // 검수 판정은 이 통로로만
Store.progress.update(function (list) { list.push(row); });  // 읽고→고치고→저장

// ❌ 이렇게 하지 않는다
div.innerHTML = 설비.name;                     // 금지 (T-2)
if (문구.status === 'reviewed') { ... }         // 언어별 판정 무시 → 안전 지시 오류
localStorage.setItem('courses', ...);          // 금지 (T-4)
```

**읽는 통로를 하나로 모은다.** 데이터의 모양이 미묘한 곳은 함수 한 곳으로만 읽는다.

| 읽고 싶은 것 | 반드시 쓰는 통로 |
|---|---|
| 문구가 이 언어에서 안전 지시로 쓸 수 있나 | `Store.phraseOk(p, lang)` |
| 문항 문구·선택지 | `Store.qtext(q, lang, field)` |
| 답이 어느 문항의 것인가 | `Store.askedQuestion(course, quizRow, i)` |
| 교육 기한 배지 | `UI.dueBadge(dueAt)` |
| 배지 글자 꺼내기 | `UI.badgeText()` (한글 여부로 아이콘을 가르지 않는다) |
| 화면 글자 | `I18N.t(키, 언어)` |

**데이터 모양을 바꿔야 한다면**: ① `store.js` 주석(계약서)부터 고친다 → ② 그 키를 읽는 화면을 모두 연다 → ③ 읽는 통로를 함수 하나로 모은다 → ④ 테스트를 돌리고 망가뜨려 본다.

## 5. git 규칙

### 5.1 브랜치

```
main              배포 전용 · 보호됨 (삭제·강제 덮어쓰기 금지, PR 필수)
 ▲ 배포할 때만 --ff-only
develop           기준(통합) 브랜치 · GitHub 기본 브랜치
 ▲ PR로 머지
feat/agent-*      ★ 해커톤 AI Agent 작업  (예: feat/agent-translate)
                  (이미 `feat/agent-plan` 브랜치가 있다 — 계획 문서용. 에이전트 코드는 주제 공지 전 금지)
feature/byeonsoyun  기존 작업용 (그대로 둔다)
```

- 태그 `v1.0-ideathon` = 아이디어톤 제출 시점. 지우지 않는다.
- `feature/yesool` (Next.js+Supabase 별개 구현) 등 옛 브랜치는 **지우지 않는다** — 서버가 필요할 때 참고할 실물이다.
- **`main`에는 `src/`가 바뀐 커밋만** 올린다. 문서만 고친 커밋은 `develop`에 둔다.

### 5.2 커밋 메시지

`태그: 한글로, 무엇을 했는지`

| 태그 | 언제 |
|---|---|
| `feat:` | 새 기능 |
| `fix:` | 버그 수정 |
| `docs:` | 문서 |
| `style:` | 화면 간격 등 로직 변경 없음 |
| `refactor:` | 기능 변경 없이 구조 개선 |
| `test:` | 테스트 추가·수정 |
| `chore:` | 설정·데이터 등 |

예) `feat: 번역 에이전트가 역번역 대조 후 재시도하게 한다` · `docs: D04 프로덕트 백로그 초안 작성`

### 5.3 PR (해커톤 작업은 혼자여도 PR을 쓴다)

심사에서 "어떻게 만들었나"의 증거가 되고, **코드를 못 읽는 팀원도 PR 본문은 읽는다.**

```
## 무엇을 했나 (한 문장)
## 왜 (어떤 스토리 US-nn / 태스크 TK-n-nn)
## 어떻게 확인했나 (화면에서 직접 + 테스트 결과 X건 통과)
## 넘지 않는 선을 어기지 않았나 (C05 §2 체크)
## 남은 것 / 알려진 한계
```

### 5.4 배포 (`main`에 올라가면 자동 배포된다)

1. `src/sw.js`의 **`VERSION`을 올린다** (안 올리면 옛 화면이 남아 "고쳤는데 안 고쳐진" 것처럼 보인다)
2. 전체 테스트 통과 확인
3. `develop → main`을 `--ff-only`로 넘긴다
4. **push 순서: `main` 먼저**, 그다음 `develop` (뒤집으면 Vercel이 배포를 건너뛴다)
5. **배포 주소를 실제로 열어서 확인한다** — push 성공 ≠ 배포 성공
   (`total_count`가 0이면 캐시가 아니라 연결 문제)

> 금지: `git push --force`, `git reset --hard`, `--no-verify`, `main`에 작업 커밋 직접 올리기 (명시적 요청이 없는 한)

## 7. 테스트 규칙

| 규칙 | 내용 |
|---|---|
| **망가뜨려 보기** | 테스트를 쓴 뒤 **일부러 코드를 망가뜨려** 테스트가 잡는지 확인한다. 안 잡히면 그 테스트는 가짜다. |
| **비정상 케이스 필수** | 빈 값·너무 긴 값·번역 배열 길이 불일치·네트워크 실패 |
| **내용이 아니라 경계** (AI) | AI 응답은 매번 다르므로 **내용**이 아니라 **"넘으면 안 되는 선을 지키는가"** 를 검사한다. 가짜 응답(고정 JSON)을 먹여 *"이 응답이 왔을 때 우리 코드가 무엇을 하는가"* 를 본다. |
| **글자를 박지 않는다** | 한국어 문구를 테스트에 직접 박지 않는다 → `I18N.t(키, 언어)`로 비교 (번역을 고칠 때마다 깨지는 테스트는 번역을 막는다) |
| **공용 파일을 고치면 전체** | `src/assets/`를 고쳤으면 반드시 전체 실행 |
| **실행** | `jsdom`은 저장소 밖에 설치 (`src/` 의존성 0 유지). `NODE_PATH=~/jsdom-box/node_modules node tests/run-all.js` |

### 7.1 에이전트(후보)용 경계 테스트 목록

| 지킬 선 | 검사 |
|---|---|
| 에이전트 경로가 `reviewed`를 쓰지 못한다 | 가짜 응답을 넣고 저장된 status가 `waiting`인지 |
| AI 실패 시 기존 화면이 그대로 나온다 | 응답을 실패로 만들고 수동 입력 칸이 살아 있는지 |
| AI 출력이 `innerHTML`로 들어가지 않는다 | `<script>`·태그가 섞인 응답을 넣고 텍스트로만 나오는지 |
| 노동자 화면 6개 외부 주소 0건 | 기존 검사 유지 |

## 8. AI 에이전트 개발 규칙 (해커톤 · `후보`)

> 에이전트 코드는 해커톤 **주제·평가표 공지 후** 작성한다 (확정, C06 D-003). 아래는 그때 지킬 규칙이다.

| # | 규칙 | 풀이 |
|---|---|---|
| A-1 | **사람이 마지막 승인** | 에이전트 산출물은 `status:'waiting'`. 판정 버튼은 사람이 누른다. |
| A-2 | **실패하면 지금의 화면** | AI 호출 실패·지연·차단 시 기존 수동 입력 경로가 그대로 있다. 버튼을 조용히 없애지 않는다 (사람은 고장으로 읽는다). |
| A-3 | **노동자 폰은 AI를 부르지 않는다** | AI 호출은 담당자·운영자 화면(사무실)에서만. 결과는 `Store` 데이터로만 노동자에게 도착한다. |
| A-4 | **키는 서버에만** | 호출은 서버리스 함수(`/api/*`)를 거치고, 키는 호스팅 환경변수에 둔다. 브라우저·저장소·문서에 키를 쓰지 않는다. |
| A-5 | **출력은 신뢰하지 않는다** | 응답 JSON 형식을 검증하고, 화면에는 `textContent`로만 넣는다. |
| A-6 | **루프에는 상한이 있다** | 재시도 횟수(예: 2~3회)·시간·비용 상한을 코드에 둔다. 상한을 넘으면 `사람에게 올림`. |
| A-7 | **판단 근거를 남긴다** | 몇 번 시도했고, 역번역 대조 결과가 무엇이었는지 사람이 볼 수 있게 저장한다. |
| A-8 | **개인 식별 정보를 보내지 않는다** | 이름·식별번호를 제거하고 문구·집계만 보낸다. 신고자는 애초에 저장하지 않는다(P-3). |
| A-9 | **프롬프트는 파일로 관리한다** | 코드 속 문자열로 흩어놓지 않고 한곳에 모아 이력을 남긴다. 프롬프트를 바꾸면 PR에 이유를 쓴다. |
| A-10 | **AI가 만든 문장도 규칙을 지킨다** | "면책" 금지(P-7), 미통과를 노동자 탓으로 쓰지 않기(P-6) |
