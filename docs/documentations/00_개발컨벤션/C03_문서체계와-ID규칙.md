## 3. 같은 내용은 한 곳에만 쓴다 (단일 출처)

같은 사실을 두 곳에 쓰면 **언젠가 한쪽이 틀린 말**이 된다. 그래서 사실마다 **정답이 사는 곳**을 정한다.
나머지는 **링크로 가리킨다.**

| 사실 | 정답이 사는 곳 | 다른 곳에서는 |
|---|---|---|
| 지금 해야 할 일 / 현재 상태 | **C01 §7** | "C01 참조" 링크 |
| 용어 정의 | **C02** | 링크 |
| 요구사항(스토리) | **D04 §2.2** | D05는 **옮겨 적되** 원본은 D04 |
| 태스크 목록 | **D05 §3.1** | D06은 완료%만 추가. **어긋나면 D05가 맞다** |
| 테스트 결과 숫자 | **D07 §6** | C01·D08은 D07 숫자를 인용 |
| 코드 규칙 | **C05** (원본은 저장소 `CLAUDE.md`) | 링크 |
| 결정과 이유 | **C06** | 링크 |
| 수익 모델(고객·가격·추정 수익) | **S01** | D01은 한 줄 요약 + 링크 |
| 발표·문서에 쓰는 숫자와 출처 | **S02** (`N-nn`) | 다른 문서는 `N-nn`으로 인용. 대장에 없는 숫자는 쓰지 않는다 |
| 기능의 상세 동작 | 저장소 `docs/08-overview.md`, `09-handover.md` | D 문서는 요약 + 링크 |
| 카테고리별 요약·색인 (새 세션 입구) | 원본은 위 각 문서. **`docs/infos/`** 는 요약만 둔다 | 원본을 고친 뒤 infos의 해당 md를 고치고 `node docs/infos/_build.js`로 html을 다시 만든다 |
| 일정 | **D02 §4 / D05 스프린트 구분표** | C01 §8은 요약본 |

> **저장소 기존 문서(`docs/00~12`)와의 관계** — 기존 문서는 *개발 중 쌓인 기술 기록*이고, 이 폴더는 *체계화된 공식 산출물*이다.
> 겹치는 부분은 **이 폴더가 요약·색인**, 기존 문서가 **세부 원본**을 맡는다. 서로 다르면 **기존 `07-next-tasks.md`(진행 상태)와 `CLAUDE.md`(규칙)** 가 코드에 더 가깝다 — 발견 즉시 고친다.

| 내용 추가·수정 | **부** +1 | 1.0 → 1.1 |
| 구조·범위가 바뀜 (기능 추가·삭제) | **주** +1 | 1.x → 2.0 |
| 초안(검토 전) | 0.x | 0.1 → 0.2 |

> 이 문서 세트는 **프로토타입이므로 모두 0.1** 로 시작한다. 비개발 팀원 검토를 거쳐 문서마다 1.0으로 올린다.

## 8. 문서를 고칠 때의 순서


**영향받는 문서 확인표** — 위에서 바뀌면 아래도 확인한다.

| 바뀐 것 | 함께 확인할 문서 |
|---|---|
| 기능이 추가/삭제 | D03 → D04 → D05 → D06 → D07 (사슬을 따라 내려감) |
| 일정 변경 | D02 §4, D05 스프린트 구분표, C01 §8 |
| 결정이 바뀜 | C06에 새 결정 추가(옛 결정은 "대체됨"으로 표시), 영향받는 C·D 문서 |
| 테스트 숫자 변경 | D07 §6, C01 §4.2, D08 |
| 용어 변경 | C02, 그 용어를 쓰는 모든 문서 |
| 수익 모델·가격 변경 | S01, D01 비용 부담 줄, C06 D-010 |
| 숫자를 새로 쓰거나 판정이 바뀜 | S02 먼저, 그 `N-nn`을 인용한 문서 (S01, D01, D08, 발표 자료) |
