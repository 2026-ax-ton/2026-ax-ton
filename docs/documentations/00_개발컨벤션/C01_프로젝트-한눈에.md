## 2. 왜 만드는가 (문제 → 해결)

```
 현재의 안전교육                              우리가 만드는 것
 ────────────────                            ──────────────────────
 한국어로 설명 → 출석부 서명 → "교육 완료"     내 언어 음성으로 수강 → 그림 문제로 이해 확인
                                              → 통과해야 "완료" → 증빙 자동 생성
 ↓                                           ↓
 이해 못 해도 서명은 됨                        이해했는지가 기록으로 남음
 사고 나면 "교육했다"는 서명만 남음             못 알아듣는 부분이 대시보드에 드러나 교육을 고침
```

**핵심 원칙 한 문장** — *이해했는지 확인되지 않으면 교육이 끝나지 않는 시스템.*

| 사용자 | 누구 | 하는 일 | 화면 색 |

| **노동자** | 외국인 제조업 노동자 (6개 언어: 크메르어·인도네시아어·베트남어·네팔어·태국어·한국어) | 교육 듣기 → 그림 문제 풀기 → 위험 신고·질문 | 코랄(빨강 계열) |

## 5. 해커톤에서 무엇을 하나

### 5.1 큰 그림

> 아이디어톤 자체 평가에서 **가장 약하다고 스스로 적은 칸**: *"제품 안의 AI가 아직 실제로 돌지 않는다."*
> 해커톤은 **정확히 그 칸을 메우는** 자리다.

### 5.2 AI Agent 후보 3개 — 전부 `후보`

| 후보 | 이름 | 한 줄 설명 | 쓰는 사람 |
|---|---|---|---|
| **A** | 번역·검수 에이전트 | AI가 번역 → 다시 한국어로 역번역 → 스스로 비교 → 어긋나면 재시도 → 안 되면 **사람에게 넘김** | 운영자 |
| **B** | 문항 출제 에이전트 | 검수된 문구와 설비 그림을 보고 **그림 문제 초안**을 만들어 줌 | 담당자 |
| **C** | 현장 신호 에이전트 | 오답·신고 데이터를 읽고 **"왜 못 알아듣는지" 가설**과 재교육 지시 초안을 제안 | 담당자 |

**모든 후보에 공통인 약속** — AI는 **초안과 제안**까지만 한다. **승인은 사람이 한다.**
AI가 실패하면 **기존의 손으로 하는 방법이 그대로 남아 있다.**

### 5.3 무엇을 만들지 정하는 조건

| 필요한 정보 | 상태 | 언제 |
|---|---|---|
| 해커톤 **공식 주제** | ❓ 공지 대기 | 미정 |
| **평가표** (배점) | ❓ 공지 대기 (지금은 아이디어톤 평가표를 임시 기준으로 사용) | 미정 |
| A·B·C 중 무엇을 만들지 | ❓ 위 두 가지를 보고 결정 | 공지 후 |
| 서버 기능(`/api`) 도입 | ❓ 배포 설정 변경 승인 필요 | 결정 필요 |

> **공지 전에는 에이전트 코드를 쓰지 않는다.** (지금 쓰면 주제가 나온 뒤 다시 써야 할 가능성이 높다)
> 대신 **지금은 문서 체계·기반 설계·사람이 해야 하는 확인**을 한다. ← **현재 단계**

## 6. 멘토링에서 나온 것 (2026-10-10, 1차)

| 항목 | 멘토 의견 | 우리가 할 일 |
|---|---|---|
| 아이템 | 나쁘지 않음. 해결하는 사회 문제와 명분이 명확함 → **열심히 하라** | — |
| 향후 고려 | 교육→사고 감소는 맞지만, **실제로 해결하는 크기가 보잘것없다면 가치가 없다** | 효과의 크기를 숫자로 설명할 준비 |
| **고객** | 실제 사용자(이주노동자)는 **돈이 나올 수 없는 사람**. 돈을 쓸 사람은 **기관·공무원·정부·지자체** | 누가 돈을 내는지 정리 ([D01](../D01_시스템정의서.md) 반영) |
| 수익 | 정부/지자체 지원이 필요. **돈을 만들 수 있는 모든 고객을 세부적으로 고민**, 가격 정책 고려. 발표 때 **추정 수익도 상상해서 써야 함** | 수익 모델 초안 작성 ⬜ |
| 시장조사 | 따로 안 해도 되나, **정리된 수치가 실제인지 환각인지 검증은 명확히** | 발표에 쓰는 숫자 **출처 검증** ⬜ |
| 아이디어 | 이주노동자 데이터 판매 / 송금 수수료 | ⚠️ 아래 주의 참고 |

> ⚠️ **데이터 판매 아이디어는 우리 제품 원칙과 충돌한다.** 우리는 *"익명 제보 보호 · 인사평가용 내보내기 금지 · 외국인등록번호를 받지 않음"* 을 약속했다.
> 이주노동자 개인 데이터를 파는 것은 이 원칙과 개인정보 보호 관점에서 맞지 않는다. **아이디어로 기록은 하되 채택 여부는 팀이 결정**한다 → [C06 결정 D-009](C06_결정기록.md).
