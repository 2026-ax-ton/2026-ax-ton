## 2. 왜 만드는가 (문제 → 해결)

```
 현재의 안전교육                              우리가 만드는 것
 ────────────────                            ──────────────────────
 한국어로 설명 → 출석부 서명 → "교육 완료"     내 언어 음성으로 수강 → 그림 문제로 이해 확인
                                              → 통과해야 "완료" → 증빙 자동 생성
 ↓                                           ↓
 이해 못 해도 서명은 됨                        이해했는지가 기록으로 남음
 사고 나면 "교육했다"는 서명만 남음             못 알아듣는 부분이 대시보드에 드러나 교육을 고침
```

**핵심 원칙 한 문장** — *이해했는지 확인되지 않으면 교육이 끝나지 않는 시스템.*

> 아이디어톤 자체 평가에서 **가장 약하다고 스스로 적은 칸**: *"제품 안의 AI가 아직 실제로 돌지 않는다."*
> 해커톤은 **정확히 그 칸을 메우는** 자리다.

### 5.2 AI Agent 후보 3개 — 전부 `후보`

| 후보 | 이름 | 한 줄 설명 | 쓰는 사람 |
|---|---|---|---|
| **A** | 번역·검수 에이전트 | AI가 번역 → 다시 한국어로 역번역 → 스스로 비교 → 어긋나면 재시도 → 안 되면 **사람에게 넘김** | 운영자 |
| **B** | 문항 출제 에이전트 | 검수된 문구와 설비 그림을 보고 **그림 문제 초안**을 만들어 줌 | 담당자 |
| **C** | 현장 신호 에이전트 | 오답·신고 데이터를 읽고 **"왜 못 알아듣는지" 가설**과 재교육 지시 초안을 제안 | 담당자 |

**모든 후보에 공통인 약속** — AI는 **초안과 제안**까지만 한다. **승인은 사람이 한다.**
AI가 실패하면 **기존의 손으로 하는 방법이 그대로 남아 있다.**
