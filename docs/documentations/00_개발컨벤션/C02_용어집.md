## 1. 우리 서비스의 말 (도메인 용어)

| 용어 | 비전공자 설명 | 개발자 메모 |
|---|---|---|
| **이해도 검증** | 교육을 들은 뒤, 정말 이해했는지 **그림 문제로 확인**하는 단계. 우리 제품의 심장. 통과해야 "교육 완료"가 된다. | 기능4 · `worker/quiz` · `progress[].quiz` |
| **증빙** | 교육을 실시했고 노동자가 이해했음을 보여주는 **제출용 문서**(인쇄). | 기능5 · `admin/proof`. "면책" 표현 금지 |
| **안전 문구** | 교육에 쓰이는 **안전 지시 한 문장** (예: "환기팬이 돌지 않으면 작업을 멈춘다"). | `Store.library` 항목 |
| **라이브러리** | 안전 문구를 모아 둔 **창고**. 검수 끝난 문구만 교육에 쓸 수 있다. | 기능9 · `admin/library` |
| **검수** | 번역이 **뜻이 맞는지 사람이 확인**하는 일. | 상태: 승인(reviewed) · 대기(waiting) · 중지(stopped) |
| **역번역** | 번역문을 **다시 한국어로 옮겨** 원문과 비교하는 검산 방법. 뜻이 뒤집혔는지 알 수 있다. | `assets/review.js` |
| **뜻이 뒤집힘** | 번역하다가 "~하지 마라"가 "~해라"로 **정반대가 되는 것**. 안전교육에서 가장 위험한 오류. | `negationFlipped()` 가 탐지 |
| **검수 게이트** | 검수를 통과해야 **다음 단계로 넘어가는 관문**. AI가 번역을 해도 이 관문은 없애지 않는다. | 핵심 설계 원칙 |
| **교육(코스)** | 안전 문구 여러 개 + 문제 여러 개를 묶어 **한 번에 발급하는 단위**. | `Store.courses` |
| **문항** | 이해도 검증의 **문제 1개**. 3유형: 위험 지점 누르기 / 고르기 / 짝 맞추기. | `quiz[]` |
| **hotspot (핫스팟)** | 설비 그림에서 **위험한 곳을 손가락으로 짚는** 문제 유형. | 좌표는 `assets/diagrams.js` |
| **취약 항목** | 많이 틀리는 문제·위험 유형. 교육을 고쳐야 할 곳. | 기능6 대시보드 |
| **재교육 지시** | 담당자가 노동자에게 **다시 교육하라고 내리는 지시**. | `Store.orders` |
| **익명 신고** | 노동자가 위험 요소를 **누가 했는지 알 수 없게** 알리는 기능. 익명이 깨지면 신고가 멈춘다. | `Store.reports` 에 식별값을 넣지 않음 |
| **담당자** | 사업장의 안전 담당자(생산팀장 겸직). 교육을 만들고 결과를 본다. | 역할 `admin` |
| **주무관** | 지자체에서 사업을 맡는 실무 공무원. 산재 예방 예산 집행·실적이 KPI다. 문서·발표에서 "지자체 담당자" 대신 쓴다 (2차 창업 멘토링). | 지불 고객 ([S08](../../infos/05_멘토링/2026-10-24_사업2차/S08_창업멘토링2차-결과-2026-10-24.md)) |
| **Risk Management Manager** | 기업의 위험관리 담당자. 사업장 「담당자」 중 돈을 쓰는 결정에 관여하는 사람을 가리킬 때 쓴다. 최종 결재는 사장(최종 의사결정권자)일 수 있다. | 지불 고객 |
| **운영자** | 번역 검수를 맡는 사람. 여러 사업장을 가로질러 본다. | 역할 `operator` |
| **노동자** | 교육을 듣는 외국인 노동자. | 역할 `worker` |
| **미통과** | 이해도 검증을 통과하지 못함. **노동자의 실패가 아니라 교육의 실패**로 본다. | 숨기지 않는다 |
| **중대재해처벌법** | 사고가 나면 경영 책임자를 처벌하는 법. 50인 미만 사업장까지 확대되어 **사업주가 증빙을 원하게 된 배경**. | 사업 배경 |

## 2. 화면·기능의 이름

> 코드에서는 "기능1~9"로 부른다. 화면 이름과 짝지어 외워 두면 편하다.

| 기능 | 화면 | 누가 | 한 줄 설명 |
|---|---|---|---|
| 기능1 | 사업장·설비 등록 (`admin/setup`) | 담당자 | 우리 공장의 설비·공정·노동자·사용 언어를 입력 |
| 기능2 | 교육 만들기 (`admin/content`) | 담당자 | 문구 고르기 + 문제 만들기 + 발급 + QR |
| 기능3 | 안전교육 수강 (`worker/learn`) | 노동자 | 내 언어 음성으로 안전 문구를 한 장씩 |
| 기능4 | 이해도 검증 (`worker/quiz`) | 노동자 | 그림 문제 풀기 |
| 기능5 | 교육 증빙 (`admin/proof`) | 담당자 | 제출용 문서 인쇄 |
| 기능6 | 대시보드 (`admin/dashboard`) | 담당자 | 어느 언어가 무엇을 못 알아듣는지 + 재교육 지시 |
| 기능7 | 현장 소통 (`worker/talk`) | 노동자 | 질문·글쓰기, 담당자 공식 답변 |
| 기능8 | 위험요소 신고 (`worker/report`) | 노동자 | 익명 신고 |
| 기능9 | 안전 문구 라이브러리 (`admin/library`) | 운영자 | 번역 검수 |
| — | 홈 (`worker/home`) · 마이 (`worker/my`) | 노동자 | 오늘의 문구·메뉴 / 내 기록·설정 |

## 3. 개발 일반 용어

### 3.1 구조

| 용어 | 비전공자 설명 | 우리 프로젝트에서는 |
|---|---|---|
| **프론트엔드** | 사용자가 **눈으로 보고 누르는 화면** 쪽. | `src/` 의 HTML·CSS·JS 전부 |
| **백엔드 / 서버** | 화면 뒤에서 **데이터를 보관하고 계산하는** 쪽. 식당의 주방. | **아직 없음.** 해커톤에서 처음 도입 검토 |
| **API** | 화면과 서버가 **주고받는 약속된 창구**. 식당의 주문서 양식. | 후보: `/api/translate` 등 |
| **서버리스 함수** | 서버를 직접 운영하지 않고, **필요할 때만 잠깐 켜지는 작은 서버 코드**. | Vercel `/api/*` — 저장소 루트 `api/` (확정, D-005·D-023) |
| 🆕 **DB (Neon Postgres)** | 데이터를 모아 두는 서버 쪽 큰 저장소. Neon은 Postgres를 빌려 주는 서비스 | 싱가포르 리전, Vercel Marketplace로 연결 (D-023) |
| 🆕 **서버 모드 / 로컬 모드** | 서버 모드 = 데이터를 서버에 저장해 여러 기기가 함께 본다. 로컬 모드 = 그 기기 안에만 저장 | https + 로그인이면 서버 모드, `file://`(현장 시연)이면 로컬 모드 ([A02 §14.5](../20_기술명세/A02_기술-개발-명세서.md)) |
| 🆕 **가입 코드** | 담당자가 받는 우리 공장 전용 번호. 노동자는 이 번호로 가입한다 | `workplaces.join_code` |
| 🆕 **보낼 대기열 (outbox)** | 인터넷이 끊긴 동안 저장한 것을 모아 두었다가 다시 연결되면 보내는 목록 | `safety.outbox.v1` |
| 🆕 **토큰** | 로그인했다는 증표. 요청마다 함께 보낸다. 시간이 지나면 만료된다 | 12시간, `sessionStorage` (탭 닫으면 로그아웃) |
| **데이터베이스(DB)** | 데이터를 오래 안전하게 **보관하는 창고**. | 없음. 지금은 브라우저 저장소 |
| **localStorage** | 브라우저 안의 **작은 보관함**(약 5MB). 기기·브라우저마다 따로. | 데이터 10칸을 여기에 저장 |
| **Store** | 우리 코드에서 **데이터를 읽고 쓰는 유일한 통로**. | `src/assets/store.js` |
| **의존성** | 다른 사람이 만든 **부품(라이브러리)**. 쓰면 편하지만 고장 원인이 늘어난다. | `src/` 는 **0개** |
| **빌드** | 코드를 **배포용으로 가공**하는 단계. | 없음 (파일 그대로 배포) |
| **Service Worker** | 브라우저에 심는 **도우미**. 화면 파일을 저장해 **인터넷이 끊겨도 열리게** 한다. | `src/sw.js` |
| **오프라인** | 인터넷이 없는 상태. 우리 노동자 화면은 오프라인이 전제. | E1 완료 |
| **외부 요청 0건** | 화면이 **다른 서버를 부르지 않는 것**. 현장 인터넷이 약해도 안 깨진다. | 노동자 화면 규칙 |
| **QR** | 폰 카메라로 찍으면 **주소가 열리는 네모 무늬**. 설비 앞에 붙인다. | `assets/qr.js` (직접 구현) |
| **i18n (다국어)** | 화면 글자를 **여러 언어로 바꾸는** 기능. i18n = internationalization. | `assets/i18n.js` |
| **TTS (음성합성)** | 글을 **소리 내어 읽어 주는** 기능. | 브라우저 내장 `speechSynthesis` |

### 3.2 배포·버전 관리

| 용어 | 비전공자 설명 | 우리 프로젝트에서는 |
|---|---|---|
| **git / GitHub** | 코드의 **변경 이력을 기록**하고 여럿이 나눠 쓰는 도구 / 그 서비스. 문서의 "변경 내용 추적"과 같다. | 조직 `2026-ax-ton` |
| **저장소(리포지토리)** | 프로젝트 **파일 전체와 이력**이 담긴 폴더. | `2026-ax-ton/2026-ax-ton` |
| **커밋(commit)** | 변경을 **한 덩어리로 저장**하는 것. 저장 시점마다 메모를 남긴다. | 메시지 규칙: [C05 §5](C05_개발규칙.md) |
| **브랜치(branch)** | 본 줄기에서 **갈라져 나온 작업용 가지**. 실험이 본 줄기를 망치지 않게 한다. | `main` · `develop` · `feat/agent-*` |
| **PR (Pull Request)** | "내 가지의 작업을 본 줄기에 합쳐도 될까요?" 하는 **합치기 요청서**. 본문에 무엇을 왜 했는지 적는다. | 해커톤 작업은 PR 사용 |
| **머지(merge)** | 가지의 작업을 **본 줄기에 합치는 것**. | |
| **태그(tag)** | 특정 시점에 붙이는 **이름표**. | `v1.0-ideathon` = 아이디어톤 제출 시점 |
| **배포(deploy)** | 만든 것을 **인터넷 주소에 올려 누구나 쓰게** 하는 것. | Vercel, `main` 에 올리면 자동 |
| **Vercel** | 웹사이트를 올려 주는 **호스팅 서비스**. | https://2026-ax-ton.vercel.app |
| **환경변수** | 코드 밖에 두는 **비밀 설정값** (예: AI 열쇠). 코드에 직접 쓰면 유출된다. | Vercel 설정에 보관 (후보) |
| **API 키** | 외부 서비스(AI 등)를 쓰는 **비밀 열쇠**. 유출되면 남이 내 요금으로 쓴다. | 브라우저 코드에 절대 두지 않음 |

## 4. AI·에이전트 용어

| 용어 | 비전공자 설명 | 우리 프로젝트에서는 |
|---|---|---|
| **LLM (거대 언어 모델)** | 글을 읽고 쓰는 AI. Claude 같은 것. | 후보: Claude API |
| **프롬프트** | AI에게 주는 **지시문**. | 에이전트 단계마다 하나 |
| **환각(hallucination)** | AI가 **그럴듯하지만 사실이 아닌 말**을 지어내는 것. | 번역·수치에서 가장 경계 |
| **챗봇 vs 에이전트** | 챗봇: 한 번 묻고 한 번 답함. **에이전트: 목표를 받으면 여러 단계를 스스로 밟고, 결과를 확인해 틀리면 다시 시도**함. | |
| **도구(tool)** | 에이전트가 **호출할 수 있는 기능**. | 예: 역번역 비교(`Review.negationFlipped()` · `newWordCount()`) |
| **루프** | 만들고 → 확인하고 → 안 되면 다시, 를 **반복하는 구조**. 재시도 횟수 상한을 둔다. | 번역→역번역→비교→재시도 |
| **에스컬레이션** | AI가 스스로 못 풀 때 **사람에게 넘기는 것**. | "사람에게 올림" 표시 |
| **HITL (Human-in-the-loop)** | 중요한 결정은 **반드시 사람이 승인**하는 구조. | 우리 핵심 원칙 |
| **waiting 상태** | 에이전트 결과물이 들어가는 **대기 상태**. 사람이 판정해야 효력이 생긴다. | `status:'waiting'` |
| **경계 테스트** | AI 출력의 **내용이 아니라 "넘으면 안 되는 선"을 지키는지** 검사. AI 답은 매번 달라 내용 검사가 어렵기 때문. | 가짜 AI 응답을 먹여 검사 |
| **토큰 / 비용** | AI가 처리하는 글의 양 단위. 많이 쓰면 요금이 늘고 느려진다. | 호출 수 관리 필요 |
