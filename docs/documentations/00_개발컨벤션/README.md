## 이 폴더는 왜 있나

개발을 하다 보면 이런 생각이 듭니다.

- 지금 **내가 뭘 하는 건지** 모르겠다
- **뭘 해야 하는지** 모르겠다
- **지금 어떤 상태인지** 모르겠다

이 폴더는 그 세 가지에 **누구나 5분 안에 답할 수 있게** 만드는 약속집입니다.
"규칙(어떻게 하나) · 정의(이게 무슨 뜻인가) · 용어(어려운 말 풀이) · 순서(무엇을 먼저 하나)"를 한곳에 모았습니다.

> **한 줄 원칙** — 문서를 읽은 사람이 **"그래서 지금 내가 할 일이 뭐지?"** 에 막힘없이 답할 수 있어야 한다.

## 이 문서 체계를 지키는 이유 (비개발자용 설명)

집을 지을 때 곧바로 벽돌부터 쌓지 않습니다. **도면을 그리고 → 자재 목록을 뽑고 → 공정 순서를 정한 뒤** 짓습니다.
소프트웨어도 같습니다.

```
 ① 설계          ② 스펙(명세)       ③ 상세 설계           ④ 개발 순서         ⑤ 개발·검증
 무엇을 왜        정확히 무엇이       화면·서버·데이터를     무엇부터 만들까      만들고 확인하고
 만드나           되어야 하나         어떻게 만들까          (스프린트)          기록한다
 ─────────       ─────────────      ─────────────────    ─────────────      ────────────
 D01 D03         D04                D06 (+C05)           D02 D05             D06 D07 D08
```

순서를 건너뛰면 **만들고 나서 "이게 아닌데"** 가 됩니다. 그 비용이 가장 큽니다.
이 폴더의 문서들은 그 순서를 지키도록 돕는 장치입니다.

## 이 약속집 자체의 운영 규칙

1. **프로토타입입니다.** 지금 문서들은 v0.1 초안이며, **비개발 팀원에게 보여주고 피드백을 받아 계속 고칩니다.**
2. 확정되지 않은 것은 **반드시 표시**합니다 — `확정` / `후보` / `미정` / `제안` 네 가지 말만 씁니다 ([C03 §5](C03_문서체계와-ID규칙.md)).
3. **모르면 비워 두지 말고 `미정` 이라고 쓰고 담당자를 적습니다.** 빈칸은 "안 했다"와 "몰랐다"를 구분하지 못합니다.
4. 바꿀 때는 문서 맨 위 **제·개정 이력**에 한 줄을 남깁니다.
5. 이해가 안 되는 문장을 발견하면 **그게 문서의 잘못입니다.** 고칠 수 있게 알려 주세요.

## 피드백 받는 방법

비개발 팀원이 문서를 읽고 **막힌 곳**을 알려 주면 가장 큰 도움이 됩니다.
어려운 용어, 이해가 안 되는 순서, 빠진 설명 — 무엇이든 좋습니다. 아래 한 줄 형식이면 충분합니다.

> `[문서명 · 절 번호] 어디가 · 왜 막혔는지`
> 예) `[C01 · §3] "서버리스"가 무슨 뜻인지 모르겠어요`

받은 피드백은 [C07 §5 피드백 기록](C07_역할과-운영.md) 에 쌓고, 반영하면 이력에 남깁니다.
