## 2. 역할별 "내가 할 일" 가이드

### 2.1 모든 팀원 공통 (매주)

1. [C01 §7](C01_프로젝트-한눈에.md)의 **할 일 표**를 열고 **내 이름의 줄**을 확인한다.
2. 끝낸 것은 ✅ 로 바꾸고 날짜를 적는다. 막혔으면 `막힘:` 한 줄을 적는다.
3. 모르는 말은 [C02](C02_용어집.md)에서 찾고, 없으면 피드백으로 알린다.

### 2.2 개발자가 아니어도 할 수 있는 일

| 일 | 어떻게 | 산출물 | 왜 중요한가 |
|---|---|---|---|
| 🧑 **실사용 확인** | 폰으로 배포 주소를 열고, 이주노동자 또는 안전관리자 1명에게 **설명 없이 건네** 본다. 어디서 막혔는지 적는다. | 관찰 메모 (`D07 §3.3`에 반영) | 평가표 "주변 의견 수렴"을 채우는 **유일한 방법** |
| 🧑 **QR·iOS·비행기 모드 확인** | 설비 QR을 폰 카메라로 찍는다 / 아이폰에서 열어 본다 / 비행기 모드에서 열어 본다 | 확인표 (`docs/10-checklist.md`) | 코드 검사로는 못 잡는 항목 |
| **시장·수치 출처 검증** | 발표에 쓰는 숫자마다 원문 출처를 찾는다. 산출식이 없으면 표시한다 | 숫자-출처 표 | 멘토 요청: "수치가 실제인지 환각인지 검증" |
| **수익 모델 정리** | 고객 유형별로 누가·왜·얼마를 낼지 표로 정리 | 수익 모델 초안 | 멘토 요청 |
| **문서 읽기 피드백** | C·D 문서를 읽고 막힌 곳을 알려 준다 | 피드백 한 줄씩 | 이 문서 세트의 목표가 "비전공자가 이해하는 것" |
| **번역 문구 검토 보조** | 한국어 안전 문구를 읽고 현장에서 쓰는 말인지 확인 | 문구 의견 | 검수 게이트 보조 |
| **발표 자료** | 제품 저장소의 `presentation/` 폴더 참고 | 슬라이드, 대본 | 평가표 15점 |

### 2.3 개발자의 일

C04의 G3~G5 + [C05](C05_개발규칙.md). 우선순위는 [C01 §7](C01_프로젝트-한눈에.md).

## 3. 회의와 소통 (제안)

| 회의 | 주기 | 시간 | 내용 | 산출 |
|---|---|---|---|---|
| **정기 회의** | 주 1회 (요일·시간 `미정`) | 30~40분 | ① 지난주 한 일 ② 이번 주 할 일 ③ 막힌 것 ④ C01 상태판 갱신 | 상태판, 결정 사항 |
| **짧은 점검** | 주 1~2회 (메신저) | 5분 | "한 일 / 할 일 / 막힘" 한 줄씩 | |
| **스프린트 계획·확인** | 2주마다 | 각 30분 | [C04 §6](C04_개발순서와-게이트.md) | D05 갱신 |
| **멘토링** | 일정에 따름 | | 질문 목록 사용 (`MENTORING-QUESTIONS.md`) | 답변을 `mentoring-날짜.md`로 기록 |

### 소통 규칙

- **결정은 글로 남긴다.** 말로 정하면 며칠 뒤 서로 다르게 기억한다 → [C06](C06_결정기록.md) 또는 회의 메모.
- **모르는 것은 모른다고 말한다.** 문서에 `미정`+담당+기한으로 적으면 된다.
- **질문에 "바보 같은 질문"은 없다.** 개발자가 문서에서 막힌 곳이 곧 문서의 결함이다.
- **개발자는 비개발자에게 설명할 때 [C02](C02_용어집.md)의 말만 쓴다.** 새 용어를 쓰면 용어집에 먼저 넣는다.
