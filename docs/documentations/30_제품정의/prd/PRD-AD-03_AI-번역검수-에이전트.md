## 1. 문제와 목표

- **문제**: 안전 문구 하나를 5개 언어로 번역하고 역번역까지 받아 대조하는 일이 전부 사람 손이다. 검수가 병목이다. 아이디어톤 자체 평가에서 가장 약한 칸이 "제품 안의 AI가 실제로 돌지 않는다"였다.
- **목표**: AI가 번역 초안과 역번역을 만들고 스스로 대조해 재시도한다. 끝까지 못 풀면 사람에게 올린다. **승인은 언제나 사람이 한다.**

| 성공 지표 | 정의 | 목표값 | 측정 |
|---|---|---|---|
| 검수 소요 시간 | 문구 1개 × 5개 언어를 승인 가능 상태로 만드는 시간 | 수작업 대비 단축 — 목표값 `미정` | 시연 전 수작업·에이전트 각 10문구 측정 (byeonsoyun, 2차 스프린트) |
| 사람 수정 비율 | 에이전트 초안 중 운영자가 고친 비율 | 측정 후 정함 | 운영 로그 |
| 사람에게 올림 비율 | 재시도 상한까지 못 푼 비율 | 측정 후 정함 | 운영 로그 |
| 경계 위반 | `reviewed`가 에이전트 경로로 저장된 건수 | **0건** | 경계 테스트 |

## 2. 사용자와 상황

- 번역 검수 운영자. 사무실 PC, 인터넷 있음. 크메르어·네팔어를 직접 읽지 못한다 — 그래서 **한국어 역번역**과 **뜻 뒤집힘 표시**에 기대 판정한다.

## 3. 사용자 스토리

- US-28 운영자는 번역 입력 시간을 줄이기 위하여 한국어 문구로 6개 언어 번역 초안과 역번역을 받는다.
- US-29 운영자는 오역을 걸러내기 위하여 AI의 역번역 비교 결과(뒤집힘 여부)를 문구·언어별로 본다.
- US-30 운영자는 AI가 풀지 못한 문구를 놓치지 않기 위하여 "사람에게 올림" 표시를 본다.
- US-31 운영자는 안전 지시의 책임을 지기 위하여 AI 제안을 승인·대기·중지로 직접 판정한다.
- US-25·26·27 (개발자) 키 보호 · 실패 시 수동 경로 유지 · 호출 상한. US-37 경계 검사.

## 4. 기능 요구사항

| ID | 요구 | 상태 | 근거 |
|---|---|---|---|
| FR-AD-03-01 | 운영자가 문구에서 "AI 번역 받기"를 누르면, 등록된 언어마다 번역 초안을 받는다 | 🔶 | US-28 |
| FR-AD-03-02 | 번역마다 다른 호출로 한국어 역번역을 받는다 (번역과 역번역은 다른 모델 또는 다른 프롬프트 — A01 질문 3) | 🔶 | R-03 |
| FR-AD-03-03 | 역번역을 원문과 규칙으로 대조한다: `Review.negationFlipped`, `Review.newWordCount` (기존 함수 재사용) | 🔶 | `review.js` |
| FR-AD-03-04 | 뜻이 뒤집혔으면 같은 언어를 다시 번역한다. 재시도 상한은 2회 (결정) | 🔶 | Q6 |
| FR-AD-03-05 | 상한까지 못 풀면 그 언어에 "사람에게 올림" 표시를 붙인다 | 🔶 | US-30 |
| FR-AD-03-06 | 에이전트 결과는 **항상 `status: 'waiting'`** 으로 저장한다. 응답에 `reviewed`가 있어도 무시한다 | 🔶 | P-2, STC-E16-002 |
| FR-AD-03-07 | AI 호출이 실패·지연되면 지금의 손 입력 칸이 그대로 나온다. 버튼만 조용히 사라지지 않고 이유를 적는다 | 🔶 | US-26, D-002 |
| FR-AD-03-08 | 진행을 단계별로 보여 준다: 번역 중 → 역번역 중 → 대조 → 재시도 n/2 → 완료·올림 | 🔶 | 시연 |
| FR-AD-03-09 | 호출 횟수·재시도·시간 상한을 둔다. 문구 1개당 최대 호출 수 = 언어 수 × 2 × (1 + 재시도 2) | 🔶 | US-27 |
| FR-AD-03-10 | AI 키는 서버 환경변수에만 둔다. `src/`에 키 문자열이 없다 | 🔶 | US-25, D-005 |
| FR-AD-03-11 | AI 출력은 신뢰할 수 없는 문자열로 다룬다: `textContent`로만 표시 | 🔶 | STC-E16-003 |
| FR-AD-03-12 | 판정 화면에 경계를 적는다: "AI는 여기까지 · 승인은 사람" | 🔶 | 기존 `library.js` 문구 |
| FR-AD-03-13 | 언어마다 시도 횟수(n/3)와 "재시도 후 해결" 여부를 보여 준다 | 🔶 | 1회차 시안에서 추가 |
| FR-AD-03-14 | "사람에게 올림" 언어는 AI 번역문 그대로 승인할 수 없다. [직접 입력] 후에만 승인할 수 있다 (결정) | 🔶 | 1회차 시안에서 추가 |
| FR-AD-03-15 | 이미 승인된 언어는 "AI 번역 받기"에서 다시 번역하지 않는다 (결정) | 🔶 | 1회차 시안에서 추가 |

## 5. 화면 흐름 (관리자앱 · 문구 라이브러리 안)

```
 [문구 카드] ko: "회전 중인 롤러에 손을 넣지 마십시오"   [ AI 번역 받기 ]
     ▼
 [진행]  km ●번역 ●역번역 ●대조 ✓   id ●번역 ●역번역 ●대조 ✕ 뒤집힘 → 재시도 1/2 …
     ▼
 [결과 — 언어별 행]
   km  번역문 | 역번역 "…넣지 마십시오" | ✓ 뒤집힘 없음 | 대기 | [승인] [중지]
   id  번역문 | 역번역 "…넣어도 됩니다"  | ⚠ 사람에게 올림 | 대기 | [직접 입력] [중지]
     ▼
 운영자가 언어별로 승인 → 그 언어만 reviewed → 작업자앱(WK-02)에 노출
 (AI 실패 시: "AI를 쓸 수 없습니다 — 아래에 직접 입력하세요" + 기존 입력 칸)
```

## 7. 비기능·넘지 않는 선

- 노동자 화면 외부 요청 0건 유지 (D-002). 에이전트 결과는 `Store` 데이터로만 노동자에게 간다.
- `reviewed`로 올리는 것은 사람뿐 (P-1·P-2). 에이전트 문장에도 "면책" 금지 (P-7).
- 비용: 문구 100개당 약 0.13~5달러 (S02 N-63, 가정 위의 계산). Vercel 함수 최대 300초 (N-60).
