## 1. 문제와 목표

- **문제**: 위험을 봐도 말로 알리지 못하고, 알리면 불이익이 있을까 걱정한다.
- **목표**: 그림 두 번으로 익명 신고를 끝낸다. 신고가 늘어나는 것이 재해의 선행지표다.
- **성공 지표**: 노동자 1인당 월 신고 건수 도입 후 3배 — 🔷 아이디어톤 PRD 가정, 측정 없음.

## 2. 사용자와 상황

- 작업 중 위험을 발견한 노동자. 글을 못 쓴다.

## 3. 사용자 스토리

- US-17 노동자는 위험을 알리기 위하여 설비·위험유형을 그림이나 음성으로 익명 신고한다.

```
 🆕 [회신 보기] 접수 번호 입력 ─► 상태(내 언어·아이콘·🔊) + 조치 내용("담당자가 한국어로 남긴 말")
```

## 6. 데이터

| 키 | 읽기/쓰기 | 내용 |
|---|---|---|
| `setup` | 읽기 | 설비 목록 |
| `reports` | 쓰기 | `{ticket, equipment, hazard, memo, at, status}` — 신고자 식별값 없음. 🆕 `photoKey`(사진 저장 위치) |
| 🆕 (서버) 회신 조회 | 읽기 | `GET /api/reports/:ticket` — 상태·조치 내용·조치일만 돌려준다. 담당자 이름·다른 신고는 주지 않는다 (SPEC-BE §3.2 BE-WK-04) |

## 7. 비기능·넘지 않는 선

- 🆕 사진의 EXIF(위치·기기)는 올리기 전에 지운다. 회신 조회는 번호만으로 하되, 번호를 차례로 맞혀 보는 것을 막는다 (시도 제한 · 번호는 시각+무작위 FR-04).
- P-3 익명. 음성 받아쓰기는 브라우저가 인식 서버를 부른다 — 노동자 화면 외부 요청 0건의 **알려진 예외**(D06 §3.4). 화면에 고지한다.
