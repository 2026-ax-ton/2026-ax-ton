# PRD 양식 — 기능별 PRD 공통 틀

> 모든 기능 PRD는 이 순서를 따른다. 빈 절은 지우지 말고 "해당 없음" 또는 `미정 (담당·기한)`으로 쓴다. 규칙: [P00](../P00_제품정의-작업흐름.md) §3·§4·§5

```
# PRD-<기능ID> · <기능명>
> 문서 상태 · 최종 수정 · 소유자 · 이 문서가 답하는 질문

| 기능 ID | 사이드 | 사용자 | 우선순위 | 상태 | 기존 매핑 (기능n·T·E·US) | 코드 | 시험 |

## 1. 문제와 목표       — 어떤 문제를, 무엇이 되면 성공인가 (성공 지표: 정의·목표값·측정 여부)
## 2. 사용자와 상황     — 누가 어떤 상황에서 쓰나 (페르소나는 아이디어톤 PRD 가정임을 표시)
## 3. 사용자 스토리     — D04 US 인용
## 4. 기능 요구사항     — FR-<기능>-nn | 요구 | 상태(✅/🔶/⬜) | 근거
## 5. 화면 흐름         — 단계별 텍스트 와이어
## 6. 데이터            — Store 키 읽기/쓰기, 모양, 읽는 통로 함수
## 7. 비기능·넘지 않는 선 — P-1~P-9, 접근성, 오프라인, 보안
## 8. 수용 기준         — AC-<기능>-nn (시험 가능한 문장) | 확인 방법(테스트 파일·STC·사람 확인)
## 9. 근거              — 코드·문서 ✅ / 벤치마킹·VOC·회의록 (없으면 미정)
## 10. 시각화와 피드백   — 회차 | 시안 | 발견(PRD와 다른 점) | 반영
## 11. 열린 질문        — 담당·기한
## 제·개정 이력
```
