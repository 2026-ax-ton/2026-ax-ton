|---|---|---|---|---|---|---|---|

## 1. 문제와 목표

- **문제**: 모든 기능이 "누가 어느 설비에서 어떤 언어로 일하나"에서 출발한다. 이것이 비면 뒤 화면이 비어 보인다.
- **목표**: 처음 한 번 등록하면 나머지 화면이 모두 그 정보로 움직인다.

## 2. 사용자와 상황

- 40인 규모 공장 생산팀장 겸직 안전 담당자 (아이디어톤 PRD 페르소나 C — 가정). 사무실 PC.

## 3. 사용자 스토리

- US-01 담당자는 교육 대상을 정하기 위하여 사업장 이름·규모·사용 언어를 등록한다.
- US-02 담당자는 설비별 교육을 만들기 위하여 공정·설비와 노동자를 등록한다.
- US-03 담당자는 기기를 옮기기 위하여 데이터를 내보내고 불러온다.

## 4. 기능 요구사항

| ID | 요구 | 상태 | 근거 |
|---|---|---|---|
| FR-AD-01-01 | 사업장 이름·규모를 등록한다 | ✅ | `setup.js` |
| FR-AD-01-02 | 사용 언어를 6개 중에서 고른다. 등록하지 않은 언어는 어디에도 나오지 않는다 | ✅ | 同 |
| FR-AD-01-03 | 공정을 먼저 만들고 설비를 붙인다. 공정이 없으면 설비 폼이 잠긴다 | ✅ | 同 |
| FR-AD-01-04 | 노동자를 사업장 내 식별번호·언어·공정으로 등록한다. 외국인등록번호·여권번호는 받지 않는다 | ✅ | P-8 |
| FR-AD-01-05 | 전체 데이터를 JSON으로 내보내고 불러온다 (서버 없이 두 기기 시연) | ✅ | E-02 |
| FR-AD-01-06 | 사업장 여러 곳을 다룬다 | ⬜ | 지금은 사업장 하나 전제 (09-handover §6.3) |
| FR-AD-01-07 | 노동자가 회원가입할 때 사업장 식별번호를 넣으면 담당자가 등록한 노동자와 연결된다. 둘 중 하나만 있어도 교육은 들을 수 있다 | ⬜ (연결) · ✅ (수강) | 2회차 결정 · `learn.js` 주석 |

## 5. 화면 흐름

```
 [사업장] ─► [언어 ☑×6] ─► [공정 +] ─► [설비 + (공정 선택)] ─► [노동자 +] ─► [내보내기 / 불러오기]
```

## 6. 데이터

| 키 | 읽기/쓰기 | 내용 |
|---|---|---|
| `setup` | 읽기·쓰기 | 사업장·언어·공정·설비·노동자. 바뀔 때마다 다시 읽어 화면 전체를 다시 그린다 |
| 전체 | 내보내기·불러오기 | `Store.exportAll` · `Store.importAll` |
