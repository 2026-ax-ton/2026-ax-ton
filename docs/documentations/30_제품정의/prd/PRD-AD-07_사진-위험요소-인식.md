## 1. 문제와 목표

- **문제**
  - 담당자는 "우리 공장 이 설비의 어디가 위험한지"를 문항으로 옮길 시간이 없다 (아이디어톤 PRD 페르소나 C).
  - 지금 위험 지점 짚기(hotspot) 문항은 **코드로 그린 도해 3종(프레스·도장 부스·분전반)** 위에서만 정답 구역을 고를 수 있다. 그 밖의 설비는 구역이 없는 공용 그림(`generic`)이라 우리 설비 모습과 다르다 (`src/assets/diagrams.js` 머리 주석·`ZONES`).
  - 아이디어톤 PRD F-01의 "설비 사진 → 교육 자료"는 v1.0으로 미뤄진 뒤 해커톤 PRD 14개에서 빠졌다. 기술 멘토가 10/31에 이 점을 짚었다 (05 멘토 기록 M6).
- **목표**: 담당자가 설비 사진 한 장을 넣으면 AI가 위험 지점과 위험유형을 **제안**하고, 담당자가 고쳐서 교육 만들기(AD-04)로 넘긴다. **AI는 제안만 하고 확정은 사람이 한다.**

| 성공 지표 | 정의 | 목표값 | 측정 |
|---|---|---|---|
| 문항 초안 시간 | 사진을 넣고 hotspot 문항 초안이 교육 만들기에 넘어가기까지 걸린 시간 | `미정` (수빈, 11/5) | 시연 전 직접 3회 잰다 (제안) |
| 그대로 쓴 비율 | AI가 제안한 위험 지점 중 담당자가 고치지 않고 확정한 비율 | 측정 후 정한다 | 시연 전 사진 5장으로 잰다 (제안) |
| 경계 위반 | 담당자 확인 없이 AI 결과가 교육(`courses`)에 저장되거나, AI가 쓴 문장이 안전 문구로 들어간 건수 | **0건** (제안 — AD-03 경계 위반 0건과 같은 기준) | 가짜 응답 경계 테스트 |
| 실패 대비 | AI가 실패했을 때 기존 손 흐름으로 발급까지 간 비율 | **100%** (제안) | 가짜 응답 경계 테스트 |

## 2. 사용자와 상황

- 40인 공장 생산팀장, 안전 업무 겸직 담당자 (아이디어톤 PRD 페르소나 C — **가정, VOC로 확인 안 됨**).
- **설비 앞에서 폰으로 찍는다** (§11 Q3 결정). P01은 관리자앱을 "사무실 PC"로 보므로, 이 화면만은 폰 화면에서도 끝까지(찍기 → 고치기 → 확정) 되어야 한다.
- 노동자는 이 기능을 직접 쓰지 않는다. 노동자가 받는 것은 결과물인 문항뿐이다.

## 3. 사용자 스토리

> D04 백로그 등록 전이라 `US-` 번호가 없다. 확정되면 개발자가 D04에 번호를 붙인다.

- 담당자는 우리 설비에 맞는 문항을 빨리 만들기 위하여 설비 사진을 넣고 AI가 짚은 위험 지점을 받는다.
- 담당자는 틀린 제안이 교육에 들어가지 않게 하기 위하여 AI가 짚은 지점과 위험유형을 고치거나 지운다.
- 담당자는 안전 문구를 새로 쓰지 않기 위하여 확정한 위험유형에 맞는 검수 완료 문구 후보를 받는다.
- 담당자는 AI가 안 될 때에도 교육을 만들기 위하여 지금의 손 흐름으로 그대로 진행한다.

## 7. 비기능·넘지 않는 선

- **AI는 제안만 한다.** 확정·승인은 사람이 한다 (D-027 ①).
- **문구는 검수된 라이브러리에서 고르기만 한다** (P-1, D-027 ②).
- **노동자 화면은 제3자 요청 0건** 그대로 (D-025, D-032).
- **사진 원본을 저장하지 않는다.** 얼굴·이름표가 나오지 않게 안내한다 (D-027 ④⑤).
- **처리방침을 고쳐야 한다.** 지금 A05 표 2는 "Google에는 안전 문구만 보낸다"라고 적혀 있다. 사진을 보내면 이 줄을 고쳐야 한다 (D-027 ④ "A05 처리방침 반영 필요").
- **실제 노동자가 찍힌 사진으로 시연하지 않는다.** 해커톤 시연은 예시 데이터로만 한다 (A05 머리말).
- 관리자 화면 공통 규칙(아이콘 + 글자 + 색, `innerHTML` 금지)을 따른다 (SPEC-FE §0).
