## 2. 역할분담 (표 2) — 확정 (D-016)

> 사실: 팀의 개발 포지션은 **byeonsoyun 1명**이다. 팀장은 다른 팀원이다. 팀 내부 상의는 아직 없다.
> 그래서 팀장과 팀원 2명을 **한 묶음 「기획·디자인 팀」** 으로 보고 진행한다 ([C06 D-016](../00_개발컨벤션/C06_결정기록.md)).

| 멘토 권장 역할 | 우리 배치 | 이 흐름에서 맡는 일 | 산출물 |
|---|---|---|---|
| **FE** 1 | byeonsoyun | ⑤ FE Spec, ⑥ 화면 코드 생성·검증 | SPEC-FE, 코드, 테스트 |
| **BE** 1 | byeonsoyun (겸임) | ⑤ BE Spec, ⑥ 서버 함수·데이터 계층 생성·검증 | SPEC-BE, `/api/*`, `Store` 교체 |
| **기획/PM** 1 | 기획·디자인 팀 (팀장 + 팀원 2) | ④ PRD 검토 · 우선순위 결정 · 설문/VOC·회의록 수집 · 일정 관리 | PRD 검토 의견, VOC 기록, 회의록 |
| **디자인** 1 | 기획·디자인 팀 (같은 묶음) | ④′ Figma 시안 검토와 피드백, 화면 문구·아이콘 확인 | 시안 피드백 (PRD §10) |

**사람 한 명이 FE·BE를 함께 맡는 대신 하는 것**
- ⑥ CodeGen을 적극 쓴다. Spec을 구체적으로 써야 생성 품질이 오른다 — 그래서 ⑤를 건너뛰지 않는다.
- 사람이 직접 보는 곳은 **넘지 않는 선**(C05 §2)과 **경계 테스트**다. 생성된 코드도 기존 테스트 1,619건을 통과해야 한다.

**기획·디자인 팀이 지금 바로 할 수 있는 일**
1. PRD 14개 §11 「결정과 남은 질문」을 읽고, 반대하는 결정이 있으면 그 PRD 이력에 적는다 (byeonsoyun이 대신 닫은 결정이다).
2. Figma 시안을 보고 "PRD와 다른 곳"을 PRD §10에 적는다.
3. 이주노동자 또는 안전 담당자 1명에게 5분 인터뷰를 하고 VOC로 기록한다 (§4).

## 3. ID 규칙

| ID | 뜻 | 정의하는 곳 | 예 |
|---|---|---|---|
| `CM-nn` | 공통 기능 (두 앱 모두) | P01 | `CM-01` 계정·로그인 |
| `AD-nn` | 관리자앱(어드민) 기능 | P01 | `AD-02` 문구 라이브러리·검수 |
| `WK-nn` | 작업자앱(LMS 서비스앱) 기능 | P01 | `WK-03` 이해도 검증 |
| `FR-<기능>-nn` | 기능 요구사항 한 줄 | 각 PRD §4 | `FR-WK-03-02` |
| `AC-<기능>-nn` | 수용 기준 한 줄 | 각 PRD §8 | `AC-WK-03-01` |
| `FE-<기능>` · `BE-<기능>` | Spec 절 | SPEC-FE · SPEC-BE | `FE-WK-03`, `BE-AD-03` |

- **사슬**: 기능(`CM/AD/WK`) ─ 에픽(`E-nn`) ─ 스토리(`US-nn`) ─ 요구(`FR`) ─ 수용 기준(`AC`) ─ Spec(`FE/BE`) ─ 태스크(`TK`) ─ 시험(`STC`).
- 기능 하나는 에픽 하나 이상에 매핑된다. 매핑이 없는 기능은 만들지 않는다 ([C03 §9](../00_개발컨벤션/C03_문서체계와-ID규칙.md) 체크리스트).
- 수용 기준(`AC`)은 D07 시험 케이스(`STC`)의 원천이다.

## 4. PRD 근거 자료 현황 (표 3)

| 근거 | 상태 | 지금 쓰는 것 | 채울 계획 |
|---|---|---|---|
| **지금까지의 코드·문서** | ✅ 사용 | `src/` 각 파일 머리 주석(읽는 키·쓰는 키·지키는 규칙), `docs/08`·`09`·`12`, 아이디어톤 PRD `PRD-safety.md` v0.2, C·D·S 문서 | — |
| **타사 앱 벤치마킹** | ❓ 미정 | 사업화 조사에서 확인한 공공 사례 2건만 참고 (성동구 QR 안전영상, 부산진해 AI 통역앱 — [S02](../10_사업화/S02_수치-근거대장.md) N-26·N-27) | 기획·디자인 팀이 앱 3개 이상 비교표 작성 — 미정 (11/06) |
| **설문조사 + 고객 VOC** | ❓ 미정 | 없음. 페르소나는 아이디어톤 PRD 가정이다 | 실사용 시험 TK-1-03·04에서 VOC 수집, 인터뷰 질문지 작성 — 미정 (기획·디자인 팀, 11/06) |
| **회의록** | ❓ 미정 | 멘토링 기록 2건(1차 html, 창업 2차 준비지)만 있다 | 팀 회의마다 `회의록-YYYY-MM-DD.md` 를 남긴다 — 미정 (기획·디자인 팀) |

> **VOC가 없다는 사실을 PRD에 숨기지 않는다.** 각 PRD §9 「근거」에 근거 종류를 적고, 가정은 가정이라고 쓴다.

## 5. 시각화 반복 규칙 (④′)

1. PRD가 초안이 되면 Figma에 그 기능의 핵심 화면 1~2개를 만든다.
2. 시안을 PRD §4(기능 요구)·§8(수용 기준)과 한 줄씩 대조한다. 시안에 없는 요구, PRD에 없는 화면 요소를 적는다.
3. 차이를 PRD §10 표에 「회차 · 발견 · 반영」으로 남기고 PRD를 고친다.
4. 시안과 PRD가 맞을 때까지 반복한다. **완료 조건**: §8 수용 기준 전부가 시안의 어느 요소로 확인된다.
