## 3. 기타 사항

- **R-01** : 개발자가 사실상 1명이다. 부재·지연 시 대체가 없다. → 대응: 문서·인계 문서 유지, 후보 범위를 하나로 좁힘, 계획의 절반만 확정.
- **R-02** : ~~해커톤 주제·평가표 공지가 늦거나 현재 제품과 맞지 않을 수 있다.~~ → **해소** (주제 유지 10/22, 평가표 10/23).
- **R-03** : AI 번역 품질이 소수 언어(크메르어 등)에서 낮을 수 있다. AI가 AI를 검증하면 같은 오류를 놓칠 수 있다. → 대응: 사람 최종 승인, 가능하면 서로 다른 모델·프롬프트로 역번역, 멘토 질문 Q5.
- **R-04** : 서버리스 도입은 배포 설정 변경·비용·키 관리·장애 요인을 새로 만든다. → 대응: 소유자 승인, 키는 환경변수, 호출 상한, 실패 시 수동 경로.
- **R-05** : 실제 사용자에게 써 본 적이 없어 핵심 주장("글 없이 끝까지")이 미검증이다. → 대응: US-38을 1차 스프린트 최우선으로.
- **R-06** : 발표용 수치 중 산출식·출처가 없는 것이 있다(예: 위험 배수·비율). → 대응: US-43. 출처 없으면 삭제.
- **R-07** : 라이브 시연 중 AI 지연·실패·네트워크 장애. → 대응: 폴백 경로를 시연에 포함, 녹화 영상 준비.
- **R-08** : 테스트가 한 PC의 절대 경로에 묶여 있어 다른 환경에서 실행되지 않는다. → 대응: US-40.
- **R-09** : 수익 모델 부재로 "가치가 없다"는 평가를 받을 수 있다(멘토 의견). → 대응: US-42, 효과 크기 설명 준비.
- **R-10** : 데이터 판매 같은 아이디어가 제품 원칙·개인정보 보호와 충돌한다. → 대응: [C06 D-009](../00_개발컨벤션/C06_결정기록.md).
- **R-11** *(2026-10-31 추가)* : 현장 시연은 운영 PC에서 제출 HTML을 `file://`로 연다. 폴더(zip) 제출이나 외부 API 호출이 금지되면 AI를 현장에서 보여 줄 수 없다. → 대응: 운영진 채널톡 문의, 영상 시연 필수, 필요 시 한 HTML 묶기 (US-57).
- **R-13** *(2026-10-31 추가)* : DB 도입으로 개인정보가 서버(싱가포르)에 저장된다. → 대응: 해커톤은 예시 데이터만, 처리방침·동의 초안([A05](../20_기술명세/A05_개인정보-처리방침-초안.md)), 실데이터 전 법률 확인.
- **R-14** *(2026-10-31 추가)* : 1인 개발로 AI와 DB를 함께 하면 일정이 넘칠 수 있다. → 대응: 서버 모드가 안 되면 로컬 모드로 제출(D-023 되돌리는 조건), H2~H9 일부 미룸.
- **R-12** *(2026-10-31 추가)* : 소수 언어(크메르어·네팔어)의 AI 번역이 대부분 "사람에게 올림"이 될 수 있다. → 대응: 11/3 실측. 올림 자체가 설계된 동작이므로 시연에서 그대로 설명한다.
