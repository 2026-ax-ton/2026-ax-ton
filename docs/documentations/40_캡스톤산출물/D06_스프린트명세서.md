## 3. 기술 명세

### 3.1 클래스 명세

> 이 프로젝트는 클래스 없이 **모듈 패턴** `var X = (function () { ... })()` 을 쓴다(ES 모듈 금지). 아래 "클래스/모듈"은 그 전역 모듈 단위이다.

그림 1. 모듈 관계

```
 [HTML 11화면]  ──script──►  store.js ◄── auth.js ◄── login.js / signup.js
      │                        ▲   ▲
      │                        │   └── seed.js (예시 데이터)
      ▼                        │
   각 화면 JS ──► ui.js ──► icons.js, i18n.js
      │             ▲
      ├──► review.js (역번역 대조)         diagrams.js (설비 그림 좌표)    qr.js (QR 인코더)
      │
   sw.js (Service Worker: 화면 파일 캐시, 배포 루트에 위치)

 🆕 2차:  admin/library.js ──► agent.js ──fetch POST──► api/translate.mjs ──► Gemini API
                                  │       └────────────► api/backtranslate.mjs ──► Gemini API
                                  ├──► review.js (대조, 기존)
                                  └──► store.js (waiting 저장 + agent·judged)

 🆕 3차:  모든 화면 ──► store.js (서버 모드) ──fetch──► api/store · api/auth/* · api/reports ──► Neon Postgres
                         └ 캐시 localStorage + 보낼 대기열(outbox)        (같은 출처, Bearer 토큰)
```

| PUT | `/api/store/:key` | 역할별 | `{data, baseVersion}` → `{data, version}` (서버 합치기, 오래된 판 409) |
| POST | `/api/reports` | 노동자 | 신고 → 201 (**계정 미저장**) |
| PATCH | `/api/reports/:id` | 담당자 | 처리 상태 → 200 |

공통: `Authorization: Bearer <token>`, 401(토큰 없음·만료) · 403(역할·사업장 밖) · 409(판 충돌) · 423(잠금). 권한·합치기 규칙은 [A02 표 14-3](../20_기술명세/A02_기술-개발-명세서.md).

## 5. 기타 구현 참고 사항

| # | 제약 | 어기면 |
|---|---|---|
| 1 | 문구는 `Store.phraseOk()`로만 판정한다 | 한 언어 오역 때문에 다른 언어 노동자가 안전 지시를 잃는다 |
| 2 | 문항 문구는 `Store.qtext()`로만 읽는다 | 정답이 다른 선택지를 가리킨다 |
| 3 | 새 문구·AI 결과는 `waiting`으로만 저장한다 | 검수를 거치지 않은 문장이 안전 지시가 된다 |
| 4 | `innerHTML`을 쓰지 않는다 (AI 출력 포함) | 설비 이름·AI 출력 한 줄로 화면이 깨지거나 스크립트가 실행된다 |
| 5 | 노동자 화면은 외부 요청 0건 | 현장 인터넷이 약할 때 교육이 끊긴다 |
| 6 | 배포마다 `sw.js`의 `VERSION`을 올린다 | 고쳤는데 옛 화면이 그대로 남는다 |
| 7 | `main`을 먼저 push한다 | 배포가 건너뛰어져 주소가 옛날 것으로 남는다 |
| 8 | 신고에 식별값을 저장하지 않는다 | 익명이 깨져 신고가 멈춘다 |
| 9 | 발급된 교육의 문항 순서·정답 번호를 바꾸지 않는다 | 옛 기록이 다른 선택지를 가리킨다 |
| 10 | 테스트에 작업자 PC의 절대 경로가 박혀 있다 (현재) | 다른 PC에서 테스트가 전부 실패한다 → TK-2-01 |
| 11 | 문서(`docs/12`)가 `Review.compare()` 를 말하지만 코드에는 없다 (`negationFlipped` 등만 있음) | 에이전트 설계가 없는 함수를 전제하게 된다 → 설계 시 실제 함수를 쓰거나 래퍼를 새로 정의한다 |
| 12 | 🆕 AI 결과의 `status`는 코드 상수 `'waiting'`이다 | AI가 승인한 문장이 노동자에게 나간다 |
| 13 | 🆕 `escalated` 언어는 직접 입력 전에 승인할 수 없다 | AI가 못 푼 번역이 그대로 승인된다 |
| 14 | 🆕 서버 코드는 저장소 루트 `api/`에만 둔다. `src/`(브라우저)에는 의존성·서버 코드를 넣지 않는다 (D-023) | 브라우저 쪽 의존성 0 원칙이 깨지고, 서버 코드가 배포 정적 파일로 노출된다 |
| 15 | 🆕 `ALLOW_FILE_ORIGIN=1`은 제출(11/22)~본선(11/28)에만 켠다 | 아무 로컬 파일이나 우리 API를 부를 수 있다 |
| 16 | 🆕 AI에는 안전 문구만 보낸다 | 노동자·신고 데이터가 외부로 나간다 |
| 17 | 🆕 서버는 요청 본문의 사업장·역할 값을 믿지 않고 **토큰**으로만 판단한다 | 주소·본문을 고쳐 남의 사업장 데이터를 본다 |
| 18 | 🆕 DB 질의는 매개변수 방식만 | SQL 인젝션 |
| 19 | 🆕 신고 경로는 계정을 저장·기록하지 않는다 | 익명이 깨져 신고가 멈춘다 |
| 20 | 🆕 서버 실패 시 캐시로 계속하고 「이 기기에 저장 중」을 표시한다 | 노동자 기록이 조용히 사라진다 |
