## 2. 테스트 개요

### 2.1 테스트 범위

- **대상** : 기준선 v1.0 의 화면 11개(노동자 6·관리 5)와 공용 모듈, 로그인·가입, 오프라인 동작. 해커톤 증분(T-09)은 **구현 전이라 계획만** 둔다.
- **단계** : 자동화는 **통합·시스템 단계**(가짜 브라우저 jsdom에서 실제 화면 스크립트를 실행). 단위 테스트는 별도 구분하지 않았다. 사람이 직접 하는 확인은 §3.3.

**제외 항목과 그 사유** (양식이 명시를 요구한다):

| 제외 항목 | 사유 |
|---|---|
| 실제 브라우저·실제 기기에서의 시험 | 자동 테스트는 가짜 브라우저(jsdom)다. 실기기는 §3.3 의 사람 확인으로 대체 (대부분 `미수행`) |
| 성능·부하 시험 | 서버가 없고 단일 사용자 정적 앱이다 |
| 실제 6개 언어 음성 발음 품질 | 브라우저 내장 음성에 의존한다. 발음 품질은 자동화할 수 없다 |
| 서버·AI 연동 (T-09) | 아직 구현되지 않았다. 계획만 §3.2 (후보) |
| 보안 침투 시험 | 인증이 모의(mock)이며 서버가 없다. 서버 도입 후 별도 `미정` |

### 6.4 🆕 2차 실측 — 문구 10개 × 5개 언어 (TK-2-11, 2026-10-31) · **M1**

> 미리보기 배포(`feat/agent-prd-v1`)에서 **실제 Gemini** 로. 측정 도구 `scripts/measure-ai.mjs`
> (에이전트와 같은 절차를 돌고, 판정은 `src/assets/review.js` 를 그대로 불러 쓴다).
> 같은 날 **다섯 번** 쟀다 — 측정 중에 공급사 요금제가 바뀌었기 때문이다.

| # | 상황 | 성공 | 재시도율 | 올림 | 평균 | p95 |
|---|---|---|---|---|---|---|
| ① | 무료 등급 | 32/50 (64.0%) | 0% | 0% | 7,882ms | 18,431ms |
| ② | 유료 전환 직후 | 50/50 (100%) | 2.0% | 0% | 2,641ms | 3,245ms |
| ③ | ② 직후 연속 | 42/50 (84.0%) | 0% | 0% | 2,991ms | 3,992ms |
| **④** | **전환이 반영된 뒤** | **50/50 (100%)** | 0% | 0% | **3,064ms** | **4,267ms** |
| **⑤** | **④ 직후 연속** | **50/50 (100%)** | 0% | 0% | **3,076ms** | **3,895ms** |
| **합계 (유료 ②④⑤)** | | **150/150 (100%)** | **0.7%** (1/150) | **0%** | **약 2.9초** | **약 3.8초** |

**읽는 법**

- **④⑤를 기준값으로 쓴다.** ②는 전환 직후, ③은 전환이 아직 다 반영되지 않은 상태였다.
- **①의 실패 18건과 ③의 8건은 전부 공급사 한도(429)다.** 번역 품질 문제가 아니다.
- **④⑤는 연속 200회 호출에도 한도에 걸리지 않았다.** 유료 등급이 붙은 뒤의 실제 모습이다.
- **처리 시간이 7.9초 → 약 3초.** ①의 느림은 상당 부분 **한도 제어**였다 —
  「AI 가 느리다」로 결론 낼 뻔한 자리다.
- **재시도 1건(②)은 스스로 고쳐서 통과했다** — 「젖은 손으로 배전반을 만지지 마십시오」
  크메르어, 3번째 시도에서 해결, 사람에게 올라가지 않음. **에이전트 루프가 실물에서
  동작한 장면**이다. 다만 **같은 문구를 다시 돌리면 한 번에 통과했다** — 뒤집힘은 매번
  나오지 않고, 재시도율은 측정마다 흔들리는 값이다 (150건에서 1건).

**이 측정에서 드러나 고친 것** (셋 다 가짜 응답으로는 안 나왔다)

| 무엇 | 증상 | 고친 것 |
|---|---|---|
| **한도를 고장으로 뭉갰다** | 공급사가 429(한도)를 보냈는데 우리는 502 「모델이 응답하지 못했습니다」로 전했다. 운영자는 고장인 줄 알고 계속 다시 누르게 된다 | 공급사 429 → 우리도 **429 `limit`**, 「잠시 뒤 다시 받거나 직접 입력해 주세요」 |
| **언어 5개를 한꺼번에 쐈다** | 운영자 화면은 언어를 동시에 돌린다 → 분당 한도에 몰린다 | `agent.js` 가 언어 출발을 **400ms 씩 어긋나게** 띄운다. 기다리는 것이 아니라 출발만 늦추는 것이라 전체 시간은 거의 그대로다 |
| **얼마나 기다려야 하는지 몰랐다** | 「잠시 뒤」가 1분인지 내일인지 알 수 없다 | 공급사 `Retry-After` 헤더를 읽어 전한다. (2026-10-31 확인: Gemini 는 이 헤더를 **보내지 않는다** — 그래서 운영자는 기다리기보다 손 입력으로 가는 쪽이 빠르다) |

**남은 한계**

- 재시도율·올림 비율은 **표본 150건**의 값이다. 「AI 번역이 거의 완벽하다」로 읽으면
  안 된다 — 설비 이름이 뭉개지는 것(「롤러」→「기계」)은 뒤집힘이 아니라 **「새 낱말」 수**로만
  드러나고, 그것을 보는 것은 사람이다
- 문구 10개는 **한 사업장 수준의 표본**이다. 재해 유형(끼임·감전·화재·추락·중독)은
  고루 덮었지만 업종이 하나다
