## 2. 기능 아키텍처

### 2.1 액터 목록

| 액터명 | 역할 | 참고 |
|---|---|---|
| 노동자 | 내 언어로 교육을 듣고 그림 문제를 풀며 위험을 익명으로 신고·질문한다 | 주 액터 (코드 `worker`) |
| 담당자 | 사업장·설비를 등록하고 교육을 만들어 발급하며 결과·증빙을 다룬다 | 주 액터 (코드 `admin`) |
| 운영자 | 안전 문구의 언어별 번역을 검수(승인·대기·중지)한다 | 주 액터 (코드 `operator`) |
| 브라우저 음성 서비스 | 글을 소리로 읽고(음성합성) 음성을 글로 받아쓴다 | 외부 시스템. 받아쓰기는 브라우저가 인식 서버를 부른다 |
| 호스팅·배포 서비스 (Vercel, GitHub) | 화면 파일을 배포하고 주소를 제공한다 | 외부 시스템 |
| Gemini API (Google) | 안전 문구를 번역하고, 번역문을 한국어로 역번역한다. **승인 권한이 없다** — 결과는 항상 `waiting` | 외부 시스템 · 2026-10-31 확정 (D-018) |
| Vercel 서버리스 함수 (`/api/translate`·`/api/backtranslate`) | 운영자 화면의 요청을 받아 출처·통과 문구·상한을 검사하고 Gemini를 부른다. 키를 보관한다 | 외부 시스템(우리 코드) · 노동자 화면은 부르지 않는다 |
| 🆕 Neon Postgres (DB) | 사업장·계정·교육·이수 기록·신고·문구를 저장한다. 서버 함수만 접근한다 | 외부 시스템 · 2026-10-31 추가 (D-023) |
| 감독기관 | 증빙 문서를 제출받는다 | 시스템 밖 수신자 (연동 없음) |

### 2.2 사용사례 다이어그램

그림 1. 사용사례 다이어그램 (텍스트 표기)

```
                    ┌───────────────────────── 시스템 경계 ─────────────────────────┐
 [노동자] ──────────┼─ T-04 수강과 이해도 검증                                       │
    │               ├─ T-05 현장 신고와 소통                                         │
    │               ├─ T-08 공통 기반 (다국어·접근성·오프라인)                        │
                    │                                                               │
 [담당자] ──────────┼─ T-01 사업장·설비 등록                                         │
    │               ├─ T-03 교육 생성·발급                                           │
    │               ├─ T-06 현황 파악과 개선 ◄── 노동자 결과 (T-04, T-05)             │
    │               ├─ T-07 교육 증빙 ─────────► [감독기관] (제출은 시스템 밖)        │
                    │                                                               │
 [운영자] ──────────┼─ T-02 안전 문구 검수 ──► 검수된 문구 ──► T-03                   │
                    │                                                               │
                    │  T-09 AI 번역·검수 에이전트 ◄──► [Vercel 함수] ◄──► [Gemini API]│
                    │     · 대상 화면: 운영자(T-02 문구 라이브러리)                   │
                    │     · 번역→역번역→대조→재시도(≤2)→사람에게 올림                │
                    │     · 결과는 항상 'waiting' → 운영자가 판정(T-02)               │
                    │                                                               │
                    │  🆕 T-11 계정과 기기 간 데이터 공유 ◄──► [Vercel 함수] ◄──► [Neon]│
                    │     · 노동자·담당자·운영자 전원 (로그인, 가입 코드)             │
                    │     · 서버가 역할·사업장 권한 검사, 신고는 계정 없이 저장       │
                    └───────────────────────────────────────────────────────────────┘
 [브라우저 음성 서비스] ◄── T-04, T-05, T-08        [호스팅·배포 서비스] ◄── 전체 배포
```

흐름: **운영자 검수(T-02) → 담당자 교육 발급(T-03) → 노동자 수강·검증(T-04) → 담당자 대시보드·증빙(T-06, T-07) → 교육 수정(T-03)** 의 개선 루프.

## 3. 기타 요구사항

- **비기능 · 현장 환경** — 노동자 화면은 외부 요청 0건(예외 2: `sw.js` 동일 오리진 전달, 신고 화면 받아쓰기), 오프라인 동작, 터치 영역 60px, 문해력 비전제(음성 병행), 색만으로 상태 구분 금지.
- **비기능 · 보안·개인정보** — 신고자 식별값 저장 0, 외국인등록번호·여권번호 미수집, AI 키 브라우저 노출 금지, AI 출력은 `textContent` 로만 표시.
- 🆕 **AI 경계 (2026-10-31)** — AI는 `reviewed`를 쓸 수 없다. "사람에게 올림" 언어는 사람이 직접 입력한 뒤에만 승인된다. 이미 승인된 언어는 다시 번역하지 않는다. AI에는 안전 문구만 보낸다. 문구 1개당 호출 상한 = 언어 수 × 2 × 3.
- 🆕 **시연 요구** — 제출 HTML을 운영 PC 크롬에서 더블클릭(`file://`)해 끝까지 시연할 수 있어야 한다. 이때 AI 호출은 배포된 `/api`로 가고, 제출~11/28에만 `null` 출처를 허용한다.
- **비기능 · 배포** — 빌드 없음, 의존성 0(`src/`), 배포마다 `sw.js` VERSION 상향.
- **제품 원칙** — [C05 §2](../00_개발컨벤션/C05_개발규칙.md) 넘지 않는 선 21개 항목.
- **제약** — ~~데이터는 기기마다 별개이다~~ → 🆕 서버 모드(https + 로그인)에서는 DB로 기기 간 공유한다(T-11). `file://` 로컬 모드는 기존처럼 기기마다 별개다.
- 🆕 **서버 요구 (T-11)** — 서버가 역할·사업장 권한을 다시 검사한다. 다른 사업장 데이터는 어떤 경로로도 나오지 않는다. 신고 저장에는 계정 정보가 없다. 서버가 응답하지 않아도 화면은 캐시로 계속 동작하고 그 사실을 표시한다.
- **범위 밖(하지 않는 것)** — 인사·평가용 점수 내보내기, 신고자 식별·"내가 낸 신고" 목록, 미이수자 필터·정렬, 노동자 개인 데이터 판매([C06 D-009](../00_개발컨벤션/C06_결정기록.md)).
